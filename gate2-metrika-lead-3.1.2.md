# 3.1.2. Полученная заявка

## 1. Что сделать (инструкция)

Настроить Яндекс Метрику для регистрации успешно отправленных заявок с сайта и подтвердить, что каждое зарегистрированное целевое действие соответствует фактическому обращению.

**Полученная заявка:** посетитель отправил форму, а система приёма зарегистрировала обращение.

Для стандартных форм Tilda рекомендуется использовать виртуальное событие успешной отправки `/tilda/form.../submitted` и цель Яндекс Метрики типа «Посещение страниц».

Не путайте:

| Действие | Что подтверждает |
|---|---|
| Открытие формы | Интерес посетителя |
| Нажатие «Отправить» | Попытку отправки |
| Виртуальное событие `/submitted` | Событие отправки формы Tilda |
| Полученная заявка | Фактическую регистрацию обращения |
| Посещение `/thankyou` | Просмотр страницы благодарности |

**Главный принцип:** настройка считается завершённой, только когда событие формы передаётся в Метрику, цель регистрирует его достижение, а обращение действительно получено.

Если на сайте несколько форм, каждую уникальную форму необходимо проверить. При этом не следует создавать дубли целей, фиксирующих одно и то же событие без отдельной аналитической необходимости.

## 2. Где нажать / Как проверить (инструкция)

### А. Найти форму и определить её виртуальное событие

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь в аккаунте, где размещён сайт.
3. В списке сайтов выберите нужный проект.
4. Откройте страницу, на которой посетитель оставляет заявку.
5. Нажмите на название страницы, чтобы перейти в редактор.
6. Найдите блок, содержащий форму.
7. Наведите указатель мыши на этот блок.
8. Нажмите «Настройки».
9. Прокрутите панель настроек до самого низа.
10. Найдите текст «Отправка формы в системе аналитики будет отображаться как просмотр страницы».
11. Под ним найдите виртуальный адрес.
12. Скопируйте его полностью, без изменений.

Адрес имеет вид:

`/tilda/formXXXXXXXXXX/submitted`

Здесь `XXXXXXXXXX` означает уникальный идентификатор блока.

**Пример для текущего проекта:**

`/tilda/form2305306971/submitted`

**Что важно:**

- Используйте адрес из настроек именно проверяемой формы.
- Не копируйте идентификатор из другого блока.
- Не создавайте виртуальную страницу в Tilda.
- Не пытайтесь открыть этот адрес вручную в браузере.

Tilda передаёт виртуальный просмотр автоматически при соответствующем событии формы.

**Результат:** определён точный адрес события отправки заявки.

### Б. Проверить получение заявок в Tilda

Перед настройкой цели убедитесь, что форма направляет данные в действующую систему приёма.

1. В редакторе формы нажмите «Контент».
2. Найдите подраздел «Приём данных из формы».
3. Посмотрите список подключённых сервисов.
4. Убедитесь, что отмечен хотя бы один действующий получатель: Tilda CRM, email, Telegram, CRM или другой поддерживаемый сервис.
5. Если нужный получатель уже отмечен, не подключайте его повторно.
6. Если получателей нет, откройте «Настройки сайта» → «Формы».
7. Выберите используемый сервис приёма данных.
8. Выполните подключение по инструкции этого сервиса.
9. Вернитесь к настройкам блока формы.
10. Откройте «Контент».
11. Отметьте галочкой подключённый сервис.
12. Нажмите «Сохранить и закрыть».
13. Опубликуйте страницу с формой.

**Ожидаемый результат:** форма настроена на отправку обращений в действующий сервис.

**Для проекта «Коричное яблоко»:** ранее в форме были подключены Tilda CRM и Telegram. Повторно подключать их не требуется, если настройки сохранились.

### В. Проверить подключение Яндекс Метрики

1. Откройте панель управления проектом Tilda.
2. Нажмите «Настройки сайта».
3. В левом меню выберите «Аналитика».
4. Найдите раздел «Яндекс Метрика».
5. Посмотрите номер подключённого счётчика.
6. Откройте https://metrika.yandex.ru/ в другой вкладке.
7. Выберите счётчик того же сайта.
8. Сравните номера.

**Если номера совпадают:** ничего менять не нужно.

**Если счётчик отсутствует или номер неверный:**

1. Скопируйте правильный ID из Метрики.
2. Вернитесь в настройки аналитики Tilda.
3. Вставьте ID в соответствующее поле.
4. Сохраните изменения.
5. Откройте список страниц проекта.
6. Нажмите «Опубликовать все страницы».

**Результат:** форма находится на сайте с правильно подключённым счётчиком Метрики.

### Г. Найти или создать цель в Яндекс Метрике

**Часть 1. Проверить существующую цель**

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Цели».
4. Просмотрите список существующих целей.
5. Найдите цель, связанную с отправкой проверяемой формы.
6. Если она существует, нажмите значок карандаша справа от названия.
7. В открывшейся панели «Редактирование цели» найдите поле URL.
8. Посмотрите условие и значение адреса.
9. Сравните значение с виртуальным адресом, полученным в Tilda.

**Правильная конфигурация:**

- Тип: «Посещение страниц».
- Условие: «Содержит».
- Значение: точный путь `/tilda/form.../submitted`.

Если настройки правильные, ничего менять не нужно.

**Часть 2. Создать цель, если её нет**

1. В разделе «Цели» нажмите фиолетовую кнопку «Добавить цель».
2. Откроется экран «Новая цель».
3. Найдите категорию «Вовлечённость».
4. Нажмите «Посещение страниц».
5. В поле «Название цели» введите понятное название.

   Например: «Полученная заявка · Форма консультации».

6. Найдите поле URL.
7. В списке условий выберите «Содержит».
8. В соседнее поле вставьте скопированный виртуальный путь формы.
9. Сравните идентификатор блока с Tilda посимвольно.
10. Нажмите «Добавить цель».
11. Вернитесь к списку целей.
12. Найдите созданную цель.
13. Запишите её числовой ID.

**Пример существующей настройки:**

| Параметр | Значение |
|---|---|
| Название | Полученная заявка · contact_request_form |
| ID | 679277707 |
| Тип | Посещение страниц |
| Условие | URL содержит |
| Значение | `/tilda/form2305306971/submitted` |

Это пример фактической конфигурации одного проекта. Для других форм используются их собственные идентификаторы.

**Важно:** завершающий `/` у фактически отправленного события не мешает условию «Содержит», если указанная в цели часть адреса совпадает.

**Результат:** создана или подтверждена существующая цель, которая отслеживает конкретную форму Tilda.

### Д. Проверить перенаправление после отправки

Если форма переводит посетителя на страницу благодарности:

1. Вернитесь в редактор Tilda.
2. Откройте блок формы.
3. Нажмите «Контент».
4. Найдите поле «Адрес страницы в случае успеха».
5. Посмотрите указанный URL.
6. Если адрес уже правильный, ничего менять не нужно.
7. Если требуется исправление, укажите действующий URL страницы благодарности.
8. Нажмите «Сохранить и закрыть».
9. Опубликуйте страницу.

Если форма находится в Zero Block, проверьте настройку `Settings → Form Style → Success URL`.

**Как это должно работать:**

1. Посетитель заполняет форму.
2. Tilda обрабатывает её отправку.
3. В Метрику передаётся виртуальный просмотр `/submitted`.
4. Посетитель переходит на страницу благодарности, если перенаправление предусмотрено настройкой.

**Важно:** переход на страницу благодарности не заменяет проверку `/submitted`.

Если в Метрике уже существует отдельная цель на `/thankyou`, не создавайте ещё одну такую же цель для заявки.

### Е. Подготовить контрольное тестирование

**Часть 1. Зафиксировать исходные показатели**

1. Откройте Метрику → «Конверсии».
2. Найдите проверяемую цель.
3. Установите период «Сегодня».
4. Запишите текущий показатель «Достижения цели».
5. Запишите текущее количество целевых визитов.

Это нужно, чтобы после теста сравнить показатели до и после, не смешивая новый тест с ранее зарегистрированными достижениями.

Если цель только что создана, подождите несколько минут, пока Метрика начнёт сбор статистики.

**Часть 2. Подготовить браузер**

1. Откройте новое приватное окно Chrome.
2. На Mac нажмите `Command + Shift + N`, на Windows `Ctrl + Shift + N`.
3. Не входите в Яндекс Метрику внутри приватного окна.
4. Откройте опубликованную страницу с формой.
5. Добавьте к адресу параметр `_ym_debug=2`.

Пример:

`https://example.ru/contacts?_ym_debug=2`

6. Дождитесь полной загрузки.
7. Внизу страницы нажмите значок отладчика Метрики.
8. Откройте вкладку `Counters`.
9. Убедитесь, что номер соответствует нужному счётчику.
10. Перейдите на вкладку `Console`.
11. Справа от поля поиска нажмите `⋮`.
12. Найдите `Preserve log`.
13. Включите сохранение журнала.

**Зачем нужен Preserve log:** при перенаправлении на `/thankyou` события предыдущей страницы должны остаться доступными для проверки.

Если опция не отображается, проверьте дополнительное меню на вкладке `Console` либо используйте сохранение журнала во встроенных инструментах разработчика Chrome.

**Ожидаемый результат:** открыт отладчик нужного счётчика, сохранение событий включено.

### Ж. Выполнить одну тестовую отправку

1. На опубликованной странице найдите форму.
2. Заполните обязательные поля подготовленными тестовыми данными.
3. Используйте собственный доступный контакт, чтобы при необходимости установить результат проверки.
4. Запомните время отправки.
5. Нажмите «Отправить заявку» или соответствующую кнопку один раз.
6. Дождитесь завершения отправки.
7. Проверьте сообщение об успехе либо перенаправление на страницу благодарности.

**Ожидаемый результат:** форма завершила отправку без сообщения об ошибке.

Если появляется ошибка обязательного поля, исправьте ввод. Такая попытка не является успешной заявкой.

Если страница не показывает результата, сначала выясните состояние отправки, прежде чем нажимать кнопку повторно.

### З. Сразу проверить передачу виртуального события

1. Откройте сохранённый журнал отладчика.
2. Выберите вкладку `Console`.
3. Найдите запись `PageView`, соответствующую странице формы.
4. Найдите следующую запись, относящуюся к виртуальному адресу `/tilda/form.../submitted`.
5. Если есть перенаправление, найдите последующее событие просмотра страницы благодарности.
6. Сравните виртуальный адрес с условием цели Метрики.
7. Проверьте номер счётчика у события.

**Ожидаемая последовательность:**

1. `PageView` страницы с формой.
2. `PageView` виртуального адреса `/tilda/form.../submitted`.
3. `PageView` страницы благодарности, если она используется.

**Правильный результат:** присутствует второй `PageView` с виртуальным адресом конкретной формы.

Для цели типа «Посещение страниц» основным подтверждением в отладчике является именно `PageView` во вкладке `Console`. Отсутствие отдельной записи о достижении цели во вкладке `Events` само по себе не доказывает ошибку.

**Если `/submitted` отсутствует:**

1. Убедитесь, что форма сообщила об успешной отправке.
2. Проверьте фактический виртуальный адрес блока Tilda.
3. Сравните его с условием цели в Метрике.
4. Проверьте правильность счётчика.
5. Убедитесь, что опубликована последняя версия страницы.
6. Проверьте, не блокирует ли браузер работу счётчика.
7. При перенаправлении убедитесь, что журнал сохранялся.

Не создавайте новую цель без установления причины.

### И. Проверить фактическое получение обращения

1. Откройте панель управления сайтом Tilda.
2. В верхнем меню нажмите «Заявки».
3. Установите период, включающий время теста, если доступен соответствующий фильтр.
4. Найдите обращение по тестовым контактным данным.
5. Нажмите на заявку.
6. Сравните имя, телефон, тему обращения и время с выполненным тестом.
7. Если форма направляет заявки также в Telegram, CRM или другой сервис, проверьте их получение там.

**Правильный результат:** тестовая заявка зарегистрирована с корректными сведениями.

Если запись отсутствует:

1. В разделе «Заявки» нажмите «Журнал ошибок».
2. Найдите записи за время теста.
3. Откройте соответствующую ошибку, если она есть.
4. Проверьте, какой сервис приёма не получил данные.
5. Вернитесь в Tilda к настройкам формы и проверьте подключение этого сервиса.
6. При необходимости исправьте подключение, сохраните настройки и опубликуйте страницу.

Если хранение заявок в Tilda отключено, проверяйте фактический сервис приёма.

**Важно:** успешный `PageView` подтверждает отправку события аналитики, но не является самостоятельным доказательством доставки заявки получателю.

### К. Проверить достижение цели в Яндекс Метрике

**Через 10-15 минут после теста:**

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Конверсии».
4. Установите период «Сегодня» или другой период, содержащий время теста.
5. Убедитесь, что не выбран ограничивающий сегмент.
6. Найдите цель по названию или ID.
7. Посмотрите показатель «Достижения цели».
8. Сравните его с показателем, записанным до теста.

**Ожидаемый результат:** после одной успешной отправки зарегистрировано достижение соответствующей цели.

Метрика обычно обрабатывает события за 10-15 минут, иногда дольше.

**Если через 15 минут результат отсутствует:**

1. Повторно проверьте период.
2. Убедитесь, что открыт правильный счётчик.
3. Проверьте отсутствие ограничивающих сегментов.
4. Откройте «Настройки» → «Фильтры».
5. Проверьте, не исключён ли тестовый визит.
6. Подождите ещё 15 минут.
7. Повторно откройте отчёт.

Если через 30-60 минут достижения нет, хотя `PageView` был отправлен, проверьте условия цели и зарегистрированные виртуальные просмотры.

Этот интервал является практическим ориентиром повторной диагностики, а не гарантированным пределом обработки Яндекса.

### Л. Проверить виртуальный просмотр в отчёте «Популярное»

Если достижение отсутствует либо нужно дополнительное подтверждение передачи:

1. В Метрике нажмите «Отчёты».
2. Откройте «Содержание» → «Популярное».
3. Установите период, включающий тест.
4. В таблице найдите основной домен сайта.
5. Нажмите стрелку слева от домена.
6. Найдите вложенный каталог `/tilda/`.
7. Раскройте его.
8. Найдите каталог `formXXXXXXXXXX`, соответствующий проверяемому блоку.
9. Раскройте каталог формы.
10. Найдите адрес `submitted`.
11. Посмотрите количество просмотров.

**Ожидаемый результат:** виртуальный адрес формы присутствует в отчёте.

Если адрес найден, но цель не достигнута:

1. Откройте «Цели».
2. Найдите нужную цель.
3. Нажмите значок редактирования.
4. Сравните условие с зарегистрированным виртуальным URL.
5. Проверьте, что цель существовала на момент теста.
6. Если условие неверно, исправьте и сохраните.
7. После исправления проверьте цель новым допустимым тестом.

Если виртуального адреса нет, проверьте правильность счётчика, фильтры и передачу события из Tilda.

### М. Проверить отсутствие повторного учёта заявок

Это особенно важно для последующей оптимизации Яндекс Директа.

**Достижения цели и целевые визиты являются разными показателями.**

Например:

- Целевые визиты: 1.
- Достижения цели: 3.

Это означает, что условие цели было зарегистрировано три раза в рамках одного целевого визита. Но это ещё не доказывает получение трёх отдельных заявок.

**Как провести сверку:**

1. В Метрике откройте «Конверсии».
2. Найдите проверяемую цель.
3. Запишите число достижений за выбранный период.
4. Откройте Tilda → «Заявки».
5. Найдите обращения за тот же период.
6. Сравните время тестовых отправок с зарегистрированными заявками.
7. Установите, сколько отдельных обращений действительно поступило.
8. Если выполнялись несколько тестов, учитывайте их отдельно.

**Правильный результат:** зарегистрированные достижения объясняются фактическими успешными отправками.

Если после одной подтверждённой отправки прирост достижений больше единицы, проверьте:

- Не отправлялась ли форма повторно.
- Не было ли повторных нажатий кнопки.
- Не передавался ли виртуальный просмотр дважды.
- Не установлен ли один счётчик на странице повторно.
- Не используется ли дополнительная интеграция, отправляющая то же событие.

Пока причина повторов не установлена, не считайте количество достижений числом уникальных заявок.

Не удаляйте существующую цель ради исправления такого расхождения.

### Н. Проверить неуспешную отправку

Дополнительная проверка достоверности цели.

1. Откройте страницу формы в приватном окне с `_ym_debug=2`.
2. Откройте отладчик и вкладку `Console`.
3. Не заполняйте одно из обязательных полей.
4. Нажмите кнопку отправки.
5. Убедитесь, что форма показывает ошибку валидации.
6. Проверьте, что при такой попытке не появился новый `PageView` виртуального адреса `/submitted`.

**Ожидаемый результат:** неуспешная попытка не регистрируется как успешная конверсия.

Если событие появляется несмотря на ошибку, дальнейшая диагностика обязательна.

### О. Подготовить цель для Яндекс Директа

После успешного завершения всех проверок:

1. Откройте Яндекс Метрику → «Цели».
2. Найдите настроенную цель.
3. Скопируйте её числовой ID.
4. Убедитесь, что цель фиксирует успешную отправку формы.
5. Убедитесь, что заявка действительно поступает в систему приёма.
6. Проверьте, нет ли необъяснимых повторных достижений.
7. Используйте эту цель как кандидата на основную конверсию при настройке рекламной кампании.

**Не используйте одновременно** открытие формы, нажатие кнопки и успешную отправку как три самостоятельные основные конверсии одного обращения.

Открытие формы и нажатие кнопки могут использоваться как промежуточные цели.

Создание кампании и выбор рекламной стратегии выполняются отдельно в Яндекс Директе.

## 3. Сверка (инструкция)

| Критерий | Ожидаемый результат |
|---|---|
| Счётчик | Правильный ID установлен на сайте |
| Форма | Определён конкретный блок Tilda |
| Виртуальный адрес | Совпадает с условием цели |
| Цель Метрики | Создана или найдена без дублирования |
| Тестовая отправка | Успешно завершилась |
| Отладчик | Зарегистрирован `PageView` нужной формы |
| Получатель | Заявка поступила в систему приёма |
| «Конверсии» | Достижение цели зарегистрировано |
| Повторный учёт | Нет необъяснимых дублирующих событий |
| Неуспешная отправка | Не регистрируется как полученная заявка |

### Итоговый результат

**Готово**

- Заявка успешно отправлена.
- Виртуальное событие Tilda передано в Метрику.
- Цель зафиксировала достижение.
- Обращение получено системой приёма.
- Отсутствуют необъяснимые дублирующие достижения.

**Требует проверки**

- Событие отправлено, но ещё не появилось в отчётах.
- Достижение зарегистрировано, но получение заявки не подтверждено.
- Количество достижений отличается от числа подтверждённых отправок, а причина пока неизвестна.

**Проблема**

- Событие не передаётся.
- Цель использует неправильный виртуальный URL.
- Заявка не поступает получателю.
- Неуспешная отправка засчитывается как полученная заявка.
- Подтверждён повторный учёт одного обращения.

**Не требуется**

На сайте отсутствует отдельный сценарий получения заявок. Например, используется исключительно уже настроенное оформление заказов через корзину.

### Результат для аналитики

- Назначение: «Полученная заявка».
- Приоритет: основная бизнес-конверсия.
- Механизм Tilda: виртуальная отправка формы.
- Тип цели Метрики: «Посещение страниц».
- Условие: индивидуальный путь `/tilda/form.../submitted`.
- Использование: измерение обращений и последующая оптимизация Яндекс Директа.

После подтверждения всех обязательных критериев цель считается полностью настроенной. Только после этого переходим к следующей применимой цели.
