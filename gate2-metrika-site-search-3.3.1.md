# 3.3.1. Поиск по сайту

## 1. Что сделать (инструкция)

Настроить и проверить внутренний поиск сайта, чтобы посетители могли находить товары, услуги или информацию по поисковому запросу.

Целевое действие: посетитель вводит запрос в поисковую строку и получает результаты поиска.

Зачем необходимо:

- Помочь посетителю быстро найти нужное предложение.
- Упростить навигацию по сайту.
- Определять востребованные товары, услуги и темы, если доступна достоверная статистика запросов.

Приоритет: поведенческая конверсия.

Различайте:

| Действие              | Что подтверждает                          |
| --------------------- | ----------------------------------------- |
| Открытие поиска       | Посетитель открыл поисковую строку        |
| Ввод запроса          | Посетитель начал поиск                    |
| Получение результатов | Поисковая система обработала запрос       |
| Переход к товару      | Посетитель открыл конкретное предложение  |
| Покупка               | Посетитель совершил коммерческое действие |

Условия применения:

- Внутренний поиск уже работает: проверяем его, повторно не создаём.
- Поиска нет, но он необходим для навигации: выбираем подходящее решение.
- Поиск не требуется по бизнес-модели: пропускаем настройку.
- Цель в Яндекс Метрике уже существует: сохраняем её, проверяя фактическую регистрацию.
- Для полного измерения требуется дополнительный код, но практическая необходимость не подтверждена: доработку откладываем.

Ожидаемый результат: поиск работает на опубликованном сайте. Фактические возможности его измерения в Метрике проверены, а ограничения зафиксированы.

Для поиска по страницам Tilda поддерживает штатные блоки T838 и T985. Яндекс Метрика поддерживает отдельный тип цели «Поиск по сайту».&#x20;

## 2. Где нажать / Как проверить (инструкция)

### А. Проверить наличие внутреннего поиска

1. Откройте опубликованный сайт проекта.
2. Найдите в шапке значок лупы или поисковую строку.
3. Если это интернет-магазин, дополнительно проверьте страницу каталога.
4. Нажмите на поиск.
5. Введите название товара или услуги, которые действительно есть на сайте.
6. Дождитесь результатов.
7. Проверьте, можно ли открыть найденное предложение.

Если поиск уже работает: сохраняем существующую реализацию.

Если поиска нет: определяем, нужен ли он посетителям. Не добавляем его исключительно ради аналитической цели.

### В. Подключить поиск T985 в шапке сайта

Выполняйте только при отсутствии подходящего поиска.

Часть 1. Добавить блок

1. Откройте [https://tilda.cc/login/](https://tilda.cc/login/?utm_source=chatgpt.com).
2. Авторизуйтесь и выберите нужный сайт.
3. Откройте страницу, используемую как общая шапка сайта (Header).
4. Нажмите «Библиотека блоков».
5. Перейдите в категорию «Виджет».
6. Найдите T985 «Виджет поиска, раскрывающийся по клику».
7. Добавьте блок на страницу.
8. Если T985 уже установлен, новый блок не добавляйте.

Часть 2. Подключить к меню ME4XX

Если в шапке используется меню серии ME4XX:

1. Найдите действующий блок меню.
2. Нажмите «Контент».
3. Откройте раздел «Корзина, поиск и избранное».
4. Включите значок поиска.
5. Если требуется показывать лупу только в меню, включите «Не показывать отдельные кнопки виджетов».
6. Сохраните изменения блока.

Для ME4XX Tilda подтверждает совместную работу меню и T985.&#x20;

Часть 3. Опубликовать

1. В верхней части редактора нажмите «Опубликовать».
2. Вернитесь к списку страниц проекта.
3. Если шапка назначена общей для сайта, нажмите «Опубликовать все страницы».
4. Откройте опубликованный сайт.
5. Убедитесь, что значок поиска появился в шапке.

Если меню и поиск уже опубликованы и работают, повторная публикация не требуется.

### Г. Разрешить внутренний поиск и проверить индексацию

1. В Tilda откройте Настройки сайта → Еще.
2. Найдите «Разрешить внутренний поиск по сайту».
3. Установите галочку, если поиск должен работать и настройка выключена.
4. Откройте Настройки сайта → SEO.
5. Найдите «Запретить поисковикам индексировать этот сайт».
6. Для общедоступного сайта убедитесь, что галочка снята.
7. Сохраните изменения, если они вносились.
8. Опубликуйте все страницы.

Не снимайте запреты индексации с конфиденциальных и закрытых страниц только ради поиска.

После первоначального включения Tilda индексирует доступные страницы, обычно в течение 15 минут.&#x20;

### Д. Проверить работу поиска на сайте

Часть 1. Проверить точный запрос

1. Откройте сайт.
2. Нажмите значок поиска.
3. Введите название существующего товара.
4. Дождитесь результатов.
5. Проверьте название, изображение и цену, если они предусмотрены в выдаче.
6. Нажмите на найденный товар.
7. Убедитесь, что открылась правильная карточка.

Часть 2. Проверить другие сценарии

1. Вернитесь к поиску.
2. Введите более общий запрос, например название категории.
3. Проверьте релевантность результатов.
4. Введите заведомо несуществующее название.
5. Убедитесь, что сайт корректно сообщает об отсутствии результатов.
6. Повторите поиск на мобильном устройстве.

Если результатов нет:

1. Убедитесь, что нужная страница опубликована.
2. Проверьте разрешение внутреннего поиска.
3. Проверьте ограничения индексации.
4. Если поиск включён недавно, дождитесь обновления индекса.
5. Повторите контрольный запрос.

### Е. Проверить подключение Яндекс Метрики

1. Откройте [https://metrika.yandex.ru/](https://metrika.yandex.ru/?utm_source=chatgpt.com).
2. Выберите счётчик нужного сайта.
3. Зафиксируйте его числовой номер.
4. Откройте [https://tilda.cc/login/](https://tilda.cc/login/?utm_source=chatgpt.com).
5. Выберите тот же проект.
6. Перейдите в Настройки сайта → Аналитика → Яндекс Метрика.
7. Сравните номер подключённого счётчика с номером в Метрике.

Если номера совпадают и счётчик работает: ничего не меняйте.

Если счётчик отсутствует, предварительно проверьте, не установлен ли он другим способом. При необходимости подключите существующий счётчик, сохраните изменения и опубликуйте все страницы.&#x20;

### Ж. Проверить или создать цель «Поиск по сайту»

Часть 1. Проверить существующую цель

1. Откройте Яндекс Метрику.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Цели».
4. Найдите «Поиск по сайту» либо автоматическую цель с таким же назначением.
5. Проверьте её тип и параметры.
6. Если подходящая цель существует, повторно не создавайте.

Часть 2. Определить поисковый параметр

1. Откройте опубликованный сайт.
2. Нажмите значок поиска.
3. Введите название существующего товара.
4. Посмотрите адрес в браузере после появления результатов.

Например:

`https://example.ru/?search=koza`

Здесь `search` обозначает параметр поиска, а `koza` является поисковой фразой.

Яндекс Метрика распознаёт четыре стандартных параметра: `q`, `text`, `query`, `search`.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://yandex.ru\&sz=32)

Яндекс



Часть 3. Создать цель, если её нет

1. Перейдите в Метрику → «Цели».
2. Нажмите «Добавить цель».
3. Выберите «Поиск по сайту».
4. В поле «Название» укажите `Поиск по сайту`.
5. Если сайт использует стандартный параметр, оставьте «Определять автоматически».
6. Если используется другой параметр, нажмите «Настроить вручную» или используйте «Дополнительные настройки» в соответствии с отображаемой версией интерфейса. Укажите фактическое название GET-параметра.
7. Нажмите «Добавить цель».
8. Убедитесь, что цель появилась в списке.

Важно: цель, основанная на URL, не обязательно регистрирует поиски, которые обновляют результаты без отправки нового просмотра страницы. Создание цели не решает эту техническую особенность.

### З. Проверить регистрацию цели

Часть 1. Включить отладчик

1\. Откройте сайт с параметром `_ym_debug=2`.

Пример: `https://example.ru/?_ym_debug=2`

2. В нижней части сайта откройте отладчик Метрики.
3. Во вкладке `Counters` проверьте номер счётчика.
4. Откройте вкладку `Console`.
5. Через меню с тремя точками включите `Preserve log`.

Часть 2. Выполнить поиск

1. Нажмите значок поиска.
2. Введите существующее название товара.
3. Дождитесь результатов.
4. Не перезагружайте страницу.
5. Проверьте, появился ли новый `PageView` с параметром `search` или другим фактическим поисковым параметром.

Часть 3. Проверить отчёт

1. Откройте Метрику.
2. Перейдите в раздел «Конверсии».
3. Установите период «Сегодня».
4. Найдите цель «Поиск по сайту».
5. Проверьте показатели «Целевые визиты» и «Достижения цели».
6. При необходимости дождитесь обработки данных и обновите отчёт.

Интерпретация:

- `PageView` содержит поисковый параметр и достижение появилось в отчёте: конверсия подтверждена для проверенного сценария.
- URL изменился, но нового `PageView` нет: поиск работает, однако достижение при таком действии не подтверждено.
- `PageView` появляется только после перезагрузки: цель учитывает просмотры загруженной поисковой страницы, но не обязательно все поисковые действия.
- Счётчик отсутствует: необходимо проверить его подключение.

Источник: [Яндекс, проверка целей](https://yandex.ru/support/metrica/ru/general/check-goal?utm_source=chatgpt.com).

### И. Определить необходимость доработок

Если поиск работает, но аналитика не учитывает часть запросов, решение принимается по практической необходимости.

Не внедряйте дополнительный JavaScript автоматически.

Сначала оцените, требуется ли бизнесу точное количество внутренних поисков, собираются ли данные о коммерчески значимых действиях и будут ли результаты поиска влиять на конкретные решения.

Если такой задачи нет, сохраняйте действующую реализацию и фиксируйте ограничение измерения.

### Итоговый результат

Готово

Поиск выполняет своё назначение, возвращает правильные результаты и работает на опубликованном сайте. Если требуется полный учёт поисковых действий, он должен быть дополнительно подтверждён в Метрике.

Требует проверки

Поиск работает, но данные Метрики ещё не обработаны либо передача события не подтверждена.

Проблема

Поиск не находит существующее содержимое, ведёт на неправильные страницы или нарушает работу сайта.

Не требуется

На сайте отсутствует необходимость во внутреннем поиске.

### Результат для аналитики

- Назначение: поиск информации внутри сайта.
- Приоритет: поведенческая конверсия.
- Тип цели Метрики: «Поиск по сайту», если применима штатная регистрация.
- Основное ограничение: факт поиска не подтверждает покупку; некоторые динамические поиски не передаются автоматически.
- Использование: анализ пользовательских потребностей, навигации и качества трафика при достаточной достоверности данных.
