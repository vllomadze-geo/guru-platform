# 3.2. Проверка приоритетных URL

## 1. Что сделать (инструкция)

Проверить, что Яндекс корректно обрабатывает основную версию каждой приоритетной страницы сайта, и при необходимости отправить её на переобход.

**Зачем:** присутствие страницы в поиске ещё не гарантирует, что Яндекс получил её актуальное содержимое, правильно определил основной URL и не обнаружил технических препятствий для индексирования.

**Целевое действие:** проверить состояние одной приоритетной страницы в Яндекс Вебмастере, устранить подтверждённые ошибки и выполнить переобход, только если он необходим.

**Ожидаемый результат:**

- Яндекс получает правильную версию страницы.
- Основной URL соответствует данным проекта.
- Страница доступна поисковому роботу.
- Отсутствуют препятствия для индексирования.
- Необходимость переобхода определена, результат проверен.

Если необходимые проверки уже выполнены, их результаты актуальны и страница с тех пор не изменялась, повторять действия не нужно.

**Разграничение:** общая техническая доступность сайта и Sitemap проверяются в разделе 2. Факт присутствия страниц в поиске проверяется в 3.1. В этом шаге проверяем корректность обработки конкретного URL. Показы, запросы и позиции относятся к 3.3.

## 2. Где нажать / Как проверить (инструкция)

### А. Подготовить адрес страницы

1. Возьмите список приоритетных страниц, проверенных в шаге 3.1.
2. Выберите одну страницу.
3. Скопируйте её полный опубликованный URL из проекта.
4. Откройте URL в браузере и убедитесь, что отображается нужная страница.
5. Проверьте, нет ли уже зафиксированных результатов технической проверки и переобхода.
6. Если результаты актуальны, используйте их, не создавая повторных заявок.

**Пример для «Коричного яблока»:**

Основной URL:

`https://k-apple.ru/simvol-2027-koza`

Если у страницы ранее менялся адрес, отдельно сохраните старый URL для проверки перенаправления.

### Б. Проверить страницу в Яндекс Вебмастере

1. Откройте https://webmaster.yandex.ru/.
2. Авторизуйтесь через рабочий Яндекс ID.
3. Выберите сайт проекта.
4. В левом меню раскройте «Индексирование».
5. Нажмите «Проверка страницы».
6. Если URL уже проверялся, найдите его в списке результатов и посмотрите дату проверки.
7. Если после проверки содержимое или настройки страницы изменялись, запустите новую проверку.
8. В поле адреса введите полный URL страницы.
9. Выберите десктопную версию.
10. Отправьте ссылку на проверку с помощью кнопки запуска рядом с полем URL.
11. Дождитесь завершения обработки.
12. Нажмите «Подробнее».
13. Откройте вкладку «Версия страницы в базе».
14. Найдите раздел «Состояние в поиске».

**Правильный результат:** страница участвует в поиске.

**Дополнительно проверьте:**

- Код ответа сервера: HTTP 200 OK.
- Контент страницы: робот получает основное содержимое.
- Технические данные: отсутствуют ошибки, препятствующие индексированию.
- Дата обработки: позволяет определить актуальность результата.

Если доступна вкладка «Контент страницы», сравните её содержимое с опубликованной версией.

Проверяйте конкретные элементы: заголовок, название товара или услуги, основной текст. Если содержимое отличается, зафиксируйте расхождение.

**Важно:** HTTP 200 подтверждает доступность страницы, а не её присутствие в поисковой базе.

Если «Проверка страницы» недоступна, не создавайте повторные запросы. Переходите к альтернативной проверке.

### В. Альтернативная проверка через «Мониторинг важных страниц»

Используйте этот способ, если основной инструмент недоступен либо требуется дополнительное подтверждение состояния URL.

**Часть 1. Найти существующую страницу**

1. В Яндекс Вебмастере раскройте «Индексирование».
2. Выберите «Мониторинг важных страниц».
3. Найдите нужный URL среди отслеживаемых страниц.
4. Если адрес присутствует, повторно добавлять его не нужно.
5. Посмотрите сведения о странице.

**Часть 2. Если страницы нет**

1. Найдите поле добавления адреса.
2. Введите полный URL из проекта.
3. Нажмите «Отслеживать».
4. Убедитесь, что URL появился в списке.
5. После обработки откройте сведения о странице.

Информация обычно появляется через несколько минут, иногда обработка занимает несколько часов.

Однократное добавление URL можно использовать в Гейте 2. Дальнейшее наблюдение за изменениями относится к Гейту 5. Повторно добавлять страницу там не нужно.

**Часть 3. Проверить результаты**

Найдите:

1. Дату последнего обхода страницы.
2. Ответ сервера.
3. Версию страницы.
4. Статус в поиске.

**Ожидаемый результат:**

- HTTP 200.
- Статус «В поиске».
- Основной URL соответствует проекту.
- Нет зарегистрированных препятствий для индексирования.

Если статус отличается от «В поиске», откройте подробности или меню с тремя точками рядом со статусом. Зафиксируйте указанную причину.

**Если данных нет:** не считайте страницу ошибочной или проиндексированной без других подтверждений.

### Г. Проверить доступность страницы для индексирования

Выполняйте этот раздел, если предыдущие инструменты недоступны, сведения противоречат друг другу или Яндекс сообщил об ошибке.

**Способ 1. Анализ индексации страницы**

1. Откройте https://webmaster.yandex.ru/.
2. Перейдите в «Инструменты».
3. Выберите «Анализ индексации страницы».
4. Введите полный URL.
5. Нажмите «Проверить».
6. Дождитесь результата.

Возможные результаты:

- **«Страница доступна для индексирования»**: инструмент не обнаружил препятствий при выполненной проверке.
- **«Страница закрыта от индексирования»**: необходимо прочитать и устранить указанную причину.
- **Проверка не выполнена**: результат отсутствует, требуется дополнительная диагностика.

Этот инструмент проверяет возможность индексирования, но не подтверждает фактическое присутствие страницы в поисковой базе.

**Способ 2. Проверка ответа сервера**

1. В Яндекс Вебмастере откройте «Инструменты».
2. Выберите «Проверка ответа сервера».
3. В поле «Опрашиваемый URL» введите полный адрес страницы.
4. В поле «Робот» выберите основного поискового робота Яндекса.
5. Нажмите «Проверить».
6. Найдите HTTP-код и сообщения об ошибках.

**Ожидаемый результат:** HTTP 200 OK, без запретов и ошибок получения документа.

Если ответ отличается от 200, зафиксируйте код и причину. Исключение составляют старые URL, для которых намеренно настроено перенаправление.

Не повторяйте общую настройку сайта из шага 2.1, если ошибка не обнаружена.

### Д. Сравнить фактический URL с данными проекта

Этот раздел необходим, если у страницы несколько адресов, ранее менялся URL или есть подозрение на неправильную каноническую версию.

**Часть 1. Проверить canonical**

1. Откройте опубликованную страницу в Google Chrome.
2. Нажмите `Command + Option + U` на Mac или `Ctrl + U` на Windows.
3. Откроется исходный код страницы.
4. Нажмите `Command + F` или `Ctrl + F`.
5. Введите `canonical`.
6. Найдите элемент `rel="canonical"`.
7. Скопируйте адрес из атрибута `href`.
8. Сравните его с основным URL проекта.

**Правильный результат:** canonical указывает на утверждённую основную версию страницы.

На Tilda canonical обычно формируется автоматически после подключения собственного домена. Ручное изменение без подтверждённой ошибки не требуется.

**Часть 2. Проверить старый URL**

Выполняйте только при наличии старого адреса.

1. Откройте «Инструменты» → «Проверка ответа сервера».
2. Введите старый URL.
3. Нажмите «Проверить».
4. Посмотрите HTTP-код.
5. Если предусмотрен постоянный перенос, убедитесь, что возвращается HTTP 301.
6. Проверьте адрес назначения.
7. Убедитесь, что он совпадает с основным URL проекта.
8. Проверьте окончательный адрес отдельно: ожидается HTTP 200.

Если canonical и перенаправления уже подтверждены и изменений не было, повторная настройка не требуется.

### Е. Устранить обнаруженную ошибку

Выполняйте только тот сценарий, который соответствует фактическому результату проверки.

**Ситуация 1. Страница закрыта от индексирования на Tilda**

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь.
3. Выберите проект.
4. Найдите нужную страницу.
5. Откройте «Настройки страницы».
6. Перейдите в «SEO».
7. Откройте «Отображение в поисковой выдаче».
8. Нажмите «Задать специальные метаданные».
9. Найдите настройку «Запретить поисковикам индексировать страницу».
10. Если запрет установлен ошибочно, снимите галочку.
11. Нажмите «Сохранить изменения».
12. Опубликуйте страницу.
13. Откройте опубликованный URL.
14. Повторите проверку индексируемости в Яндекс Вебмастере.

Если запрет установлен для всего сайта через robots.txt или общие настройки, исправляйте его по уже существующей инструкции 2.1.

**Ситуация 2. Неправильный canonical**

1. Откройте Tilda и выберите проект.
2. Найдите нужную страницу.
3. Перейдите в «Настройки страницы» → «SEO».
4. Откройте «Отображение в поисковой выдаче» → «Задать специальные метаданные».
5. Найдите «Каноническая ссылка на страницу».
6. Сравните значение с основным URL проекта.
7. Устраните ошибочное ручное переопределение или укажите правильный адрес.
8. Сохраните изменения.
9. Опубликуйте страницу.
10. Повторно проверьте canonical в исходном коде опубликованной страницы.

**Ситуация 3. Неправильное перенаправление**

1. В Tilda откройте «Настройки сайта».
2. Перейдите в «SEO».
3. Откройте «Редиректы страниц (code 301)».
4. Найдите правило для старого адреса.
5. Проверьте, куда оно направляет посетителя.
6. Если правило ошибочное, исправьте адрес назначения.
7. Если корректное правило уже существует, не создавайте дубль.
8. Сохраните изменения.
9. Повторно проверьте старый URL через «Проверка ответа сервера».

Не заменяйте серверный редирект 301 блоком T223: он использует JavaScript-перенаправление.

**Ситуация 4. Ошибка HTTP или загрузки**

1. Зафиксируйте код ответа и текст ошибки.
2. Если страница не опубликована, опубликуйте её в используемой CMS.
3. Если адрес ошибочный, исправьте ссылку на окончательный URL.
4. При ошибках сервера, DNS или SSL проверьте результаты раздела 2.1 и настройки хостинга.
5. После исправления повторите «Проверка ответа сервера».
6. Убедитесь, что основная страница возвращает HTTP 200.

**Ситуация 5. «Малоценная или маловостребованная страница»**

1. Зафиксируйте точный статус.
2. Убедитесь, что технических препятствий нет.
3. Проверьте, не выбран ли вместо основного URL другой дубль.
4. Если технические настройки корректны, зафиксируйте проблему содержания или релевантности.

Содержательную SEO-оптимизацию выполняйте в Гейте 5. Переобход сам по себе не гарантирует устранение этого статуса.

### Ж. Определить, нужен ли переобход

**Отправляйте страницу на переобход, если:**

- Опубликована новая приоритетная страница, которую Яндекс ещё не обработал.
- Исправлена ошибка индексирования.
- Исправлен canonical или перенаправление.
- Изменён основной URL.
- Существенно обновлено содержание, но Яндекс продолжает использовать старую версию.

**Не отправляйте повторно, если:**

- Страница корректно индексируется.
- Существенных изменений не было.
- Заявка уже находится в очереди.
- Обработанная заявка и последующая проверка подтвердили правильное состояние страницы.

Не отправляйте на переобход `robots.txt`, Sitemap и XML-фиды: для них предусмотрены другие механизмы обработки.

### З. Отправить страницу на переобход

Выполняйте только после подтверждения необходимости.

1. Откройте https://webmaster.yandex.ru/.
2. Выберите сайт проекта.
3. В левом меню раскройте «Индексирование».
4. Нажмите **«Переобход страниц»**.
5. В поле «Выбрать сайт» выберите нужный домен.
6. Найдите список ранее отправленных страниц.
7. Проверьте, нет ли уже заявки для нужного URL.
8. Если актуальная заявка отсутствует, введите полный основной адрес страницы.

   Пример:

   `https://k-apple.ru/simvol-2027-koza`

9. Нажмите **«Отправить»**.
10. Убедитесь, что URL появился в таблице.
11. Зафиксируйте дату отправки и статус заявки.

Повторная публикация сайта только ради отправки заявки не требуется. Если вы предварительно исправляли страницу на Tilda, изменения должны быть опубликованы до отправки.

### И. Проверить результат переобхода

1. Откройте «Индексирование» → «Переобход страниц».
2. Найдите отправленный URL.
3. Посмотрите значение в колонке «Статус».

| Статус | Значение | Что делать |
|---|---|---|
| В очереди | Робот ещё не обработал заявку | Не отправлять повторно |
| Заявка обработана | Робот посетил страницу | Проверить состояние в поиске |
| Ошибка | Обработка не выполнена корректно | Найти причину, исправить, повторить |

По документации Яндекса обход обычно выполняется в пределах трёх дней. После посещения роботом обновление данных в поисковой базе может занимать до двух недель.

**Важно:** статус «Заявка обработана» не подтверждает, что страница проиндексирована.

**Контрольная проверка:**

1. Вернитесь в «Индексирование» → «Проверка страницы».
2. Найдите проверяемый URL.
3. Откройте результат через «Подробнее».
4. Проверьте «Версия страницы в базе» → «Состояние в поиске».
5. Сравните содержимое и статус с ожидаемым результатом.

Если инструмент недоступен, используйте «Мониторинг важных страниц», если URL уже отслеживается.

Дополнительное подтверждение присутствия страницы можно получить в Поиске Яндекса через оператор `url:` с полным адресом, как в шаге 3.1.

Если после переобхода страница отсутствует в поиске, повторная отправка без устранения причины не считается исправлением.

### К. Зафиксировать итог проверки

Для каждого приоритетного URL зафиксируйте:

1. Полный адрес страницы.
2. Дату проверки.
3. Источник технических данных.
4. HTTP-код.
5. Основной canonical, если проверялся.
6. Статус страницы в поиске.
7. Наличие технических ошибок.
8. Необходимость переобхода.
9. Статус заявки, если переобход выполнялся.
10. Результат повторной проверки после исправлений.

Переходите к следующему URL только после определения результата текущей страницы.

## 3. Сверка (инструкция)

| Проверка | Правильный результат |
|---|---|
| Основной URL | Совпадает с адресом проекта |
| HTTP-код основной страницы | 200 OK |
| Содержимое для робота | Соответствует нужной странице |
| Canonical | Совпадает с основным URL |
| Старые URL | Корректно перенаправляют, если существуют |
| Запреты индексирования | Отсутствуют для обязательных страниц |
| Состояние в поиске | «В поиске» или подтверждено альтернативной проверкой |
| Переобход | Выполнен только при необходимости |
| Статус заявки | Зафиксирован, если заявка отправлялась |
| Повторная проверка | Подтверждает фактический результат |
| Дублирование | Повторные настройки и заявки без необходимости отсутствуют |

### Готово

- Основной URL соответствует проекту.
- Страница корректно доступна роботу.
- Индексируемое содержимое соответствует нужной версии.
- Ошибок, препятствующих индексированию, нет.
- Присутствие страницы в поиске подтверждено.
- Если переобход был необходим, его результат проверен.

### Требует проверки

- Основной инструмент Яндекса временно недоступен, а альтернативных данных недостаточно.
- Индексируемая версия не подтверждена.
- Исправления опубликованы, но ещё не обработаны роботом.
- Заявка обработана, но состояние в поиске после неё неизвестно.

### Проблема

- Основной URL возвращает ошибочный HTTP-код.
- Обнаружен неправильный canonical.
- Установлен ошибочный запрет индексирования.
- Старый URL ведёт на неправильную страницу.
- Приоритетная страница подтверждённо исключена из поиска.
- Робот получает неправильное или неполное содержимое.

### Не требуется

Переобход не требуется, если страница уже корректно индексируется и изменений, требующих повторной обработки, не было.

Это решение относится к переобходу, а не к обязательной проверке URL.

### Подтверждённые данные проекта «Коричное яблоко»
