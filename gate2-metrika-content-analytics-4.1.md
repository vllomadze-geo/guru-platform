# 4.1. Контентная аналитика

## 1. Что сделать (инструкция)

Настроить контентную аналитику Яндекс Метрики для сбора статистики о просмотрах, доскроллах и дочитываниях текстовых материалов сайта, затем проверить правильность передачи данных и их отображение в отчётах.

**Анализируемое действие:** посетитель открыл статью и взаимодействовал с её содержимым.

Различайте:

| Показатель | Что подтверждает |
|---|---|
| Просмотр материала | Посетитель открыл размеченный материал |
| Доскролл | Посетитель прокрутил материал до конца |
| Дочитывание | Посетитель достиг конца материала с учётом методики оценки чтения Метрики |
| Время на материал | Расчётное время взаимодействия с материалом |
| Коммерческая конверсия | Заказ, заявка или другое отдельно отслеживаемое действие |

**Приоритет:** дополнительный аналитический инструмент.

**Практическая ценность:**

- Определять наиболее популярные материалы.
- Выявлять статьи с высокой и низкой вовлечённостью.
- Сравнивать источники трафика по качеству чтения.
- Определять темы и форматы, которые эффективнее привлекают аудиторию.
- Использовать результаты для развития контентной стратегии.

Для подключения используем штатную опцию Яндекс Метрики **«Контентная аналитика»**.

Метрика поддерживает разметку Schema.org (Microdata или JSON-LD) и Open Graph.

**Рекомендация для GURU:** для новых текстовых материалов на Tilda использовать Schema.org в формате JSON-LD, если подходящая разметка ещё не существует.

**Условия применения:**

- Есть статьи, новости, записи блога, обзоры или другие поддерживаемые материалы: проверяем возможность подключения.
- Контентная аналитика уже настроена и работает: повторно не подключаем.
- На сайте только карточки товаров и обычные коммерческие страницы: инструмент обычно не требуется.
- Нет подходящих материалов: отдельную настройку не выполняем.
- Для оценки эффективности достаточно стандартной статистики посещаемости: дополнительная разметка необязательна.

**Важное ограничение:** для получения полной статистики текст статьи должен содержать более 500 символов. Для материалов типа «Вопросы и ответы» действуют отдельные правила.

Контентная аналитика не требует создания дополнительных конверсионных целей.

## 2. Где нажать / Как проверить (инструкция)

### А. Проверить наличие подходящих материалов

**Часть 1. Найти публикации**

1. Откройте опубликованный сайт проекта.
2. Найдите раздел «Блог», «Статьи», «Новости», «Журнал», «Полезные материалы» или аналогичный.
3. Откройте отдельную публикацию.
4. Убедитесь, что страница содержит полноценный текстовый материал.
5. Проверьте, что основной текст содержит более 500 символов.
6. Скопируйте URL публикации.

**Часть 2. Определить тип материала**

| Тип материала | Решение |
|---|---|
| Статья | Подключать |
| Новость | Подключать |
| Публикация блога | Подключать |
| Подробный обзор | Подключать, если соответствует поддерживаемому формату |
| Вопросы и ответы | Подключать по отдельным правилам разметки |
| Карточка товара | Не использовать вместо Ecommerce |
| Страница каталога | Не требуется |
| Контактная страница | Не требуется |

Для первой проверки выбираем одну опубликованную статью. После подтверждения правильной работы можно подключать остальные.

**Ожидаемый результат:** определён подходящий материал с собственным URL.

### Б. Проверить существующую контентную аналитику

1. Откройте https://metrika.yandex.ru/.
2. Войдите через рабочий Яндекс ID.
3. Выберите счётчик нужного сайта.
4. В левом меню нажмите **«Настройки»**.
5. Откройте вкладку **«Счётчик»**.
6. Найдите настройку **«Контентная аналитика»**.
7. Проверьте, включена ли она.
8. Если включена, посмотрите выбранный тип разметки.

Возможные варианты:

- Schema.org (JSON-LD).
- Schema.org (Microdata).
- Open Graph.

**Если контентная аналитика уже включена:** повторно не включайте её. Сначала проверьте, собирается ли статистика.

**Если выключена:** пока не включайте, сначала проверяем наличие микроразметки и готовность текстовых материалов.

### В. Проверить существующую микроразметку статьи

**Часть 1. Открыть исходный код**

1. Откройте опубликованную статью в Chrome.
2. На Mac нажмите `Command + Option + U`.
3. На Windows нажмите `Ctrl + U`.
4. Откроется исходный HTML-код страницы.
5. Нажмите `Command + F` или `Ctrl + F`.

**Часть 2. Проверить Schema.org**

1. В поле поиска введите `application/ld+json`.
2. Проверьте, есть ли такой код на странице.
3. Если найден, посмотрите содержимое соответствующего блока.
4. Найдите `@type`.
5. Проверьте наличие подходящего типа, например `Article`, `NewsArticle` или `BlogPosting`.
6. Проверьте идентификатор `@id`.
7. Проверьте заголовок `headline`.
8. Найдите поле `text`.

**Важно:** наличие JSON-LD для товаров, хлебных крошек или организации не означает, что статья уже размечена для контентной аналитики.

**Часть 3. Проверить Open Graph**

1. В исходном коде найдите `og:type`.
2. Посмотрите значение.
3. Для статьи должно быть указано `article`.
4. Найдите `og:title`.
5. Сравните его с заголовком публикации.

**Результат проверки:**

- Подходящая разметка существует: проверяем её корректность.
- Разметка существует, но неполная: исправляем необходимые поля.
- Подходящей разметки нет: подготавливаем её.
- Контентная аналитика уже получает правильные данные: ничего не меняем.

Не добавляйте второй экземпляр разметки одной статьи без необходимости.

### Г. Подготовить микроразметку Schema.org JSON-LD

Выполняйте только при отсутствии подходящей разметки.

**Часть 1. Собрать исходные данные**

Откройте опубликованную статью и подготовьте:

| Поле | Что указать | Источник |
|---|---|---|
| `@context` | `https://schema.org` | Стандарт Schema.org |
| `@type` | `Article` для обычной статьи | Тип публикации |
| `@id` | Уникальный идентификатор материала | Постоянный URL статьи |
| `headline` | Фактический заголовок | Опубликованная статья |
| `text` | Полный основной текст | Содержимое статьи |
| `url` | Канонический адрес статьи | Опубликованный URL |
| `datePublished` | Фактическая дата публикации | Данные публикации, если доступны |

**Важно:** для JSON-LD Яндекс Метрика использует поле `text` для определения объёма материала. Поле `articleBody` описано в документации Метрики для формата Microdata. Не заменяйте `text` на `articleBody` в этой инструкции.

**Часть 2. Подготовить код**

Пример структуры:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "@id": "https://example.ru/article",
  "headline": "Фактический заголовок статьи",
  "text": "Полный основной текст статьи",
  "url": "https://example.ru/article"
}
</script>
```

Это шаблон, а не готовая разметка конкретной публикации.

Перед использованием:

1. Замените `https://example.ru/article` фактическим URL.
2. Замените заголовок настоящим названием статьи.
3. Вместо текста-примера укажите полный основной текст.
4. Исключите из текста меню, футер, рекламные элементы и комментарии.
5. Проверьте правильность JSON: кавычки, обратные слеши и переносы строк внутри текста должны быть корректно экранированы.
6. Если используется дата публикации, добавьте `datePublished` с реальным значением в формате ISO 8601.

**Особенность расчёта доскроллов и дочитываний**

Яндекс рекомендует указывать в `@id` или `url` ссылку с фрагментом `#`, соответствующим реальному HTML-элементу статьи.

Например, если основной текст находится внутри элемента с `id="article-content"`, идентификатор может выглядеть так:

`https://example.ru/article#article-content`

Содержимое этого HTML-элемента должно соответствовать статье.

Если публикация Tilda состоит из нескольких отдельных блоков без общего HTML-контейнера, точность определения границ текста по такому якорю нельзя гарантировать. Не подставляйте вымышленный идентификатор. Используйте действующий URL и отдельно проверьте корректность показателей чтения.

При необходимости выделения общей области статьи потребуется дополнительная настройка HTML-разметки. Это отдельная техническая задача, которую нельзя считать выполненной автоматически.

### Д. Добавить JSON-LD на страницу Tilda

**Выполняйте только после подготовки корректного кода.**

**Часть 1. Найти нужную страницу**

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь.
3. Выберите нужный проект.
4. Найдите страницу проверяемой статьи.
5. Откройте её **«Настройки»**.

**Часть 2. Открыть вставку кода**

1. В настройках страницы найдите раздел **«Вставка кода»**.
2. Найдите **«HTML-код для вставки внутрь HEAD»**.
3. Откройте редактор кода.
4. Проверьте, нет ли в поле действующей микроразметки этой статьи.
5. Если код уже существует, сохраните его копию перед изменениями.

**Часть 3. Вставить код**

1. Вставьте подготовленный JSON-LD.
2. Не удаляйте существующие корректные скрипты.
3. Нажмите **«Сохранить»**.
4. Вернитесь к редактору страницы.
5. Нажмите **«Опубликовать»**.
6. Дождитесь завершения публикации.

**Важно:** разметку одной статьи добавляем только на её страницу.

Не размещайте её в общих настройках HEAD всего сайта, иначе одинаковый материал может определяться на других страницах.

**Часть 4. Проверить публикацию**

1. Откройте опубликованную статью.
2. Нажмите `Command + Option + U` на Mac или `Ctrl + U` на Windows.
3. Найдите `application/ld+json`.
4. Проверьте наличие добавленного кода.
5. Сравните `headline`, `@id` и `text` с подготовленными данными.

**Ожидаемый результат:** на опубликованной странице присутствует корректная микроразметка выбранного материала.

### Е. Включить контентную аналитику Яндекс Метрики

Выполняйте, если подходящая настройка ещё не включена.

1. Откройте https://metrika.yandex.ru/.
2. Выберите счётчик нужного сайта.
3. Перейдите в **«Настройки» → «Счётчик»**.
4. Найдите **«Контентная аналитика»**.
5. Включите соответствующую опцию.
6. Выберите тип разметки **Schema.org (JSON-LD)**, если именно он используется для подготовленных материалов.
7. Сохраните настройки счётчика.

Названия вариантов выбора могут незначительно отличаться в обновлённом интерфейсе. Официальная документация подтверждает саму настройку и поддерживаемые форматы, но не все текущие подписи элементов выбора.

**Если на сайте уже используется корректная Microdata или Open Graph:** выбирайте фактически существующий тип. Не заменяйте разметку исключительно ради перехода на JSON-LD.

**Ожидаемый результат:** контентная аналитика включена и настроена на действующий формат разметки.

### Ж. Проверить передачу данных через отладчик

**Часть 1. Подготовить браузер**

1. Откройте Chrome в режиме инкогнито.
2. На Mac нажмите `Command + Shift + N`.
3. На Windows нажмите `Ctrl + Shift + N`.
4. Не авторизуйтесь в Яндекс Метрике в этом окне.
5. Откройте опубликованную статью.

**Часть 2. Включить отладчик**

1. Добавьте к URL статьи параметр `_ym_debug=2`.

Например:

`https://example.ru/article?_ym_debug=2`

2. Нажмите Enter.
3. Дождитесь полной загрузки.
4. В нижней части страницы откройте панель отладчика Яндекс Метрики.
5. Перейдите на вкладку **Counters**.
6. Проверьте номер счётчика.
7. Перейдите на вкладку **Publishers**.

**Часть 3. Проверить материал**

1. Найдите информацию о размеченной статье.
2. Проверьте тип разметки.
3. Проверьте заголовок.
4. Проверьте идентификатор.
5. Откройте вкладку **Console** для дополнительных сведений.
6. Убедитесь, что данные относятся к правильному счётчику и публикации.

**Ожидаемый результат:** вкладка Publishers показывает распознанный материал с корректными данными.

**Если появляется предупреждение о недостаточной длине:** проверьте поле `text` и количество символов. Для полной статистики статьи требуется более 500 символов.

**Если Publishers не показывает материал:**

1. Проверьте, установлен ли новый код Метрики.
2. Проверьте, включена ли контентная аналитика.
3. Сравните выбранный формат разметки с фактическим.
4. Проверьте наличие JSON-LD на опубликованной странице.
5. Проверьте `@type`, `@id`, `headline`, `text`.
6. Убедитесь в отсутствии синтаксических ошибок.
7. Повторите проверку после исправления.

### З. Выполнить контрольное чтение

После подтверждения микроразметки:

1. Откройте опубликованную статью в приватном окне Chrome без параметра отладчика.
2. Дождитесь полной загрузки.
3. Прочитайте начало материала.
4. Прокрутите страницу до основной части текста.
5. Продолжите чтение.
6. Дойдите до конца статьи.
7. Оставьте страницу открытой на время контрольного взаимодействия.

**Ожидаемый результат:** Метрика получает данные о просмотре размеченного материала и взаимодействии с ним.

**Важно:** прохождение контрольного сценария ещё не означает, что доскролл или дочитывание обязательно будет засчитано. Необходимо подтвердить появление и корректность соответствующих показателей в отчётах.

### И. Проверить статистику в Яндекс Метрике

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В разделе **«Отчёты»** найдите группу **«Контент»**.
4. Откройте отчёт **«Материалы»**.
5. Установите период, включающий контрольное посещение.
6. Найдите размеченную статью по заголовку.
7. Проверьте доступные показатели:
   - Просмотры материалов.
   - Доскроллы.
   - Дочитывания.
   - Время на материал.
8. Сравните название статьи и URL с исходными данными.
9. При необходимости проверьте сведения в отчёте «Сводка».

**Ожидаемый результат:** статья появилась в контентных отчётах, а данные соответствуют фактической публикации.

Метрика указывает, что отчёты по контенту появляются через несколько часов после начала получения данных.

**Если статья не появилась:**

1. Проверьте период отчёта.
2. Убедитесь, что статья действительно была просмотрена после настройки.
3. Проверьте её распознавание во вкладке Publishers.
4. Проверьте настройку контентной аналитики.
5. Дождитесь обработки данных.
6. Повторите проверку.

**Важно:** если статья присутствует в отчёте, но показатели доскроллов и дочитываний выглядят неправдоподобно, проверьте, правильно ли Метрика определяет границы материала. Особенно это важно для страниц Tilda, состоящих из нескольких текстовых блоков.

### К. Проверить отсутствие дублирования

1. Откройте исходный код статьи.
2. Найдите все элементы с типом `Article`, `NewsArticle` или `BlogPosting`.
3. Проверьте, нет ли повторной разметки одного материала.
4. Сравните значения `@id`.
5. Убедитесь, что идентификатор статьи уникален.
6. Проверьте, что разметка товара не используется как разметка статьи.
7. Повторно откройте Publishers и убедитесь, что обнаруживается нужный материал.

Не удаляйте существующую разметку, не выяснив её назначение и влияние на другие сервисы.

### Л. Определить использование контентной аналитики

После успешной проверки:

1. Откройте отчёт «Контент → Материалы».
2. Выберите период с достаточным количеством просмотров.
3. Сравните показатели разных публикаций.
4. Определите материалы с высоким интересом и низким дочитыванием.
5. Сравните источники посещений.
6. При необходимости сопоставьте интерес к материалам с уже существующими коммерческими целями.

**Важно:** не создавайте новую цель «Дочитал статью» автоматически.

Для универсальной методологии GURU предпочтительно использовать штатные отчёты контентной аналитики. Дополнительные конверсии создавать только при конкретной маркетинговой задаче.

## 3. Сверка (инструкция)

| Проверка | Правильный результат |
|---|---|
| Подходящий материал | Существует и опубликован |
| Объём текста | Более 500 символов для полной статистики статьи |
| Счётчик Метрики | Соответствует проекту |
| Код счётчика | Поддерживает контентную аналитику |
| Контентная аналитика | Включена |
| Тип разметки | Совпадает с форматом на сайте |
| `@type` | Соответствует типу публикации |
| `@id` | Уникален для материала |
| `headline` | Соответствует заголовку статьи |
| `text` | Содержит основной текст |
| URL | Соответствует опубликованному материалу |
| Границы материала | Определены корректно для анализа чтения |
| Tilda | Изменения опубликованы |
| Дубли разметки | Отсутствуют |
| Publishers | Материал распознан |
| «Контент → Материалы» | Материал и статистика отображаются |
| Показатели чтения | Не содержат выявленных искажений |

### Итоговый результат

**Готово**

- Подходящая публикация определена.
- Контентная аналитика подключена.
- Разметка соответствует требованиям Метрики.
- Материал распознаётся во вкладке Publishers.
- Статистика появилась в отчёте «Контент».
- Корректность показателей проверена.
- Нежелательное дублирование отсутствует.

**Требует проверки**

- Разметка распознана, но отчёты ещё пусты.
- Статистика находится в обработке.
- Точность доскроллов и дочитываний не подтверждена из-за особенностей HTML-структуры статьи.
- Недостаточно посещений для оценки эффективности материала.

**Проблема**

- Контентная аналитика выключена.
- Выбран неправильный формат разметки.
- Отсутствуют обязательные поля.
- JSON-LD содержит синтаксическую ошибку.
- В качестве текста учитывается всё содержимое страницы вместо статьи.
- Материал не распознаётся.
- Обнаружены противоречивые или повторяющиеся данные.

**Не требуется**

На сайте отсутствуют подходящие публикации либо для решения текущих маркетинговых задач достаточно стандартной статистики посещаемости.

### Результат для аналитики

- Назначение: анализ эффективности текстовых материалов.
- Приоритет: дополнительный аналитический инструмент.
- Инструмент: контентная аналитика Яндекс Метрики.
- Формат разметки по умолчанию: Schema.org JSON-LD.
- Основные показатели: просмотры материалов, доскроллы, дочитывания и время чтения.
- Основное ограничение: корректность анализа чтения зависит от разметки и определения границ материала.
- Использование: оценка контентной стратегии, источников трафика и вовлечённости читателей.

**После подтверждения правильного распознавания материала и появления достоверной статистики настройку 4.1 можно считать выполненной.**
