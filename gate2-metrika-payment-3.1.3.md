# 3.1.3. Подтверждённая оплата

## 1. Что сделать (инструкция)

Настроить в Яндекс Метрике отдельную конверсию, которая фиксирует фактически оплаченную покупку и может использоваться для оптимизации Яндекс Директа по оплаченным заказам.

**Подтверждённая оплата** означает, что платёжная система или учётная система компании подтвердила поступление оплаты по конкретному заказу.

Не путайте:

| Событие | Подтверждает оплату? |
|---|---|
| Добавление товара в корзину | Нет |
| Оформление заказа | Нет |
| Ecommerce `purchase` при оформлении | Не обязательно |
| Переход в платёжную систему | Нет |
| Возвращение из платёжной системы | Нет |
| Статус «Оплачен» от платёжной системы | Да, если статус достоверен |
| Подтверждённое поступление оплаты | Да |

### Как передавать оплату в Метрику

Для сайтов на Tilda возможны два основных сценария:

**Сценарий А. Онлайн-оплата**

Покупатель оплачивает заказ через подключённую платёжную систему. Tilda получает сведения о платеже, однако их отдельную передачу в Метрику необходимо настроить или подтвердить существующей интеграцией.

**Сценарий Б. Оплата после оформления**

Покупатель оформляет заказ, а оплачивает позднее: переводом, по счёту, наличными или другим способом.

Подтверждённую оплату передают в Метрику из CRM, учётной системы либо через загрузку офлайн-конверсий.

**Рекомендуемый механизм для Яндекс Директа:** отдельная цель «Подтверждённая оплата», связанная с реальным платёжным статусом заказа.

Если такой передачи ещё нет, простое создание цели в Метрике не решает задачу.

## 2. Где нажать / Как проверить (инструкция)

### А. Определить, как компания принимает оплату

1. Откройте https://tilda.cc/login/.
2. Войдите в аккаунт сайта.
3. Выберите нужный проект.
4. Нажмите «Настройки сайта».
5. В левом меню откройте «Платёжные системы».
6. Просмотрите уже подключённые способы оплаты.
7. Определите, какой способ используется покупателями:
   - Онлайн-оплата через платёжную систему.
   - Наличные.
   - Безналичный расчёт.
   - Другой предусмотренный способ.
8. Если онлайн-оплата подключена, откройте настройки соответствующей платёжной системы.
9. Убедитесь, что используется рабочее подключение, а не демонстрационный или тестовый режим.
10. Если способ оплаты уже настроен правильно, ничего не изменяйте.

**Ожидаемый результат:** установлен фактический источник, который подтверждает оплату.

### Б. Найти подтверждение оплаты в Tilda

1. Вернитесь на панель управления проектом.
2. Откройте раздел «Заявки».
3. Найдите существующий заказ, по которому известен результат оплаты.
4. Откройте карточку заказа.
5. Найдите блок «Оплата».
6. Прочитайте отображаемый статус.

В зависимости от платёжной системы можно увидеть:

- «Ожидает оплаты».
- «Оплачено».
- «Не оплачено».

Если оплата выполнена через подключённую внешнюю платёжную систему, Tilda обновляет статус автоматически при получении подтверждения.

Если заказ оформлен с оплатой наличными или безналичным расчётом, статус может изменяться сотрудником вручную.

**Поэтому ручной статус необходимо дополнительно сверять с реальным подтверждением поступления денег.**

Если используется «Личный кабинет интернет-магазина», сведения об оплате также могут отображаться в разделе «Заказы».

**Сверка:**

1. Найдите идентификатор заказа.
2. Определите фактически поступившую сумму.
3. Установите дату и время оплаты.
4. Для онлайн-платежа откройте личный кабинет подключённой платёжной системы и найдите соответствующую успешную операцию.
5. Сравните номер заказа, сумму и статус.

**Ожидаемый результат:** существует конкретный заказ с подтверждённым платежом.

Не изменяйте неоплаченный заказ на «Оплачен» только ради проверки аналитики.

### В. Проверить существующие цели Яндекс Метрики

1. Откройте https://metrika.yandex.ru/.
2. Авторизуйтесь под рабочим Яндекс ID.
3. Выберите счётчик сайта.
4. В левом меню нажмите «Цели».
5. Найдите цели, связанные с оплатой.
6. Отдельно проверьте наличие:
   - «CRM: Заказ оплачен».
   - Ранее созданной цели подтверждённой оплаты.
   - «Ecommerce: покупка».
   - «Возвращение из платёжной системы».
7. Для существующей ручной цели откройте настройки через значок редактирования.
8. Установите, какое событие вызывает её достижение.

**Как интерпретировать результаты:**

- «CRM: Заказ оплачен» может подтверждать полученный статус оплаты, если подключена передача CRM-данных.
- Отдельная цель оплаты может работать, если подтверждённое событие передаётся интеграцией.
- «Ecommerce: покупка» фиксирует событие покупки, которое может происходить ещё при оформлении.
- «Возвращение из платёжной системы» фиксирует возврат пользователя на сайт, а не сам платёж.

**Если уже существует правильно работающая цель подтверждённой оплаты, повторно создавать её не нужно.**

### Г. Выбрать способ передачи подтверждённой оплаты

**Вариант 1. Данные об оплаченных заказах уже передаются из CRM**

1. В Метрике откройте «Цели».
2. Найдите «CRM: Заказ оплачен».
3. Откройте «Конверсии».
4. Найдите эту же цель.
5. Выберите период, в котором были реально оплаченные заказы.
6. Убедитесь, что достижения зарегистрированы.
7. Сопоставьте несколько достижений с оплаченными заказами.

При передаче статуса `PAID` через официальную интеграцию CRM Метрика может автоматически фиксировать цель «CRM: Заказ оплачен».

Если передача данных уже работает, повторно загружать те же оплаты другим способом не требуется.

Если в Метрике нет такой цели и CRM ещё не интегрирована, потребуется настроить передачу данных из используемой CRM по официальной инструкции Яндекса.

**Вариант 2. CRM-интеграции нет, используем офлайн-конверсии**

Метрика позволяет загрузить подтверждённые оплаты из файла CSV.

Для этого необходимо связать оплату с ранее зарегистрированным посещением сайта.

Поддерживаются идентификаторы:

- `ClientID`.
- `UserID`.
- `yclid`.
- `PurchaseId`.

Для магазина с уже настроенной электронной коммерцией удобно использовать `PurchaseId`, если он передаётся и совпадает с идентификатором покупки, который можно сопоставить с оплаченной операцией.

**Важно:** обычный номер заявки Tilda и `PurchaseId` Метрики не обязательно совпадают. Использовать один вместо другого без проверки нельзя.

### Д. Проверить наличие PurchaseId

Этот этап необходим при выборе загрузки оплаты через идентификатор Ecommerce-покупки.

1. Откройте Яндекс Метрику.
2. В левом меню нажмите «Отчёты».
3. Откройте «Электронная коммерция».
4. Выберите «Содержимое заказов».
5. Установите период, в который был оформлен нужный заказ.
6. Найдите соответствующую покупку.
7. Посмотрите идентификатор покупки.
8. Откройте заказ в Tilda или системе приёма.
9. Сопоставьте идентификаторы, состав товаров, сумму и время.

**Ожидаемый результат:** установлено соответствие между Ecommerce-покупкой и реально оплаченным заказом.

Если идентификаторы не удаётся сопоставить, не используйте случайный номер заявки в качестве `PurchaseId`.

В этом случае необходим другой идентификатор, который был собран во время посещения сайта и сохранён вместе с заказом.

Без подходящего идентификатора Метрика не сможет надёжно связать оплату с нужным визитом.

### Е. Создать цель подтверждённой оплаты

Выполняйте только при отсутствии существующей подходящей цели и если подготовлен способ передачи оплаты.

1. Откройте Яндекс Метрику.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Цели».
4. Убедитесь, что аналогичная цель ещё не существует.
5. Нажмите «Добавить цель».
6. На экране «Новая цель» найдите раздел «Пользовательские события».
7. Выберите **«Целевое событие · ex JS-событие»**.
8. В поле названия укажите:

   `Подтверждённая оплата`

9. В поле идентификатора события укажите уникальное значение, например:

   `payment_confirmed`

10. Убедитесь, что этот идентификатор не используется другой целью.
11. Нажмите «Добавить цель».
12. Вернитесь к списку целей.
13. Найдите созданную цель.
14. Сохраните её числовой ID и идентификатор события.

**Важно:** после создания цель ещё не работает автоматически. В неё необходимо передавать подтверждённые оплаты.

Идентификатор `payment_confirmed` является предлагаемым обозначением, а не встроенной целью Яндекса.

### Ж. Настроить передачу через CSV

Выполняйте, если выбрана загрузка офлайн-конверсий.

**Часть 1. Подготовить данные**

1. Найдите заказ с реально подтверждённой оплатой.
2. Получите его корректный `PurchaseId` либо другой поддерживаемый идентификатор.
3. Запишите дату и время фактического подтверждения платежа.
4. Получите фактически оплаченную сумму.
5. Определите валюту платежа.
6. Подготовьте CSV-файл с соответствующими данными.

Для варианта `PurchaseId` поля файла:

| Поле CSV | Что указать |
|---|---|
| `PurchaseId` | Идентификатор Ecommerce-покупки |
| `Target` | `payment_confirmed` |
| `DateTime` | Время подтверждения оплаты в формате Unix timestamp, секунды |
| `Price` | Фактическая сумма, передаваемая как доход цели |
| `Currency` | Код валюты, например `RUB` |

`DateTime` должен соответствовать реальному моменту оплаты. Для перевода даты используйте инструмент, учитывающий часовой пояс. Не вводите дату в обычном формате вместо Unix timestamp.

Сохраните CSV в кодировке UTF-8.

**Часть 2. Загрузить данные в Метрику**

1. Откройте Яндекс Метрику.
2. Выберите счётчик.
3. В левом меню нажмите «Настройки».
4. В верхнем меню выберите «Загрузка данных».
5. Найдите блок «Загрузка офлайн-конверсий».
6. При необходимости включите учёт офлайн-конверсий.
7. Нажмите «Загрузить данные».
8. В появившемся окне выберите тип привязки, соответствующий идентификатору в CSV.
9. Выберите подготовленный файл.
10. При необходимости добавьте понятный комментарий к загрузке.
11. Нажмите «Загрузить данные».
12. Дождитесь сообщения о результате.

**Ожидаемый результат:** файл принят на обработку.

Если система сообщает об ошибке формата, откройте описание ошибки и исправьте соответствующее поле.

Не загружайте тот же платёж повторно без необходимости.

### З. Проверить регистрацию подтверждённой оплаты

После загрузки данных:

1. Запомните время загрузки.
2. Подождите обработки данных.
3. В Метрике нажмите «Отчёты».
4. Откройте «Сквозная аналитика».
5. Выберите «Офлайн-конверсии».
6. Установите период, включающий загруженную конверсию.
7. Найдите запись по `PurchaseId` или другому переданному идентификатору.
8. Посмотрите статус «Привязка к визиту».
9. Проверьте указанную цель и данные оплаты.

**Ожидаемый результат:** конверсия привязана к посещению, а идентификатор цели соответствует `payment_confirmed`.

По документации Яндекса загруженные офлайн-конверсии появляются в отчётах **в течение 3 часов после загрузки**.

Если по истечении этого срока результата нет:

1. Откройте «Настройки» → «Загрузка данных».
2. Найдите последнюю загрузку.
3. Проверьте результат обработки.
4. Откройте «Отчёты» → «Сквозная аналитика» → «Офлайн-конверсии».
5. Найдите причину отсутствия привязки, если запись присутствует.

Распространённые причины:

- Неизвестный идентификатор цели.
- Неправильный `PurchaseId`.
- Отсутствие соответствующего визита.
- Неверная дата конверсии.
- Истечение периода привязки.

**Срок привязки:** офлайн-конверсию необходимо передать так, чтобы между подходящим визитом и обработкой данных прошло не более 21 дня.

Для автоматической передачи статусов из CRM может действовать расширенный механизм обновления уже привязанных заказов. Это отдельный способ интеграции.

### И. Проверить достижение цели в «Конверсиях»

1. Откройте Яндекс Метрику.
2. В левом меню нажмите «Конверсии».
3. Выберите период, включающий загруженный платёж и связанный визит.
4. Найдите цель «Подтверждённая оплата».
5. Посмотрите показатель «Достижения цели».
6. Сравните результат с успешно привязанными офлайн-конверсиями.

**Ожидаемый результат:** Метрика зарегистрировала подтверждённую оплату.

Если конверсия появилась в отчёте офлайн-данных, но не видна в текущем представлении «Конверсий», проверьте период, сегменты и модель атрибуции.

Не создавайте вторую цель, если первая уже существует и данные находятся в обработке.

### К. Если оплата происходит через подключённую платёжную систему

Для автоматизации используйте подтверждённое событие со стороны платёжной системы или интегрированной CRM.

Правильная последовательность:

1. Платёжная система подтверждает успешное списание.
2. Tilda или учётная система обновляет статус заказа.
3. Интеграция передаёт факт подтверждённой оплаты в Метрику.
4. Метрика связывает событие с заказом и посещением.
5. Достижение цели появляется в отчёте.

Если в вашем проекте такого механизма нет, его необходимо настроить отдельно. Одного включения Ecommerce и создания цели недостаточно.

**Не используйте событие, которое отправляется только при открытии страницы благодарности, для подтверждения фактической оплаты.**

Возврат из платёжной системы может происходить и без успешного платежа.

### Л. Подготовить цель для Яндекс Директа

После успешной проверки:

1. Откройте Метрику → «Цели».
2. Найдите «Подтверждённая оплата».
3. Скопируйте ID цели.
4. Убедитесь, что зарегистрированы реальные оплаченные заказы.
5. Проверьте достоверность суммы, если передаётся доход.
6. Определите, будет ли эта цель основной для рекламной стратегии.

Если в одной стратегии используются и «Оформленный заказ», и «Подтверждённая оплата», необходимо учитывать, что это два этапа одной воронки.

Не складывайте их достижения как две независимые продажи.

При стратегии с оплатой за конверсии нужно отдельно учитывать стоимость достижения каждой выбранной цели.

## 3. Сверка (инструкция)

| Проверка | Критерий успеха |
|---|---|
| Источник платежа | Определён |
| Статус оплаты | Подтверждён |
| ID заказа | Установлен |
| Сумма оплаты | Соответствует фактическому платежу |
| Цель Метрики | Создана или найдена без дублей |
| Способ передачи | Настроен |
| Идентификатор привязки | Корректен |
| Передача данных | Успешна |
| Привязка к визиту | Подтверждена |
| «Конверсии» | Достижение зарегистрировано |

### Итоговый статус

**Готово**

Оплата фактически подтверждена, событие передано в Метрику, конверсия связана с соответствующим посещением и отражена в отчётах.

**Требует проверки**

Платёж подтверждён, но конверсия ещё обрабатывается или привязка не завершена.

**Проблема**

Оплата не передаётся, используется неправильный идентификатор, отсутствует связь с визитом либо цель регистрирует неуспешный платёж.

**Не требуется**

Отдельная конверсия оплаченных продаж объективно не применяется к выбранной бизнес-модели. Отсутствие онлайн-оплаты само по себе не является основанием для этого статуса, если клиенты оплачивают заказы позднее.

### Результат для аналитики

- Назначение: подтверждённая оплата.
- Приоритет: основная бизнес-конверсия.
- Источник истины: платёжная или учётная система.
- Предпочтительный механизм: подтверждённый статус оплаты из CRM либо офлайн-конверсия с привязкой к визиту.
- Использование: анализ оплаченных продаж и оптимизация Яндекс Директа.

Следующая цель рассматривается только после подтверждения работоспособности этой конверсии либо обоснованного статуса «Не требуется».
