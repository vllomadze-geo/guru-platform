## WRITE

- Заголовок карточки теперь равен только ручному `publication.title`; до ввода показан нейтральный номер публикации.
- Новая публикация получает пустое лаконичное название. Одноразовая миграция очищает прежние явно автосгенерированные значения и копии имени идеи, сохраняя самостоятельные ручные названия.

- Порядок полей сделан вертикальным: название, тема, формат, площадки, дата, ссылка, статус, смысл, условное описание/бриф, содержимое, результаты.
- `Смысл` вынесен из брифа и продолжает читать `insight` исходной идеи живьём.
- Для видео скрывается `Описание` и показывается одноколоночный бриф: Хук → Сюжет / раскадровка → CTA → Хронометраж. Для невидео действует обратное правило.
- Скрытие не очищает `description` или `creativeBrief` в данных.

- карусель: бриф скрыт, описание показано с прежним значением;
- возврат к видео: описание снова скрыто, заполненный бриф восстановлен без потерь;
- изменение `Идеи` сразу обновляет `Смысл`;

## Банк идей и drag-and-drop · v2.3.139

- Перед понедельником добавлена отдельная колонка `Банк идей`; в ней автоматически собираются сформулированные идеи без даты.
- Карточка идеи стала draggable. Drop в день записывает его дату, перенос между днями меняет дату, drop обратно в банк очищает только дату размещения.
- После каждого переноса состояние сохраняется и календарь вместе со сводкой обновляется без копирования идеи.
- Старые выпадающие списки `Разместить идею` удалены из календаря.
- Колонки получили минимальную рабочую ширину и горизонтальную прокрутку: заголовки больше не разбиваются по одной букве. Банк закреплён слева при прокрутке.
- Браузерный тест выполняет полный маршрут `банк → понедельник → среда → банк → среда`, проверяет отсутствие дублей и сохранение даты.

## Durable-сохранение календаря · v2.3.140

- Причина потери даты: drag-and-drop не генерирует `input/change`, поэтому вкладка не помечалась изменённой; при быстрой перезагрузке стартовая облачная гидратация могла заменить свежий localStorage старым облачным снимком.
- `guruPersistStateFast` получил системный режим `durable`: он синхронно сохраняет workspace, ставит маркер подтверждённой локальной мутации и отмечает вкладку изменённой.
- Drop и действие `В банк` используют durable-сохранение непосредственно до перерендера календаря.
- При старте более новый durable-маркер локальной копии имеет приоритет над старым облачным маркером; локальная версия отправляется в облако вместо потери изменения.
- В smoke-тест добавлен отдельный сценарий: перенос на другую дату → немедленная hard reload без промежуточного сохранения формы → проверка даты после полной гидратации.
