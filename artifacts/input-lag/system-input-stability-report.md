# Устойчивость ввода и сохранения

## Причина

- Путеводитель проверял актуальность кэша через `JSON.stringify(state)` на главном потоке. На изолированной копии «Коричного яблока» сериализация 23,9 МБ занимала около 0,2 с при каждом таком обращении.
- Любой ввод внутри блока сравнения, включая ещё не отправленную форму добавления конкурента, попадал в общий обработчик таблицы и запускал отложенный пересчёт Gate 1.
- Общий обработчик ввода отменял уже отправленный в Worker снимок сохранения даже для черновых и экранных полей, которые не меняют проект и не вызывают новое сохранение.
- В «Не хватает» для колонки конкурента использовался весь текст заголовка таблицы вместе с кнопкой удаления и подписью типа.

## Изменения

- В версии кэша путеводителя используется счётчик изменений экрана и идентичность проекта; в проект не добавлено поле версии. Реальные изменения и события ввода инвалидируют кэш, а черновая форма и экранные фильтры его не трогают.
- Черновая форма не запускает пересчёт Gate 1. Табличный обработчик принимает только собственные поля конкурента.
- Для черновой формы и экранных фильтров сохранён уже выполняющийся снимок Worker; для редактируемых полей прежняя инвалидация остаётся.
- В подсказке «Не хватает» выводится только название конкурента.

## Проверка

- `system-input-stability-smoke`: изолированная копия проекта с 119 конкурентами; ввод черновика 9,4 мс, версия путеводителя 0,1 мс; состояние проекта до/после ввода идентично; ожидающее сохранение завершилось и записало точный снимок; заголовок «Не хватает» содержит только имя. Исходный файл не изменён.
- `workspace-save-worker-smoke`, `platform-input-performance-smoke`, `gate1-responsiveness-smoke`, `gate1-company-search-guide-smoke` — прошли.
- Смоуки раскрывашек компаний и запросов прошли на четырёх проектах.
- `gate12-now-readiness-smoke` — прошёл: статусы страниц и навигации совпали, сериализованный проект до/после идентичен (28 121 855 байт, 259 полей времени).

Первичная полная сборка путеводителя после загрузки большого проекта всё ещё занимает около 4 с; этот расчёт выполняется вне обработчика чернового ввода. Push и публикация не выполнялись.
