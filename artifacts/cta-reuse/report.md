# Выбор существующих CTA

Сборка: `2.3.526+7e8b199597f7`. Базовый коммит: `4486bf9a78f1d482f69ad435fd1c5a2c96c890e6`. Push и публикация не выполнялись.

## Решение

В блоке «Оффер и CTA · Продукт/Услуга» у каждого уровня CTA появилась кнопка «Из существующих». Компактный список содержит поиск и подпись источника. Продукты, существующие категории продуктов и компания разделены. Основной CTA выбирается только из основных, вторичный из вторичных, альтернативный из альтернативных. Совпадающие тексты одного владельца показываются один раз. Архивные записи, удалённые продукты и записи чужого проекта исключены.

Список читает существующие `gate0ScopedValuesV194`, `catalogItemsV189`, `productRegistryV185`. Нового хранилища и миграций нет. Старый `offer.cta` читается только как основной CTA. Выбор копирует текст в конкретное поле через существующий обработчик ввода и автосохранения. Исходные офферы не меняются. Статусы готовности и данные других блоков не менялись вручную.

Расчёт списка выполняется по запросу пользователя. Поиск обновляет только список. Escape и кнопка «Закрыть» возвращают фокус; выбор возвращает курсор в поле. Клик снаружи закрывает список. На узких экранах ширина ограничена размером экрана.

## Изменённые файлы в этой задаче

- app.js: кнопки, чистый сбор вариантов, выбор и позиционирование списка.
- styles.css: оформление списка и кнопок, перенос заголовков на узком экране.
- scripts/gate0-cta-reuse-smoke.mjs: профильная проверка.

`changes.patch` содержит только runtime-правки этой задачи. Прежние изменения репозитория сохранены.

## Проверки

| Проверка | Результат |
| --- | --- |
| gate0-cta-reuse-smoke | PASS |
| gate0-offer-foundation-source-smoke | PASS |
| gate0-company-offer-smoke | FAIL до и после правки, одна и та же строка 168 |
| npm run build | PASS, 42 matching assets |
| node --check и git diff --check | PASS |

Старый тест компании ожидает пять полей сразу после открытия пустой карточки, хотя действующий редактор рисует поля для записей офферов. При отсутствии записей он показывает кнопку добавления. Повтор на копии кода до текущей задачи подтвердил такое же падение. Старый тест не изменялся.

Новый smoke подтвердил: чистоту чтения (включая полностью замороженную копию), разделение ролей и владельцев, фильтрацию архивных и чужих записей, удаление повторов, поиск, закрытие клавиатурой, неизменность всех других записей при выборе, обновление превью, автосохранение в изолированном Storage, сохранность значения после JSON round trip, отсутствие ошибок браузера, размещение списка в узком окне. После smoke дополнительно изменён только CSS переноса мобильных заголовков; финальный вид снят отдельно.

SHA256 исходного экспорта до и после: `4df7d838dca5e8ea2d9112e5bf1a8ba69799d6a453546bd346c4bc7e4a76cc37`.

## Источники решения

- Apple HIG, Popovers: https://developer.apple.com/design/human-interface-guidelines/popovers/
- Apple HIG, Menus: https://developer.apple.com/design/human-interface-guidelines/menus
- MDN, Popover API: https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using

Использованы компактный временный список по кнопке, логические группы и штатное закрытие списка. Для веб-реализации использован Popover API с доступным названием, фокусом, Escape и резервным показом в браузере без API.
