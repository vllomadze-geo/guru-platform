# 4.2. Яндекс Тег Менеджер

## 1. Что сделать (инструкция)

Проверить подключение Яндекс Тег Менеджера к действующему счётчику Яндекс Метрики, убедиться в доступности контейнера и сохранении работоспособности существующих аналитических интеграций.

**Основное действие:** подключить или проверить Яндекс Тег Менеджер без повторной установки счётчика и создания дублирующих тегов.

**Зачем необходимо:**

- Централизованно управлять аналитическими и рекламными тегами.
- Подключать дополнительные сервисы без постоянного редактирования кода сайта.
- Настраивать условия срабатывания новых событий.
- Проверять изменения до их публикации.
- Контролировать версии и права пользователей.

**Приоритет:** дополнительный аналитический инструмент.

Различайте:

| Компонент | Назначение |
|---|---|
| Счётчик Метрики | Собирает данные о посещениях и действиях |
| Контейнер | Объединяет настройки Тег Менеджера |
| Тег | Выполняет код для определённой задачи |
| Триггер | Определяет момент запуска тега |
| Переменная | Передаёт значение в тег или триггер |
| Бандл | Готовая комбинация тега, триггера и переменной |
| Шаблон | Основа для создания тега или переменной |
| Версия контейнера | Зафиксированный набор настроек |

**Условия применения:**

- Тег Менеджер уже подключён: повторно не подключаем.
- Счётчик Метрики работает: используем существующий счётчик.
- Дополнительные теги не требуются: сохраняем контейнер без изменений.
- Нужно подключить новый сервис: сначала проверяем действующие интеграции.
- Аналогичный тег уже существует: не создаём дубль.
- Нет практической необходимости в управлении тегами: дополнительные настройки не выполняем.

**Важно:** Яндекс Тег Менеджер не заменяет Яндекс Метрику. Для его включения не требуется второй счётчик или отдельный код на сайте.

**Ожидаемый результат:** контейнер доступен, существующие интеграции работают, нежелательное дублирование отсутствует. Новые теги создаются только при возникновении конкретной задачи.

## 2. Где нажать / Как проверить (инструкция)

### А. Проверить действующий счётчик Яндекс Метрики

**Часть 1. Открыть счётчик**

1. Откройте https://metrika.yandex.ru/.
2. Войдите через рабочий Яндекс ID.
3. Выберите нужный сайт.
4. Посмотрите название сайта и числовой номер счётчика.
5. Убедитесь, что они соответствуют проекту.

**Часть 2. Проверить интеграцию с Tilda**

Если сайт создан на Tilda:

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь.
3. Выберите нужный проект.
4. Перейдите в **«Настройки сайта»**.
5. В левом меню нажмите **«Аналитика»**.
6. Найдите раздел **«Яндекс Метрика»**.
7. Посмотрите подключённый номер счётчика.
8. Сравните его с номером в Яндекс Метрике.

**Правильный результат:** номера совпадают, счётчик передаёт статистику.

**Если счётчик уже работает:** ничего не меняйте.

**Если счётчик отсутствует:**

1. Проверьте, не установлен ли он другим способом.
2. Если установки действительно нет, подключите существующий счётчик через Tilda.
3. Сохраните настройки.
4. Опубликуйте все страницы сайта.
5. Проверьте работу счётчика.

Не устанавливайте второй экземпляр счётчика.

### Б. Проверить, подключён ли Тег Менеджер

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В левом меню Метрики найдите **«Тег Менеджер»**.
4. Нажмите на него.
5. Дождитесь открытия интерфейса.

В верхней части экрана должны отображаться:

- Название «Тег менеджер».
- Название или номер контейнера.
- Выбранный контейнер.
- Кнопка «Предварительный просмотр».
- Кнопка «Опубликовать».

**Если интерфейс открылся:** подключение уже существует. Повторно включать инструмент не требуется.

**Если Тег Менеджер недоступен:**

1. Вернитесь в Метрику.
2. Откройте **«Настройки» → «Счётчик»**.
3. Найдите переключатель **«Тег менеджер»**.
4. Проверьте его состояние.
5. Если он выключен, попросите владельца счётчика включить его.
6. При наличии прав владельца включите переключатель.
7. Нажмите «Сохранить».
8. Повторно откройте Тег Менеджер.

**Важно:** первоначально включить инструмент может только владелец счётчика.

Настройку «Пользовательский HTML» без необходимости не включайте.

### В. Проверить контейнер и его состояние

**Часть 1. Найти контейнер**

1. Откройте Яндекс Метрику.
2. Выберите нужный счётчик.
3. Нажмите «Тег Менеджер».
4. В верхней части интерфейса найдите надпись **«Контейнер · ID»**.
5. Посмотрите числовой идентификатор.
6. Проверьте, какой контейнер выбран.

**Часть 2. Открыть обзор**

1. В левом меню Тег Менеджера нажмите **«Обзор»**.
2. Найдите блок **«Текущая версия»**.
3. Проверьте, имеются ли неопубликованные изменения.
4. Найдите блок **«Опубликованная версия»**, если контейнер уже публиковался.
5. Посмотрите номер версии и дату публикации.
6. Проверьте состав изменений в рабочей области.

Различайте:

| Состояние | Значение |
|---|---|
| Текущая версия | Рабочая область с настройками |
| Опубликованная версия | Настройки, опубликованные для посетителей |
| Добавлено | Новый объект |
| Изменено | Изменён существующий объект |
| Удалено | Объект удалён из рабочей области |

**Если изменений нет:** публиковать новую версию не требуется.

**Если обнаружены неизвестные изменения:** не публикуйте их до выяснения назначения.

**Если опубликованной версии ещё нет:** проверьте наличие тегов. Для пустого контейнера отсутствие опубликованной версии не означает ошибку.

### Г. Проверить существующие теги

**Часть 1. Открыть список**

1. В левом меню Тег Менеджера нажмите **«Теги»**.
2. Дождитесь загрузки списка.
3. Проверьте наличие существующих тегов.
4. Если теги есть, посмотрите их названия и статусы.
5. Откройте настройки каждого тега, назначение которого необходимо уточнить.
6. Проверьте привязанные триггеры.

**Часть 2. Исключить дублирование**

Сравните существующие теги с интеграциями сайта.

| Существующая настройка | Решение |
|---|---|
| Яндекс Метрика через Tilda | Не устанавливать повторно |
| Ecommerce через Tilda | Не дублировать события |
| Отправка заявки | Не создавать второе событие без необходимости |
| Клик по телефону | Проверить существующую цель |
| Поиск по сайту | Учитывать уже принятое решение об аналитике поиска |
| Сторонний пиксель | Проверить наличие действующей установки |

**Правильный результат:** назначение каждого существующего тега понятно, нежелательное дублирование отсутствует.

**Если список тегов пуст:** это допустимо. Не создавайте технические теги исключительно ради заполнения контейнера.

### Д. Проверить триггеры

1. В левом меню нажмите **«Триггеры»**.
2. Просмотрите список.
3. Если триггеры существуют, откройте их настройки.
4. Проверьте название, тип и условие срабатывания.
5. Установите, какие теги используют соответствующие триггеры.

Основные типы:

| Тип триггера | Назначение |
|---|---|
| Просмотр страницы | Загрузка страницы |
| Клик | Нажатие на элемент |
| Отправка формы | Стандартное событие отправки формы |
| Специальное событие | Пользовательское событие |
| История изменений | Изменение URL без перезагрузки |
| Таймер | Срабатывание по интервалу времени |
| Глубина прокрутки | Достижение заданного уровня прокрутки |
| Видимость элемента | Появление элемента в области просмотра |

**Важно:** триггер сам по себе не отправляет конверсию. Для выполнения действия к нему должен быть привязан тег.

Некоторые формы и интерактивные элементы Tilda используют JavaScript. Поэтому стандартный триггер «Отправка формы» не следует считать работающим без контрольного теста.

**Если триггеров нет:** это нормальное состояние для контейнера, в котором не настроены дополнительные сценарии.

### Е. Проверить переменные

1. В левом меню нажмите **«Переменные»**.
2. Просмотрите доступные переменные.
3. Различайте встроенные и пользовательские переменные.
4. Если пользовательские переменные есть, откройте их настройки.
5. Проверьте назначение и источник данных.

Примеры встроенных переменных:

| Переменная | Значение |
|---|---|
| Page URL | Полный адрес страницы |
| Page Path | Путь страницы |
| Page Hostname | Домен |
| Click URL | Адрес ссылки |
| Click Text | Текст элемента |
| Form ID | Идентификатор формы |

**Правильный результат:** переменные соответствуют задачам тегов и триггеров.

Если дополнительные переменные не требуются, создавать их не нужно.

### Ж. Проверить бандлы

**Бандлы являются отдельной функцией Яндекс Тег Менеджера.**

Бандл содержит готовую комбинацию тега, триггера и переменной. Он может публиковаться отдельно от обычного контейнера.

**Часть 1. Открыть список**

1. В левом меню нажмите **«Бандлы β»**.
2. Посмотрите, есть ли подключённые бандлы.
3. Если есть, проверьте их названия и назначение.
4. Определите, какие интеграции они используют.

**Часть 2. Исключить дублирование**

1. Сравните функции бандлов с существующими тегами.
2. Проверьте, не выполняют ли они одинаковые действия.
3. Убедитесь, что бандлы не дублируют уже работающие интеграции Tilda.

**Если бандлов нет:** ничего добавлять не требуется.

**Важно:** пустой список обычных тегов не гарантирует отсутствия дополнительных действий, если отдельно опубликованы бандлы.

Подключение новых бандлов выполняется только при конкретной задаче и наличии необходимых прав.

### З. Проверить историю версий

1. В левом меню нажмите **«История версий»**.
2. Просмотрите список опубликованных версий.
3. Найдите последнюю опубликованную версию.
4. Посмотрите её номер, дату и автора.
5. При необходимости откройте сведения о составе версии.

**Ожидаемый результат:** понятно, какая конфигурация была опубликована и какие изменения в неё входили.

Если контейнер ранее не публиковался, история может быть пустой.

**Важно:** возможность выбрать предыдущую версию в качестве последней отмечена в документации Яндекса как находящаяся в разработке. Не рассчитывайте на автоматический откат одной кнопкой без проверки доступности функции.

### И. Проверить шаблоны

**Часть 1. Личные шаблоны**

1. В левом меню нажмите **«Шаблоны»**.
2. Посмотрите, имеются ли пользовательские шаблоны.
3. Если есть, проверьте их назначение и статус.
4. Не изменяйте неизвестные шаблоны.

**Часть 2. Каталог шаблонов**

1. В левом меню нажмите **«Каталог шаблонов»**.
2. Ознакомьтесь с доступными готовыми решениями.
3. Не устанавливайте дополнительные шаблоны без конкретной необходимости.

**Рекомендация:** при подключении нового сервиса сначала проверять наличие подходящего шаблона.

Пользовательский HTML применять, только если штатного решения недостаточно и безопасность стороннего кода проверена.

### К. Проверить права доступа

Выполняйте, если с аналитикой работают несколько пользователей.

**Часть 1. Открыть доступы**

1. В левом меню нажмите **«Доступы»**.
2. Просмотрите список пользователей.
3. Проверьте назначенные роли.
4. Убедитесь, что доступ имеют только уполномоченные специалисты.

**Часть 2. Настроить доступ при необходимости**

1. Нажмите **«Настроить доступы»**.
2. Выберите нужного пользователя.
3. Если пользователь отсутствует, добавьте его Яндекс ID.
4. Выберите необходимые права.
5. Нажмите **«Сохранить»**.

Основные уровни доступа:

| Уровень | Возможности |
|---|---|
| Просмотр контейнера | Изучение существующих настроек |
| Редактирование контейнера | Изменение тегов, триггеров и переменных |
| Публикация контейнера на сайт | Публикация версии |
| Управление доступами | Выдача прав другим пользователям |
| Управление бандлами | Работа с бандлами |

**Важно:** право редактирования контейнера не означает автоматически право публикации.

Если доступы уже настроены правильно, ничего менять не требуется.

### Л. Определить необходимость новых тегов

Перед созданием нового тега необходимо установить конкретную задачу.

**Часть 1. Определить действие**

Например:

- Подключение дополнительного рекламного пикселя.
- Передача специального пользовательского события.
- Отслеживание нестандартного взаимодействия.
- Подключение внешней аналитической системы.

**Часть 2. Проверить существующую настройку**

1. Откройте список тегов.
2. Проверьте бандлы.
3. Проверьте интеграции Tilda.
4. Проверьте действующие цели Метрики.
5. Убедитесь, что необходимое действие ещё не отслеживается.

**Часть 3. Подготовить данные**

Перед созданием тега должны быть известны:

| Данные | Откуда получить |
|---|---|
| Название сервиса | Из задачи проекта |
| Назначение тега | Из требований к аналитике |
| Идентификатор | Из кабинета подключаемого сервиса |
| Условие срабатывания | Из фактического действия пользователя |
| Передаваемые параметры | Из документации сервиса |

**Если конкретной задачи нет:** новые теги не создаём.

### М. Создать новый тег при необходимости

Выполняйте только после определения конкретной задачи.

1. Откройте **«Тег Менеджер»**.
2. В левом меню нажмите **«Теги»**.
3. Нажмите кнопку создания тега. В документации Яндекса она называется **«Добавить тег»**.
4. Откроется окно **«Настройка тега»**.
5. В поле **«Название»** укажите назначение.
6. В поле **«Шаблон тега»** выберите подходящий шаблон.
7. Заполните параметры из документации подключаемого сервиса.
8. Добавьте существующий триггер либо создайте новый.
9. Нажмите **«Сохранить»**.

**Важно:** название кнопки создания тега в показанном вами интерфейсе пока не подтверждено скриншотом раздела «Теги». Здесь использовано официальное название из документации Яндекса.

**Если необходим новый триггер:**

1. В левом меню нажмите **«Триггеры»**.
2. В правом верхнем углу нажмите **«+ Триггер»**.
3. Укажите название.
4. Выберите тип триггера.
5. Настройте конкретное условие.
6. Нажмите **«Сохранить»**.
7. Вернитесь к тегу.
8. Привяжите созданный триггер.

**Ожидаемый результат:** новый тег сохранён и имеет конкретное условие запуска.

Создание тега или триггера ещё не означает, что он работает на опубликованном сайте.

### Н. Проверить тег перед публикацией

Выполняйте только при наличии нового или изменённого тега.

**Часть 1. Открыть предварительный просмотр**

1. Откройте Тег Менеджер.
2. В правом верхнем углу нажмите **«Предварительный просмотр»**.
3. Дождитесь подготовки черновой версии.
4. Скопируйте сформированную ссылку.
5. Откройте её в браузере.

Ссылка будет содержать параметр:

`_ytm_preview=...`

Значение параметра формируется Яндексом. Самостоятельно придумывать его не нужно.

**Часть 2. Выполнить контрольное действие**

1. Откройте сайт по сформированной ссылке.
2. Выполните действие, для которого создан тег.
3. Проверьте его срабатывание доступными средствами отладки.
4. Проверьте передаваемые параметры.
5. Если тег отправляет данные во внешний сервис, откройте этот сервис и проверьте получение тестового события.

В официальной документации Яндекса предусмотрена проверка через консоль браузера. Однако вывод подробных сообщений зависит от конкретного шаблона, его разрешений и настроек логирования.

**Часть 3. Исключить ложные срабатывания**

1. Откройте страницу, где тег не должен работать.
2. Выполните другое действие.
3. Проверьте отсутствие нежелательной отправки.
4. Убедитесь, что аналогичное событие не передаётся другой интеграцией.

**Ожидаемый результат:** тег срабатывает при нужном действии и не создаёт нежелательных событий.

**Если тег не работает:**

1. Проверьте, включён ли он.
2. Проверьте привязанный триггер.
3. Проверьте условия срабатывания.
4. Сравните параметры с документацией сервиса.
5. Исправьте найденную ошибку.
6. Повторите тест.

**Важно:** если контейнер пуст и новых тегов нет, проверять несуществующие события не требуется.

### О. Опубликовать изменения

Выполняйте только после успешной проверки конкретных изменений.

1. Откройте **«Тег Менеджер»**.
2. В правом верхнем углу нажмите **«Опубликовать»**.
3. В открывшемся окне найдите поле **«Название версии»**.
4. Укажите понятное название.
5. В поле **«Описание версии»** перечислите изменения.
6. Найдите блок **«Изменения при публикации»**.
7. Проверьте все добавленные, изменённые и удалённые объекты.
8. Убедитесь, что отсутствуют непредусмотренные действия.
9. Нажмите **«Опубликовать»**.

**Ожидаемый результат:** проверенная конфигурация становится новой опубликованной версией.

Изменения тегов, триггеров и переменных начинают действовать для обычных посетителей после публикации версии.

**Если изменений нет:** публикация не требуется.

Повторно публиковать страницы Tilda не нужно, если менялся только контейнер Тег Менеджера.

### П. Проверить опубликованную версию

Выполняйте после публикации новых или изменённых тегов.

1. Откройте Тег Менеджер.
2. В левом меню нажмите **«Обзор»**.
3. Найдите **«Опубликованная версия»**.
4. Проверьте номер и дату.
5. Откройте сведения о версии.
6. Убедитесь, что опубликованы нужные изменения.
7. Откройте сайт обычным способом, без режима предварительного просмотра.
8. Выполните проверяемое действие.
9. Проверьте его регистрацию в целевом сервисе.

**Ожидаемый результат:** опубликованный тег выполняет своё назначение, а передаваемые данные соответствуют исходным настройкам.

**Если результат отсутствует:**

1. Проверьте опубликованную версию.
2. Проверьте статус тега.
3. Проверьте триггер.
4. Проверьте передачу данных.
5. Проверьте ошибки браузера и блокировку скриптов.
6. После исправления повторно протестируйте и опубликуйте изменения.

Не удаляйте другие рабочие теги для устранения ошибки одного тега.

### Итоговый результат

**Готово**

Для базового подключения:

- Тег Менеджер доступен.
- Контейнер соответствует нужному счётчику.
- Существующие интеграции работают.
- Дублирующие настройки не создавались.
- Дополнительные действия не требуются.

Для нового тега дополнительно:

- Тег настроен.
- Триггер проверен.
- Срабатывание подтверждено.
- Версия опубликована.
- Данные поступают в нужный сервис.

**Требует проверки**

- Контейнер доступен, но существующие настройки ещё не изучены.
- Создан новый тег без контрольного тестирования.
- Изменения не опубликованы.
- Передача данных в целевой сервис не подтверждена.

**Проблема**

- Тег Менеджер недоступен.
- Нет необходимых прав.
- Обнаружено нежелательное дублирование.
- Тег срабатывает неправильно.
- Опубликована непроверенная конфигурация.
- Данные не поступают в нужный сервис.

**Не требуется**

Для сайта достаточно существующих интеграций, а дополнительных тегов, триггеров и бандлов пока не нужно.

В этом случае подключённый инструмент сохраняется, но дополнительные настройки не выполняются.

### Результат для аналитики

- Назначение: централизованное управление аналитическими и рекламными тегами.
- Приоритет: дополнительный инструмент.
- Платформа: Яндекс Метрика.
- Механизм: контейнер, теги, триггеры, переменные и бандлы.
- Подключение: через действующий счётчик Метрики.
- Основное ограничение: включение инструмента само по себе не создаёт новых событий и не улучшает коммерческие показатели.
- Использование: подключение новых аналитических систем, управление событиями и контроль изменений.

**После подтверждения доступности контейнера, отсутствия нежелательных дублей и сохранения существующей аналитики базовую настройку 4.2 можно считать выполненной.**

Дополнительные теги настраиваются при появлении конкретной задачи.
