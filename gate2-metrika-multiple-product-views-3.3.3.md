# 3.3.3. Просмотр нескольких товаров

## 1. Что сделать (инструкция)

Проверить, передаёт ли интернет-магазин в Яндекс Метрику данные о просмотре товаров, и определить возможность анализа нескольких просмотров в рамках одного визита.

Целевое действие: посетитель открыл карточки нескольких товаров, чтобы изучить или сравнить предложения.

Приоритет: поведенческая аналитика.

Различайте:

| Действие                    | Что подтверждает                                 |
| --------------------------- | ------------------------------------------------ |
| Просмотр каталога           | Посетитель увидел ассортимент                    |
| Просмотр карточки товара    | Посетитель открыл информацию о товаре            |
| Просмотр нескольких товаров | Посетитель несколько раз открыл карточки товаров |
| Добавление в корзину        | Посетитель перешёл к выбору товара для покупки   |
| Покупка                     | Зафиксирована коммерческая конверсия             |

Важное уточнение: в Метрике нет отдельного штатного типа цели «Просмотр нескольких товаров».

Однако электронная коммерция поддерживает событие `detail` (просмотр товара), а в отчётах предусмотрена группировка «Количество просмотров товаров в визите».&#x20;

Повторное открытие одного товара тоже может увеличивать число просмотров. Поэтому этот показатель нельзя автоматически считать количеством разных изученных товаров.

Рекомендация для GURU: использовать существующие данные электронной коммерции. Новые цели и JavaScript создавать только при подтверждённой аналитической необходимости.

## 2. Где нажать / Как проверить (инструкция)

### А. Проверить существующую электронную коммерцию

1. Откройте [Яндекс Метрику](https://metrika.yandex.ru/?utm_source=chatgpt.com).
2. Выберите счётчик нужного сайта.
3. В левом меню нажмите «Цели».
4. Найдите существующие цели электронной коммерции.
5. Проверьте, имеются ли «Ecommerce: покупка» и «Ecommerce: добавление в корзину».
6. Если они существуют, ничего не изменяйте.

Для k-apple.ru: счётчик `105213127`. Обе перечисленные цели ранее уже были созданы.

Важно: наличие этих целей не подтверждает, что Метрика также получает события просмотра карточек товаров.

### Б. Проверить передачу просмотров товаров с Tilda

Часть 1. Открыть сайт

1. Откройте Chrome в режиме инкогнито.
2. Перейдите по адресу:

`https://k-apple.ru/novogodnie-podarki-2027?_ym_debug=2`

3. Дождитесь загрузки страницы.
4. В нижней части экрана откройте отладчик Яндекс Метрики.
5. Перейдите на вкладку `Counters`.
6. Убедитесь, что отображается счётчик `105213127`.

Часть 2. Проверить первый товар

1. В отладчике откройте вкладку Ecommerce.
2. Нажмите меню с тремя точками.
3. Включите `Preserve log`.
4. На странице найдите товар «Шапка Коза».
5. Нажмите «Посмотреть подробнее» или откройте его карточку другим предусмотренным способом.
6. Вернитесь к вкладке `Ecommerce`.
7. Найдите новое событие просмотра товара.
8. Если появилось событие `detail`, проверьте название или ID товара.

Часть 3. Проверить второй товар

1. Вернитесь в каталог.
2. Найдите другой товар, например «Коза & Ёлка».
3. Откройте его карточку.
4. Проверьте вкладку `Ecommerce`.
5. Найдите второе событие `detail`.
6. Сравните идентификаторы или названия товаров.

Ожидаемый результат: два события просмотра с разными товарами.

Если события отсутствуют, это означает, что передача просмотров пока не подтверждена. Исправлять её дополнительным кодом без отдельной необходимости не требуется.

Источник: [Яндекс, проверка электронной коммерции](https://yandex.ru/support/metrica/ru/ecommerce/check?utm_source=chatgpt.com).

### В. Проверить статистику в Метрике

Выполняйте, если события `detail` действительно передаются.

1. Откройте Яндекс Метрику.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Отчёты».
4. Откройте группу «Электронная коммерция».
5. Выберите отчёт «Популярные товары».
6. Установите период, включающий проведённую проверку.
7. Найдите товары, которые открывали.
8. Проверьте наличие просмотров.

Если данных ещё нет, дождитесь обработки информации. По документации Яндекса первые данные электронной коммерции могут появиться в течение нескольких часов.&#x20;

### Г. Проанализировать количество просмотров товаров за визит

Если данные собираются, для анализа используйте группировку «Количество просмотров товаров в визите».

1. В Метрике откройте «Отчёты».
2. Найдите «Создать отчёт» → «Отчёт».
3. Откройте выбор группировок.
4. Найдите категорию «Электронная коммерция».
5. Выберите «Количество просмотров товаров в визите».
6. В выборе метрик добавьте «Визиты».
7. Нажмите «Создать».
8. Проверьте распределение визитов по количеству товарных просмотров.

При наличии данных можно сравнивать визиты с одним и несколькими просмотрами товаров.

Не устанавливайте порог произвольно. Сначала оцениваем распределение просмотров, затем решаем, нужен ли отдельный сегмент для маркетингового анализа.

Источник: [Яндекс, настройка отчётов и группировок](https://yandex.ru/support/metrica/ru/reports/report-general?utm_source=chatgpt.com).

### Д. Проверить ошибки

| Проблема                             | Что сделать                                                   |
| ------------------------------------ | ------------------------------------------------------------- |
| Счётчик отсутствует                  | Проверить подключение Метрики в Tilda                         |
| Нет событий `detail`                 | Проверить, передаются ли просмотры карточек                   |
| Есть `PageView`, но нет `detail`     | Не считать обычный просмотр страницы товарным событием        |
| События есть, отчёт пуст             | Проверить период и дождаться обработки данных                 |
| Один товар учитывается несколько раз | Проверить повторные открытия и возможное дублирование событий |
| Есть только покупки и корзина        | Не считать это подтверждением передачи товарных просмотров    |

Если требуется техническая диагностика, в Метрике откройте «Настройки» → «Счётчик» и проверьте подключение электронной коммерции и контейнер данных. В Tilda проверьте существующую интеграцию в «Настройки сайта» → «Аналитика».

Без подтверждённой причины не добавляйте второй счётчик, новые обработчики событий или пользовательский JavaScript.

## 3. Сверка (инструкция)

| Проверка             | Правильный результат                                      |
| -------------------- | --------------------------------------------------------- |
| Каталог              | Товары доступны для просмотра                             |
| Карточки товаров     | Открываются корректно                                     |
| Счётчик              | Соответствует проекту                                     |
| Ecommerce            | Проверена передача товарных событий                       |
| Событие `detail`     | Регистрируется при открытии карточки, если поддерживается |
| Идентификатор товара | Соответствует фактически открытому товару                 |
| Отчёт                | Отображает реальные просмотры                             |
| Дубли                | Отсутствуют нежелательные повторные события               |
| Новые цели           | Не создаются без необходимости                            |

### Итоговый результат

Готово

- Просмотры карточек передаются через электронную коммерцию.
- Данные появляются в отчётах.
- Количество просмотров товаров можно анализировать по визитам.
- Дополнительная разметка не требуется.

Требует проверки

- Событие `detail` появилось в отладчике, но статистика ещё не отобразилась.
- Обнаружены повторные события, происхождение которых не установлено.

Проблема

- Данные товарных просмотров передаются некорректно.
- События относятся к неправильным товарам.
- Есть техническое дублирование просмотров.

Не требуется

- Сайт не является интернет-магазином.
- Нет аналитической задачи по сравнению просмотров товаров.
- Бизнесу достаточно существующих отчётов и основных коммерческих конверсий.

### Результат для аналитики

- Назначение: оценка глубины знакомства с ассортиментом.
- Приоритет: поведенческая аналитика.
- Основной механизм: Ecommerce `detail`.
- Инструмент: отчёты и группировки Метрики.
- Ограничение: число просмотров не равно числу уникальных товаров.
- Использование: анализ поведения покупателей и сравнение трафика при наличии достоверных данных.

## Решение для «Коричного яблока»

Отдельную цель пока не создаём. Проверяем, передаёт ли Tilda просмотры товаров в уже работающую Метрику.

Следующее действие: откройте `https://k-apple.ru/novogodnie-podarki-2027?_ym_debug=2`, затем карточку «Шапка Коза» и вкладку `Ecommerce` в отладчике. Пришлите скриншот.

После проверки определим, можно ли использовать существующую аналитику без дополнительных настроек. К 3.3.4. Количество просмотров страниц переходим после завершения текущего пункта.
