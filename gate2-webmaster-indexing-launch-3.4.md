# 3.4. Первичный запуск индексирования всех страниц

## 1. Что сделать (инструкция)

Однократно передать Яндексу все опубликованные страницы сайта, предназначенные для поиска, и проверить запуск их обработки.

**Зачем:** обеспечить обнаружение страниц поисковым роботом и ускорить первоначальное индексирование.

**Целевое действие:** проверить автоматический Sitemap, включить обход через действующий счётчик Яндекс Метрики и отправить новые приоритетные страницы на переобход, если это необходимо.

**Ожидаемый результат:** все необходимые URL переданы Яндексу, файлы Sitemap обработаны, механизмы обхода работают.

Если настройки уже существуют и работают корректно, повторно создавать их не требуется.

## 2. Где нажать / Как проверить (инструкция)

### А. Передать все страницы через Sitemap

**Шаг 1. Проверить карту сайта**

1. Откройте сайт проекта.
2. Добавьте к домену `/robots.txt`.

   **Пример:** https://k-apple.ru/robots.txt

3. Нажмите `Command + F` на Mac или `Ctrl + F` на Windows.
4. Введите `Sitemap:`.
5. Найдите все строки, начинающиеся с `Sitemap:`.
6. Скопируйте указанные в них адреса XML-файлов.
7. Откройте каждый адрес в новой вкладке.
8. Убедитесь, что XML-файл открывается, содержит адреса страниц и не возвращает ошибку.

**Пример того, как могут выглядеть строки в robots.txt сайта на Tilda:**

```text
Sitemap: https://k-apple.ru/sitemap.xml
Sitemap: https://k-apple.ru/sitemap-store.xml
Sitemap: https://k-apple.ru/sitemap-feeds.xml
```

Это образец, а не подтверждённое содержимое текущего robots.txt. Используйте только реально указанные в нём файлы.

Назначение:

- `sitemap.xml`: обычные страницы сайта.
- `sitemap-store.xml`: опубликованные товары из каталога Tilda.
- `sitemap-feeds.xml`: опубликованные записи из Потоков Tilda.

**Если Sitemap отсутствует или сформирован неправильно:**

1. Откройте https://tilda.cc/login/.
2. Выберите проект.
3. Перейдите в «Настройки сайта» → «SEO» → «Редактирование sitemap.xml».
4. Выберите **«Автоматическая генерация»**.
5. Нажмите «Сохранить».
6. Повторно откройте опубликованный `sitemap.xml`.
7. Убедитесь, что необходимые URL присутствуют.

Если автоматическая генерация уже включена и карта корректна, ничего менять не нужно.

**Шаг 2. Проверить обработку Sitemap в Яндексе**

1. Откройте https://webmaster.yandex.ru/.
2. Выберите сайт проекта.
3. В левом меню откройте «Индексирование» → «Файлы Sitemap».
4. Найдите таблицу зарегистрированных файлов.
5. Сравните её строки с адресами `Sitemap:` из `robots.txt`.
6. Убедитесь, что каждый необходимый файл присутствует в таблице.
7. Проверьте колонку со статусом.
8. Проверьте дату последней загрузки файла роботом.

**Пример правильного результата для сайта «Коричное яблоко»:**

| Файл | Статус | Последняя загрузка |
|---|---|---|
| `https://k-apple.ru/sitemap.xml` | OK | Указана дата |
| `https://k-apple.ru/sitemap-store.xml` | OK | Указана дата |
| `https://k-apple.ru/sitemap-feeds.xml` | OK | Указана дата |

Это образец ожидаемого состояния. Реальные статусы и наличие каждого файла необходимо подтвердить в Вебмастере. Файлы, отсутствующие в конфигурации опубликованного сайта, добавлять не нужно.

**Что означает правильный результат:**

- URL совпадает с адресом Sitemap сайта.
- Статус **«OK»**.
- Указана дата последней загрузки.
- Вебмастер не сообщает об ошибках обработки файла.

Если карта отсутствует в списке:

1. Скопируйте её полный адрес из `robots.txt`.
2. Вставьте адрес в поле добавления Sitemap.
3. Нажмите **«Добавить»**.
4. Убедитесь, что файл появился в списке.

Если карта уже добавлена, повторно добавлять её не нужно.

**Если статус отличается от «OK»:**

| Статус | Что сделать |
|---|---|
| «Ошибка» | Нажать на статус, прочитать причину, исправить файл и запросить обновление |
| «Редирект» | Проверить, почему URL карты перенаправляет на другой адрес, и указать окончательный URL |
| «Не проиндексирован» | Проверить доступность XML-файла и HTTP-код через «Проверку ответа сервера» |
| Файл обрабатывается | Дождаться обработки, не создавать дублирующую запись |

Не путайте обработку Sitemap с индексированием HTML-страниц. Статус «OK» означает, что файл корректно обработан, но не гарантирует включения всех указанных страниц в поиск.

**Шаг 3. Ускорить обработку Sitemap**

Выполняйте только после существенного обновления карты.

1. Откройте «Индексирование» → «Файлы Sitemap».
2. Найдите обновлённый файл.
3. Нажмите значок приоритетного обхода рядом с ним.
4. Убедитесь, что запрос принят.

Яндекс предусматривает обработку такого запроса в течение трёх дней. Повторять действие без новых изменений не требуется.

### Б. Включить автоматический обход по Метрике

**Шаг 1. Проверить привязку счётчика**

1. Откройте Яндекс Вебмастер.
2. Выберите сайт проекта.
3. Перейдите в «Настройки» → «Привязка к Яндекс Метрике».
4. Найдите действующий счётчик.
5. Сравните его номер с номером счётчика проекта.
6. Проверьте статус **«Связан»**.

**Пример для «Коричного яблока»:**

- Сайт: `https://k-apple.ru`
- Счётчик Метрики: `105213127`
- Ожидаемый статус: «Связан».

Если счётчик уже связан, повторная привязка не требуется.

**Если счётчик отсутствует:**

1. Нажмите «Добавить счетчик».
2. Введите номер действующего счётчика проекта.
3. Отправьте запрос.
4. Если требуется подтверждение, откройте https://metrika.yandex.ru/.
5. Выберите нужный счётчик.
6. Откройте «Настройка» → вкладка «Счётчик».
7. Найдите запрос на привязку и нажмите «Подтвердить».
8. Вернитесь в Вебмастер.
9. Убедитесь, что появился статус «Связан».

Если сайт и счётчик принадлежат одному владельцу, запрос может подтвердиться автоматически.

**Шаг 2. Включить обход**

1. В Яндекс Вебмастере откройте «Индексирование» → «Обход по счётчикам».
2. Найдите привязанный счётчик.
3. Убедитесь, что номер совпадает с проектом.
4. Проверьте примеры обнаруживаемых страниц, если они отображаются.
5. Убедитесь, что среди них нет закрытых служебных URL.
6. Включите обход для соответствующего счётчика.
7. Проверьте, что функция отображается как активная.

**Ожидаемый результат:** Яндекс может использовать данные установленного счётчика для обнаружения страниц сайта.

Если обход уже включён, ничего менять не требуется.

### В. Отправить отсутствующие приоритетные страницы на переобход

Выполняйте только для новых или исправленных страниц, которые требуют повторной обработки.

1. Откройте Яндекс Вебмастер.
2. Перейдите в «Индексирование» → «Переобход страниц».
3. Выберите сайт.
4. Найдите список ранее отправленных адресов.
5. Проверьте, не отправлялся ли нужный URL ранее.
6. Возьмите окончательный адрес страницы из проекта.
7. Введите его в поле отправки.
8. Нажмите **«Отправить»**.
9. Убедитесь, что адрес появился в списке заявок.

**Пример правильного URL:**

`https://k-apple.ru/simvol-2027-koza`

**Ожидаемый результат:** адрес появился в списке со статусом «В очереди».

Если страница уже присутствует в поиске, её версия актуальна и переобход ранее выполнен, повторно отправлять адрес не нужно.

### Г. Сроки обработки

| Процесс | Контрольный срок |
|---|---|
| Первичная загрузка Sitemap | До 2 недель |
| Приоритетная загрузка Sitemap | До 3 дней |
| Обход URL по заявке | До 3 дней |
| Обновление данных после переобхода | До 2 недель |
| Включение страницы в поиск | Не гарантировано |
| Появление показов и позиций | Гарантированный срок отсутствует |

Сроки основаны на документации Яндекса. Для индексации и начала ранжирования фиксированного срока нет.

### Д. Проверить результат

**Проверка 1. Заявка на переобход**

1. Откройте «Индексирование» → «Переобход страниц».
2. Найдите отправленный URL.
3. Проверьте статус.

| Статус | Значение |
|---|---|
| «В очереди» | Робот ещё не посетил страницу по заявке |
| «Заявка обработана» | Робот посетил страницу |
| «Ошибка» | Не удалось выполнить обработку |

**Важно:** «Заявка обработана» не означает, что страница включена в поиск.

**Проверка 2. Присутствие в поиске**

1. Откройте https://yandex.ru/.
2. Введите `url:` и полный адрес без пробела.

   Например:

   `url:https://k-apple.ru/simvol-2027-koza`

3. Нажмите Enter.
4. Убедитесь, что найден правильный URL.

**Правильный результат:** страница отображается в результатах поиска Яндекса.

**Проверка 3. Начало ранжирования**

1. Откройте Яндекс Вебмастер.
2. Перейдите в «Эффективность» → «Статистика страниц».
3. Выберите проверяемую страницу.
4. Проверьте «Показы» и «Ср. позиция».
5. Запишите период отчёта.

**Правильный результат:** за выбранный период имеются реальные показы и измеряемая позиция.

Отсутствие показов не доказывает отсутствие индексации.

### Е. Если страница не появилась в поиске

1. Проверьте правильность и доступность URL.
2. Убедитесь, что страница опубликована.
3. Проверьте её наличие в соответствующем Sitemap.
4. Проверьте последнюю заявку на переобход.
5. Выполните техническую проверку согласно шагу 3.2.
6. Устраните подтверждённую ошибку, если она обнаружена.
7. При необходимости отправьте исправленную страницу на переобход.
8. Повторите проверку присутствия страницы в поиске после обработки.

Если технических ошибок нет, но Яндекс признал страницу малоценной или маловостребованной, требуется работа с содержанием и релевантностью. Она относится к Гейту 5.

## 3. Сверка (инструкция)

| Проверка | Правильный результат |
|---|---|
| Режим Sitemap Tilda | «Автоматическая генерация» |
| Список Sitemap | Совпадает с картами, указанными в robots.txt |
| Адреса файлов | Принадлежат правильному домену |
| Статус файлов | «OK» |
| Последняя загрузка | Дата присутствует |
| Привязка Метрики | «Связан», номер совпадает с проектом |
| Обход по счётчику | Активен |
| Переобход | Заявки отправлены только при необходимости |
| Индексация | Проверена по конкретным URL |
| Ранжирование | Проверено по фактическим показам и позициям |

### Готово

- Sitemap формируется автоматически и содержит необходимые опубликованные страницы.
- Все необходимые файлы зарегистрированы в Яндекс Вебмастере со статусом «OK».
- Действующий счётчик Метрики привязан.
- Обход по счётчику включён.
- Необходимые заявки на переобход приняты.
- Повторные настройки и заявки без необходимости отсутствуют.

### Требует проверки

- Sitemap ожидает обработки.
- Заявки находятся в очереди.
- Вебмастер временно недоступен.
- Отсутствуют необходимые данные для подтверждения результата.

### Проблема

- Sitemap отсутствует или сформирован неправильно.
- Нужные URL отсутствуют в карте.
- Вебмастер сообщает об ошибке обработки.
- Счётчик не привязан или обход не включён.
- Заявка на переобход завершилась ошибкой.

### Не требуется

Повторное добавление Sitemap или переобход страниц не требуется, если они уже корректно обработаны и новых изменений нет.

### Итоговый результат

**Назначение:** первоначальная массовая передача индексируемых страниц Яндексу.

**Основной механизм:** автоматический Sitemap.

**Дополнительный механизм:** обход по счётчику Яндекс Метрики.

**Условный механизм:** переобход новых и исправленных страниц.

**Критерий завершения:** необходимые URL переданы Яндексу, механизмы обхода настроены и их работа проверена.

Фактическая индексация подтверждается в шаге 3.1, первоначальное ранжирование в шаге 3.3.

Дальнейший мониторинг и SEO-оптимизация выполняются в Гейте 5.
