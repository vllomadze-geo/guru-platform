# 1. Подключение сайта

## 1.1. Основной адрес сайта

### 1. Что сделать (инструкция)

Проверить основной адрес сайта, настройки HTTPS и перенаправлений, затем убедиться, что именно этот адрес добавлен в Яндекс Вебмастер.

**Целевое действие:** определить единственный основной адрес сайта, который должен участвовать в поисковой выдаче Яндекса.

**Зачем необходимо:**

- Исключить конкуренцию альтернативных версий одного сайта.
- Обеспечить безопасный доступ посетителей и поисковых роботов.
- Сосредоточить поисковую статистику на правильном адресе.
- Исключить ошибки перенаправлений между HTTP, HTTPS и WWW.
- Подготовить сайт к последующей проверке индексирования страниц.

**Приоритет:** фундаментальная настройка.

Различайте:

| Понятие | Назначение |
|---|---|
| Основной адрес | Предпочтительная версия сайта |
| Главное зеркало | Адрес, выбранный Яндексом для участия в поиске |
| HTTPS | Защищённое соединение |
| SSL-сертификат | Подтверждение защищённого соединения |
| DNS | Направление домена на соответствующий сервер |
| Редирект 301 | Постоянное перенаправление на другой URL |
| Canonical | Указание предпочтительного URL для поисковых систем |

**Ожидаемый результат:** сайт доступен по основному HTTPS-адресу, альтернативные версии корректно перенаправляют посетителей, а в Яндекс Вебмастере присутствует правильный адрес без ненужного дублирования.

Если сайт уже добавлен и настроен правильно, повторно создавать или изменять настройки не требуется.

### 2. Где нажать / Как проверить (инструкция)

#### А. Определить основной адрес сайта

**Часть 1. Проверить действующий домен**

1. Откройте опубликованный сайт.
2. Нажмите на адресную строку браузера.
3. Посмотрите полный адрес.
4. Убедитесь, что используется протокол `https://`.
5. Скопируйте URL.

Пример:

`https://k-apple.ru/`

Для другого проекта используйте его фактический домен.

**Часть 2. Проверить альтернативные адреса**

Последовательно откройте в браузере:

1. `http://k-apple.ru/`
2. `https://k-apple.ru/`
3. `http://www.k-apple.ru/`
4. `https://www.k-apple.ru/`

Каждый адрес вводите отдельно и нажимайте Enter.

После открытия смотрите, какой адрес отображается в браузере.

**Ожидаемый результат:**

Все четыре варианта приводят к одному основному адресу:

`https://k-apple.ru/`

При этом браузер не должен показывать предупреждения безопасности.

**Важно:** изменение адреса в браузере подтверждает перенаправление, но не его HTTP-код. Для проверки кода используйте Яндекс Вебмастер.

Если появляется ошибка сертификата, не обходите предупреждение браузера и не отключайте защиту.

#### Б. Проверить подключение домена в Tilda

Выполняйте, если сайт создан на Tilda.

1. Откройте https://tilda.cc/login/.
2. Войдите в аккаунт.
3. Выберите нужный проект.
4. Нажмите **«Настройки сайта»**.
5. В левом меню откройте **«Домен»**.
6. Найдите поле **«Подключить свой домен»**.
7. Проверьте указанное значение.
8. Ниже найдите **«Результаты проверки»**.

Проверьте сообщения:

- Домен подключён корректно.
- DNS-записи настроены верно.
- Сайт открывается по заданному адресу.
- SSL-сертификат выпущен.
- Сайт открывается по защищённому протоколу HTTPS.

**Правильный результат:** основной домен работает без ошибок.

Если настройки правильные, ничего не меняйте.

Если Tilda сообщает об ошибке, откройте соответствующее пояснение и определите причину. Не заменяйте DNS-записи без необходимости.

#### В. Проверить DNS-записи

**Часть 1. Открыть настройки DNS**

1. В Tilda перейдите в **«Настройки сайта» → «Домен»**.
2. Найдите сообщение об управлении DNS.
3. Если DNS управляется через Tilda, нажмите ссылку **«Управление»**.
4. Откройте страницу **«Настройка DNS»**.
5. Найдите раздел **«DNS-записи»**.

**Часть 2. Проверить записи**

Проверьте:

1. A-запись основного домена.
2. Запись для поддомена `www`.
3. Статус DNS.
4. Используемые NS-серверы.

Для сайта «Коричное яблоко» ранее подтверждены:

| Параметр | Фактическое значение |
|---|---|
| Основной домен | `k-apple.ru` |
| A-запись | `176.57.67.97` |
| WWW | CNAME → `k-apple.ru` |
| NS1 | `ns1.tildadns.com` |
| NS2 | `ns2.tildadns.com` |
| Статус DNS | Активный |

Эти значения относятся к проверенному проекту. Для других сайтов используйте фактические данные их DNS.

**Ожидаемый результат:** записи соответствуют действующим требованиям Tilda и не содержат выявленных конфликтов.

**Если DNS работает:** ничего не изменяйте.

#### Г. Проверить HTTPS

1. В Tilda откройте **«Настройки сайта»**.
2. Нажмите **«SEO»**.
3. Найдите раздел **«Настройка HTTPS»**.
4. Откройте его.
5. Найдите переключатель защищённого протокола.
6. Проверьте его состояние.

**Правильный результат:**

Переключатель включён, а Tilda подтверждает работу защищённого соединения.

Затем:

1. Откройте основной адрес сайта.
2. Убедитесь, что браузер не показывает предупреждений безопасности.
3. Проверьте, что используется `https://`.

**Если HTTPS уже работает:** ничего менять не требуется.

**Если HTTPS выключен:**

1. Проверьте корректность подключения домена.
2. При отсутствии препятствий включите HTTPS по инструкции Tilda.
3. Дождитесь выпуска сертификата.
4. Повторно проверьте открытие сайта.

Не отключайте работающий HTTPS для устранения ошибок альтернативного адреса.

#### Д. Проверить перенаправления

**Часть 1. Открыть настройки**

1. В Tilda перейдите в **«Настройки сайта»**.
2. Откройте **«SEO»**.
3. Найдите **«Редиректы для WWW, HTTPS»**.
4. Откройте этот раздел.

**Часть 2. Проверить WWW**

В блоке **«Редирект WWW для домена»** выберите:

`Редирект с WWW на основной домен`

Для `k-apple.ru` именно этот вариант уже установлен.

Если настройка совпадает, ничего не изменяйте.

**Часть 3. Проверить HTTPS**

В блоке **«Редирект с HTTP на HTTPS для домена»** выберите:

`Редирект с HTTP на HTTPS`

Для `k-apple.ru` эта настройка также уже установлена.

**Часть 4. Сохранить**

Если настройки изменялись:

1. Проверьте выбранные значения.
2. Нажмите **«Сохранить»**.
3. Повторно откройте основной адрес сайта.
4. Проверьте перенаправления.

Если настройки не изменялись, повторное сохранение не требуется.

**Важно:** настройки перенаправлений не исправляют автоматически недействительный SSL-сертификат. HTTPS-соединение должно успешно устанавливаться до выполнения HTTP-редиректа.

#### Е. Проверить альтернативный WWW-адрес

Выполняйте, если сайт использует основной домен без `www`.

1. Откройте Chrome.
2. Введите адрес с `www`.
3. Нажмите Enter.
4. Убедитесь, что браузер безопасно перенаправляет на основной адрес.

**Ожидаемый результат:**

`https://www.k-apple.ru/`

перенаправляет на:

`https://k-apple.ru/`

без предупреждений безопасности.

**Если появляется ошибка SSL:**

1. Зафиксируйте точный код ошибки.
2. Проверьте DNS-запись для `www`.
3. Проверьте действующие настройки HTTPS.
4. Проверьте выбранный редирект WWW.
5. Если настройки корректны, обратитесь в поддержку хостинг-платформы для диагностики сертификата.
6. После устранения ошибки повторите проверку.

Для «Коричного яблока» зафиксирована ошибка:

`NET::ERR_CERT_AUTHORITY_INVALID`

при открытии:

`https://www.k-apple.ru/`

Основной домен работает. DNS и настройки редиректов проверены, но причина ошибки сертификата WWW пока не установлена.

**Не удаляйте CNAME, не заменяйте DNS-записи и не отключайте HTTPS без подтверждённой технической причины.**

#### Ж. Проверить основной адрес в Яндекс Вебмастере

**Часть 1. Открыть сервис**

1. Откройте https://webmaster.yandex.ru/.
2. Войдите через рабочий Яндекс ID.
3. В левой верхней части интерфейса найдите поле выбора сайта.
4. Нажмите на него.
5. Найдите основной адрес проекта.

Для «Коричного яблока»:

`https://k-apple.ru`

**Часть 2. Проверить существующий сайт**

1. Выберите найденный адрес.
2. Дождитесь открытия страницы **«Сводка»**.
3. Проверьте адрес в верхней части страницы.
4. Убедитесь, что отображаются данные именно нужного сайта.
5. Проверьте доступность разделов «Индексирование» и «Эффективность».

**Ожидаемый результат:** сайт уже присутствует в Вебмастере, повторное добавление не требуется.

**Часть 3. Добавить сайт, если его нет**

1. Нажмите значок **«+»** рядом с выбором сайта либо перейдите на страницу «Мои сайты».
2. Нажмите **«Добавить сайт»**.
3. Введите полный основной адрес.

Например:

`https://k-apple.ru/`

4. Нажмите **«Добавить»**.
5. Убедитесь, что адрес появился в списке.

**Важно:** альтернативные HTTP- и WWW-версии не нужно добавлять отдельно без конкретной необходимости.

Яндекс объединяет зеркала одного сайта и определяет главный адрес для участия в поиске.

Если права управления сайтом не подтверждены, их проверка выполняется в следующем шаге **1.2. Подтверждение прав**.

#### З. Проверить главное зеркало Яндекса

1. Откройте Яндекс Вебмастер.
2. Перейдите к выбору сайта или откройте **«Мои сайты»**.
3. Найдите основной адрес.
4. Проверьте, объединён ли он в группу с альтернативными адресами.
5. Если группа зеркал отображается, посмотрите, какой адрес находится первым.
6. Сравните его с основным адресом проекта.

**Правильный результат:** главным зеркалом является желаемый основной адрес.

Если Яндекс показывает другое главное зеркало, не начинайте перенос сайта автоматически.

Сначала проверьте перенаправления и выясните, почему Яндекс использует другой адрес.

**Важно:** наличие сайта в Вебмастере само по себе не доказывает, что Яндекс выбрал его главным зеркалом. Это отдельная проверка.

#### И. Проверить ответ сервера через Яндекс Вебмастер

**Часть 1. Открыть инструмент**

1. Откройте https://webmaster.yandex.ru/.
2. Выберите нужный сайт.
3. В левом меню раскройте **«Инструменты»**.
4. Нажмите **«Проверка ответа сервера»**.

**Часть 2. Проверить основной адрес**

1. Найдите поле для ввода URL.
2. Введите полный основной адрес сайта.

Например:

`https://k-apple.ru/`

3. В списке роботов выберите основного робота Яндекса.
4. Запустите проверку.
5. Дождитесь результата.
6. Найдите HTTP-код ответа.
7. Проверьте сведения об SSL-сертификате, если они отображаются.

**Ожидаемый результат:**

- HTTP-код `200 OK`.
- Нет ошибок SSL.
- Страница доступна поисковому роботу.

**Часть 3. Проверить альтернативные адреса**

При необходимости повторите проверку для:

- `http://k-apple.ru/`
- `http://www.k-apple.ru/`
- `https://www.k-apple.ru/`

Для альтернативных адресов ожидается перенаправление на основной адрес, конечная страница которого возвращает `200 OK`.

Если инструмент сообщает об ошибке сертификата или подключения, зафиксируйте её для исправления.

**Важно:** проверка ответа сервера подтверждает техническую доступность, но не гарантирует индексирование страницы.

### 3. Сверка (инструкция)

| Проверка | Правильный результат |
|---|---|
| Основной домен | Соответствует проекту |
| HTTPS | Работает |
| SSL основного домена | Действителен |
| DNS | Настроен корректно |
| WWW | Перенаправляет на основной домен |
| HTTP | Перенаправляет на HTTPS |
| Альтернативные адреса | Не содержат ошибок безопасности |
| Главное зеркало Яндекса | Совпадает с основным адресом |
| Яндекс Вебмастер | Сайт добавлен |
| Дублирование | Нет ненужных отдельных настроек |
| Ответ основного сервера | `200 OK` |
| Доступность для робота | Подтверждена |
| Существующие данные | Сохранены |

#### Итоговый результат

**Готово**

- Основной адрес определён.
- Сайт открывается по HTTPS.
- Сертификат действителен.
- Альтернативные адреса перенаправляют на основной.
- Главное зеркало соответствует нужному домену.
- Сайт присутствует в Яндекс Вебмастере.
- Основной адрес доступен поисковому роботу.
- Дублирующие настройки отсутствуют.

**Требует проверки**

- Основной адрес работает, но одна из альтернативных версий выдаёт ошибку.
- Главное зеркало в группе Яндекса ещё не подтверждено.
- Перенаправления настроены, но их фактическая работа не проверена.

**Проблема**

- Основной сайт недоступен.
- SSL-сертификат основного адреса недействителен.
- Неправильно настроены DNS.
- Редиректы ведут на ошибочный адрес.
- Вебмастер показывает неверный домен.
- Поисковый робот не может получить главную страницу.

**Не требуется**

Отдельное добавление альтернативных адресов, если правильный основной сайт уже подключён.

#### Результат для Яндекс Вебмастера

- Назначение: правильное подключение основного адреса.
- Приоритет: фундаментальная настройка.
- Основной механизм: домен, HTTPS, редиректы и главное зеркало.
- Критерий выполнения: правильный адрес подключён, доступен и не создаёт ненужных дублей.
- Результат: сайт подготовлен к подтверждению прав и проверке индексирования.

**После проверки основного адреса и отсутствия нерешённых ошибок переходите к 1.2. Подтверждение прав.**
