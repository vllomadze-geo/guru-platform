# 3.1.7. Полученная заявка из окна (Pop-up)

## 1. Что сделать (инструкция)

Настроить Яндекс Метрику для регистрации успешно отправленных заявок из всплывающих окон (Pop-up) сайта и убедиться, что каждое достижение цели соответствует фактически полученному обращению.

**Полученная заявка из Pop-up:** посетитель открыл всплывающее окно, заполнил форму, успешно отправил данные, а обращение поступило в систему приёма заявок.

### Какие события различать

| Событие | Что фиксирует | Назначение |
|---|---|---|
| Открытие Pop-up | Посетитель открыл окно | Промежуточная конверсия |
| Нажатие «Отправить» | Попытка отправки | Не является полученной заявкой |
| `/tilda/form.../submitted` | Успешную отправку формы Tilda | Основная конверсия |
| `/thankyou` | Открытие страницы благодарности | Дополнительный сигнал |

**Рекомендуемый механизм:** виртуальное событие отправки формы Tilda, отслеживаемое целью Яндекс Метрики типа «Посещение страниц».

Для полноценного подтверждения необходимо получить четыре результата:

1. Pop-up открывается правильно.
2. Tilda передаёт виртуальное событие `/submitted`.
3. Заявка действительно поступает в CRM, Telegram или другой подключённый приёмник.
4. Яндекс Метрика регистрирует достижение соответствующей цели.

Не создавайте новую цель, если нужная форма уже отслеживается существующей целью с тем же условием.

## 2. Где нажать / Как проверить (инструкция)

### А. Найти Pop-up и проверить его открытие

**Часть 1. Найти блок Pop-up**

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь в аккаунте сайта.
3. Выберите нужный проект.
4. Откройте страницу, на которой находится всплывающее окно.
5. Если Pop-up размещён в общем подвале сайта, откройте страницу, назначенную подвалом.
6. Найдите блок Pop-up.
7. Наведите на него указатель мыши.
8. Нажмите «Контент».
9. Найдите поле «Ссылка на Pop-up».
10. Скопируйте указанное значение.

Например:

`#popup:myform`

Это специальная ссылка, которая открывает окно. Она не является событием отправки заявки.

**Часть 2. Проверить кнопку открытия**

1. Откройте страницу, на которой расположена кнопка вызова Pop-up.
2. В редакторе найдите эту кнопку.
3. Нажмите «Контент» блока с кнопкой.
4. Найдите поле «Ссылка для кнопки».
5. Сравните его значение со ссылкой Pop-up.

Пример:

| Место | Значение |
|---|---|
| Pop-up → «Контент» → «Ссылка на Pop-up» | `#popup:myform` |
| Кнопка → «Контент» → «Ссылка для кнопки» | `#popup:myform` |

**Правильный результат:** значения полностью совпадают.

Если ссылки различаются:

1. Скопируйте правильную ссылку из Pop-up.
2. Вставьте её в поле ссылки кнопки.
3. Нажмите «Сохранить».
4. Опубликуйте изменённую страницу.
5. Откройте опубликованный сайт.
6. Нажмите кнопку.
7. Убедитесь, что открылось нужное окно.

Если Pop-up открывается автоматически, без кнопки, проверка ссылки кнопки не требуется.

### Б. Найти виртуальное событие открытия Pop-up

1. Вернитесь в редактор блока Pop-up.
2. Нажмите «Настройки».
3. Найдите параметр «Отправлять данные об открытии попапа в систему аналитики».
4. Посмотрите положение галочки.
5. Если она включена, ниже должен отображаться виртуальный адрес вида:

`/tilda/popup/recXXXXXXXXXX/opened`

6. Скопируйте адрес, если требуется анализ открытий окна.

**Пример:**

`/tilda/popup/rec2329699421/opened`

Это событие подтверждает исключительно открытие окна.

**Важно:** включать передачу открытий для работы цели «Полученная заявка» необязательно.

Не используйте `/opened` вместо `/submitted`.

### В. Найти виртуальное событие отправки формы

1. Откройте настройки блока Pop-up.
2. Прокрутите панель настроек до самого низа.
3. Найдите сообщение:

   «Отправка формы в системе аналитики будет отображаться как просмотр страницы».

4. Под сообщением найдите адрес виртуальной страницы.
5. Скопируйте его полностью.

Адрес имеет вид:

`/tilda/formXXXXXXXXXX/submitted`

В текущем проверенном проекте:

`/tilda/form2329699421/submitted/`

**Как определить правильный адрес:**

- `tilda/form` означает виртуальное событие формы.
- Число после `form` идентифицирует форму.
- `submitted` обозначает событие отправки.

Не подставляйте номер другой формы.

Виртуальную страницу не нужно создавать, публиковать или открывать вручную. Tilda передаёт её просмотр при отправке формы.

**Ожидаемый результат:** установлен точный виртуальный адрес отправки заявки из нужного Pop-up.

### Г. Проверить приём заявок

1. Вернитесь в редактор Pop-up.
2. Нажмите «Контент».
3. Найдите раздел «Приём данных из формы».
4. Посмотрите подключённые сервисы.
5. Убедитесь, что галочкой отмечен действующий получатель заявок.

Например:

- Tilda CRM.
- Telegram.
- Email.
- Другая CRM.

Если приёмщик уже подключён и работает, ничего менять не требуется.

**Если получатель отсутствует:**

1. Откройте панель управления проектом.
2. Нажмите «Настройки сайта».
3. Перейдите в раздел «Формы».
4. Выберите нужный сервис.
5. Выполните подключение по официальной инструкции сервиса.
6. Вернитесь к блоку Pop-up.
7. Откройте «Контент».
8. Отметьте подключённый приёмщик.
9. Нажмите «Сохранить и закрыть».
10. Опубликуйте страницу.

**Ожидаемый результат:** форма направляет обращения в выбранный сервис.

### Д. Проверить подключение Яндекс Метрики

1. Откройте Tilda → «Настройки сайта».
2. В меню слева нажмите «Аналитика».
3. Найдите раздел «Яндекс Метрика».
4. Посмотрите ID подключённого счётчика.
5. Откройте https://metrika.yandex.ru/.
6. Выберите счётчик нужного сайта.
7. Сравните оба номера.

**Если совпадают:** ничего менять не требуется.

**Если отличаются:**

1. Скопируйте правильный ID из Метрики.
2. Вставьте его в настройки Tilda.
3. Сохраните изменения.
4. Вернитесь к списку страниц.
5. Нажмите «Опубликовать все страницы».

Не создавайте отдельный счётчик для Pop-up.

### Е. Найти или создать цель Яндекс Метрики

**Часть 1. Проверить существующие цели**

1. Откройте https://metrika.yandex.ru/.
2. Выберите счётчик сайта.
3. В левом меню нажмите «Цели».
4. Найдите цель, связанную с заявкой из Pop-up.
5. Если она существует, нажмите значок карандаша справа от названия.
6. В открывшейся панели проверьте тип цели.
7. Найдите поле URL.
8. Посмотрите установленное условие.

**Правильные настройки:**

| Поле | Значение |
|---|---|
| Тип | Посещение страниц |
| Условие URL | Содержит |
| Значение | `/tilda/formXXXXXXXXXX/submitted` |

Адрес должен соответствовать фактической форме Pop-up.

Если настройки совпадают, повторно создавать цель не нужно.

**Часть 2. Создать цель при отсутствии**

1. В Метрике нажмите «Цели».
2. Нажмите «Добавить цель».
3. На экране «Новая цель» найдите категорию «Вовлечённость».
4. Выберите «Посещение страниц».
5. В поле названия укажите:

   `Полученная заявка · Pop-up`

6. Найдите настройку условия URL.
7. Выберите «Содержит».
8. Вставьте виртуальный адрес формы из Tilda.
9. Сравните адрес посимвольно.
10. Нажмите «Добавить цель».
11. Вернитесь к списку целей.
12. Найдите созданную цель.
13. Зафиксируйте её числовой ID.

**Пример подтверждённой настройки:**

| Параметр | Значение |
|---|---|
| Название | Полученная заявка · Pop-up |
| ID | 679326353 |
| Тип | Посещение страниц |
| Условие | URL содержит |
| Значение | `/tilda/form2329699421/submitted` |

Если Tilda передаёт адрес с завершающим `/`, условие «Содержит» продолжит работать при совпадении указанной части пути.

**Важно:** цель должна существовать до контрольной отправки. Созданная после события цель не засчитает уже прошедшую отправку задним числом.

### Ж. Подготовить контрольное тестирование

**Часть 1. Проверить публикацию**

1. Откройте редактор Tilda.
2. Если настройки Pop-up, формы или счётчика изменялись, сохраните их.
3. Опубликуйте изменённую страницу.
4. Если изменялась общая интеграция Метрики, опубликуйте все страницы.
5. Откройте опубликованный сайт.
6. Убедитесь, что Pop-up открывается.

**Часть 2. Зафиксировать исходное состояние цели**

1. Откройте Метрику.
2. В левом меню нажмите «Конверсии».
3. Выберите проверяемую цель.
4. Установите период «Сегодня».
5. Запишите количество достижений до теста.
6. Зафиксируйте время начала проверки.

Это позволит сравнить результат до и после отправки.

**Часть 3. Открыть отладчик**

1. Откройте приватное окно Chrome:
   - Mac: `Command + Shift + N`.
   - Windows: `Ctrl + Shift + N`.
2. Не авторизуйтесь в Яндекс Метрике в приватном окне.
3. Откройте опубликованную страницу, где находится Pop-up.
4. Добавьте к адресу параметр `_ym_debug=2`.

Пример:

`https://example.ru/?_ym_debug=2`

5. Дождитесь загрузки.
6. В нижней части сайта нажмите значок отладчика Метрики.
7. Откройте вкладку `Counters`.
8. Убедитесь, что отображается ID нужного счётчика.
9. Перейдите во вкладку `Console`.

**Часть 4. Обязательно включить Preserve log до отправки**

Это важнейшая настройка при перенаправлении на страницу благодарности.

1. В панели отладки найдите поле `Search`.
2. Справа от него нажмите значок `⋮`.
3. Найдите пункт `Preserve log`.
4. Включите его.
5. Убедитесь, что опция отмечена.

**Зачем:** после отправки формы посетитель может перейти на `/thankyou`. Без сохранения журнала события открытия Pop-up и отправки формы могут исчезнуть из панели.

Если в панели Метрики не удаётся включить эту опцию:

1. Откройте инструменты разработчика Chrome:
   - Mac: `Option + Command + J`.
   - Windows: `Ctrl + Shift + J`.
2. Перейдите в `Console`.
3. Откройте настройки консоли.
4. Включите `Preserve log`.
5. Оставьте консоль открытой во время теста.

Если используется встроенная консоль Chrome, для сообщений Метрики при необходимости можно открыть страницу с параметром `_ym_debug=1`.

**Ожидаемый результат:** журнал готов сохранить события при перенаправлении.

### З. Проверить открытие Pop-up без отправки

1. На опубликованном сайте нажмите кнопку открытия Pop-up.
2. Убедитесь, что окно открылось.
3. В отладчике перейдите во вкладку `Console`.
4. Если включена аналитика открытий, найдите `PageView` вида:

   `/tilda/popup/recXXXXXXXXXX/opened`

5. Не заполняйте форму.
6. Закройте Pop-up крестиком.
7. Вернитесь в `Console`.
8. Убедитесь, что событие `/tilda/form.../submitted` не появилось.

**Правильный результат:** открытие и закрытие окна не регистрируется как полученная заявка.

Если `/submitted` появляется без отправки, необходима диагностика формы. Такую цель нельзя считать достоверной.

### И. Выполнить одну тестовую отправку

1. Повторно откройте Pop-up.
2. Заполните обязательные поля тестовыми данными.
3. Используйте собственный действующий контакт.
4. Запомните точное время отправки.
5. Нажмите кнопку «Отправить заявку» один раз.
6. Дождитесь сообщения об успехе либо перенаправления.

**Ожидаемый результат:** форма успешно завершила отправку.

Если появилась ошибка обязательного поля, исправьте данные. Такая попытка не считается полученной заявкой.

Если нет сообщения об успехе, сначала выясните результат отправки. Не нажимайте кнопку повторно без необходимости.

### К. Сразу проверить передачу события

1. После отправки откройте сохранённый журнал отладчика.
2. Выберите вкладку `Console`.
3. Найдите запись `PageView` исходной страницы.
4. Если включено отслеживание открытия Pop-up, найдите соответствующий виртуальный просмотр.
5. Затем найдите `PageView` формы с адресом:

   `/tilda/formXXXXXXXXXX/submitted`

6. Убедитесь, что номер формы совпадает с условием цели.
7. Проверьте номер счётчика.
8. Если было перенаправление, найдите последующий `PageView` страницы благодарности.

**Ожидаемая последовательность:**

| № | Событие | Значение |
|---|---|---|
| 1 | `PageView` исходной страницы | Посетитель открыл сайт |
| 2 | `/tilda/popup/rec.../opened` | Открыл Pop-up |
| 3 | `/tilda/form.../submitted` | Отправил форму |
| 4 | `PageView /thankyou` | Открыл страницу благодарности |

**Главное событие для данной цели: третье.**

Вкладка `Events` может не отображать отдельного достижения для цели типа «Посещение страниц». В этом случае ориентируйтесь на `PageView` виртуального адреса во вкладке `Console` и последующее достижение в отчёте «Конверсии».

**Если `/submitted` отсутствует:**

1. Проверьте, что форма завершила отправку.
2. Проверьте правильный ID счётчика.
3. Откройте настройки формы в Tilda.
4. Повторно скопируйте виртуальный адрес.
5. Сравните его с событием и условием цели.
6. Убедитесь, что последние изменения опубликованы.
7. Проверьте, был ли включён `Preserve log`.
8. Проверьте блокировщики рекламы.

Не меняйте условия цели на адрес открытия Pop-up.

### Л. Подтвердить получение заявки

**Часть 1. Проверить Tilda CRM**

1. Откройте панель управления проектом Tilda.
2. В верхнем меню нажмите «Заявки».
3. Найдите обращение по времени отправки.
4. Откройте запись.
5. Сравните тестовые сведения с отправленной формой.
6. Убедитесь, что указаны нужные данные клиента.

**Часть 2. Проверить подключённые получатели**

Если форма отправляет обращения в Telegram:

1. Откройте чат, в который поступают уведомления.
2. Найдите сообщение за время тестовой отправки.
3. Откройте его.
4. Найдите данные заявки.
5. Найдите дополнительные технические сведения.

Например:

- `Block ID`: идентификатор формы.
- `Form Name`: название формы.
- `Transaction ID`: идентификатор отправки, если передаётся.
- URL сайта.

**Сверка:** идентификатор блока из Telegram должен совпадать с блоком проверяемого Pop-up.

В проверенном проекте:

- `Block ID`: `rec2329699421`.
- `Form Name`: `individual_order_popup`.

Эти значения показывают, что заявка поступила именно из нужного Pop-up.

**Если заявки нет:**

1. Откройте Tilda → «Заявки».
2. Нажмите «Журнал ошибок».
3. Найдите записи за время теста.
4. Откройте обнаруженную ошибку.
5. Определите, какой сервис не получил данные.
6. Откройте настройки Pop-up → «Контент».
7. Проверьте галочки подключённых приёмщиков.
8. При необходимости исправьте подключение.
9. Сохраните и опубликуйте изменения.

Не считайте виртуальный `PageView` самостоятельным подтверждением доставки заявки.

### М. Проверить регистрацию цели в Яндекс Метрике

**Через 10-15 минут после успешной отправки:**

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Конверсии».
4. Установите период, включающий время теста.
5. Убедитесь, что не выбран ограничивающий сегмент.
6. Найдите цель «Полученная заявка · Pop-up».
7. Посмотрите показатель «Достижения цели».
8. Сравните его с количеством достижений до теста.

**Ожидаемый результат:** достижение цели зарегистрировано.

Яндекс указывает, что статистика обычно появляется в течение 10-15 минут, но обработка может занимать больше времени.

**Практический пример:**

В проведённой проверке:

- В 19:17 заявка поступила в Telegram.
- К 19:38 достижение отобразилось в Метрике.
- Наблюдаемое ожидание составило около 21 минуты.
- В отчёте было 1 достижение и 1 целевой визит.

Это нормальный результат. Время появления записи в отчёте не следует автоматически считать временем самой отправки.

**Если через 15 минут данных нет:**

1. Подождите ещё 15 минут.
2. Обновите отчёт.
3. Проверьте ID счётчика.
4. Проверьте период.
5. Убедитесь, что цель была создана до теста.
6. Проверьте отсутствие ограничивающего сегмента.
7. Откройте «Настройки» → «Фильтры».
8. Убедитесь, что тестовый визит не исключён.

**Если спустя 30-60 минут данных нет:**

1. Откройте «Отчёты».
2. Выберите «Содержание» → «Популярное».
3. Установите период с тестовым посещением.
4. Найдите каталог `/tilda/`.
5. Раскройте его.
6. Найдите каталог `formXXXXXXXXXX` нужной формы.
7. Раскройте его.
8. Найдите виртуальную страницу `submitted`.
9. Проверьте количество просмотров.

**Если виртуальная страница есть, но цель не достигнута:**

1. Откройте «Цели».
2. Найдите нужную цель Pop-up.
3. Нажмите значок редактирования.
4. Проверьте условие «Содержит».
5. Сравните адрес с фактически зарегистрированным виртуальным просмотром.
6. Если адрес отличается, исправьте и сохраните.
7. Для проверки исправления проведите новый допустимый тест.

**Если виртуальной страницы нет:** проверяйте передачу события, фильтры и публикацию сайта.

Интервал 30-60 минут является практическим ориентиром повторной диагностики, а не официально гарантированным сроком Яндекса.

Не отправляйте повторные заявки только потому, что отчёт пока не обновился.

### Н. Проверить отсутствие ложных и повторных конверсий

**Часть 1. Исключить регистрацию открытия окна как заявки**

1. Откройте сайт с `_ym_debug=2`.
2. Откройте Pop-up.
3. Не заполняйте форму.
4. Закройте окно.
5. Убедитесь, что не появился виртуальный `PageView` `/submitted`.

**Часть 2. Исключить неуспешную отправку**

1. Повторно откройте Pop-up.
2. Оставьте одно обязательное поле пустым.
3. Нажмите кнопку отправки.
4. Убедитесь, что появилось сообщение об ошибке.
5. Проверьте отсутствие нового события `/submitted`.

**Часть 3. Проверить повторные достижения**

1. Откройте Метрику → «Конверсии».
2. Найдите цель Pop-up.
3. Посмотрите количество достижений за период теста.
4. Откройте Tilda → «Заявки».
5. Найдите обращения из того же Pop-up.
6. Сопоставьте фактические успешные отправки с достижениями.

Если одна заявка породила несколько достижений, проверьте повторную отправку виртуального события или другие причины дублирования.

### О. Исключить двойной учёт с другими целями

Если на сайте существуют:

- Общая цель «Полученная заявка».
- Отдельная цель «Полученная заявка · Pop-up».
- Цель на страницу `/thankyou`.

Проверьте, какие фактические события они регистрируют.

**Важно:**

1. Один Pop-up может иметь собственную уникальную цель.
2. Страница `/thankyou` может открываться после отправки разных форм.
3. Одна заявка может одновременно приводить к достижению цели Pop-up и цели страницы благодарности.
4. Эти достижения нельзя складывать как две разные полученные заявки.

Для Яндекс Директа необходимо выбрать правильную бизнес-конверсию и исключить двойную оценку одного результата.

### П. Подготовить цель для Яндекс Директа

После успешного завершения проверки:

1. Откройте Метрику → «Цели».
2. Найдите «Полученная заявка · Pop-up».
3. Скопируйте её числовой ID.
4. Убедитесь, что достижения отображаются в отчёте.
5. Убедитесь, что обращения действительно поступают в систему приёма.
6. Проверьте отсутствие необъяснимых повторных достижений.
7. Определите, будет ли эта цель использоваться самостоятельно или вместе с другими целями получения заявок.

Создавать рекламную кампанию на этом этапе не требуется.

## 3. Сверка (инструкция)

### А. Технические критерии

| Проверка | Правильный результат |
|---|---|
| Ссылка Pop-up | Совпадает со ссылкой кнопки или триггера |
| Открытие окна | Работает |
| ID формы | Известен и подтверждён |
| Цель Метрики | Существует без дублирования |
| Условие цели | Соответствует `/submitted` |
| Отладчик | Использует правильный счётчик |
| `Preserve log` | Включён до теста с перенаправлением |
| Отправка формы | Передан виртуальный `PageView` |
| Tilda CRM / Telegram | Заявка получена |
| «Конверсии» | Достижение зарегистрировано |
| Повторный учёт | Отсутствуют необъяснимые дубли |

### Б. Критерии успешного результата

**Готово**

1. Pop-up открывается.
2. Простое открытие окна не регистрируется как заявка.
3. Успешная отправка передаёт виртуальное событие формы.
4. Заявка поступает в систему приёма.
5. Метрика регистрирует достижение нужной цели.
6. Количество достижений соответствует проверенным отправкам.
7. Нет подтверждённой ошибки двойного учёта.

**Требует проверки**

- Событие отправлено, но статистика ещё обрабатывается.
- Заявка доставлена, но достижение цели пока не появилось.
- Есть расхождение между числом заявок и достижений, причина которого не установлена.

**Проблема**

- Pop-up открывается неправильно.
- Виртуальное событие `/submitted` отсутствует.
- Цель использует адрес `/opened` вместо `/submitted`.
- Заявка не поступает получателю.
- Неуспешная отправка засчитывается как конверсия.
- Подтверждён двойной учёт одного обращения.

**Не требуется**

Проект не использует Pop-up-формы для получения обращений.

### В. Подтверждённый пример

Для проекта «Коричное яблоко» установлены следующие значения:

| Параметр | Значение |
|---|---|
| ID счётчика | `105213127` |
| Ссылка Pop-up | `#popup:myform` |
| ID формы | `rec2329699421` |
| Открытие окна | `/tilda/popup/rec2329699421/opened` |
| Отправка формы | `/tilda/form2329699421/submitted/` |
| Название цели | Полученная заявка · Pop-up |
| ID цели | `679326353` |
| Условие | URL содержит `/tilda/form2329699421/submitted` |
| Приём заявки | Tilda CRM / Telegram |
| Подтверждённая отправка | 19:17 |
| Появление в отчёте | К 19:38 |
| Результат Метрики | 1 достижение, 1 целевой визит |

**Вывод:** в проверенном проекте событие отправки Pop-up, получение заявки и достижение цели подтверждены.

### Г. Результат для GURU

- Назначение: полученная заявка из Pop-up.
- Приоритет: основная конверсия, если Pop-up используется для получения обращений.
- Механизм: виртуальная отправка формы Tilda.
- Тип цели Метрики: «Посещение страниц».
- Условие: индивидуальный адрес `/tilda/form.../submitted`.
- Отдельное событие открытия: `/tilda/popup/rec.../opened`.
- Использование: анализ заявок из Pop-up и последующая оптимизация Яндекс Директа.

**После подтверждения всех обязательных критериев цель считается полностью настроенной.**
