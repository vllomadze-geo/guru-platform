# 2.1. Проверка доступности страниц

## 1. Что сделать (инструкция)

Проверить доступность всех необходимых страниц сайта для поискового робота Яндекса, выявить технические ограничения и подтвердить, что страницы, предназначенные для поисковой выдачи, могут быть загружены и проиндексированы.

**Целевое действие:** убедиться, что важные страницы сайта возвращают корректные HTTP-ответы и не имеют нежелательных ограничений индексирования.

Различайте:

| Состояние | Что подтверждает |
|---|---|
| Страница открывается в браузере | Доступна посетителю |
| HTTP 200 OK | Сервер успешно вернул документ |
| Разрешена в robots.txt | Роботу разрешён обход адреса |
| Отсутствует noindex | Нет соответствующего запрета индексирования |
| Доступна для индексирования | Не выявлены проверяемые технические препятствия |
| Страница в поиске | Яндекс включил страницу в поисковую базу |

**Приоритет:** фундаментальная настройка.

**Практическая ценность:**

- Выявлять страницы, недоступные поисковому роботу.
- Предотвращать случайное исключение коммерчески значимых страниц из поиска.
- Обнаруживать ошибки сервера, SSL и перенаправлений.
- Проверять ограничения `robots.txt` и `noindex`.
- Обеспечивать технические условия для максимально полного индексирования полезных страниц сайта.

Используем штатные инструменты Яндекс Вебмастера:

1. «Статистика обхода».
2. «Анализ robots.txt».
3. «Проверка ответа сервера».
4. «Анализ индексации страницы».

**Основной принцип GURU:** массовая проверка по умолчанию, индивидуальная диагностика только при необходимости.

Все URL для проверки GURU должен предоставлять автоматически из существующих данных проекта.

**Условия применения:**

- Сайт уже добавлен в Вебмастер: используем существующее подключение.
- Все необходимые страницы доступны: ничего не изменяем.
- Обнаружены технические ошибки: исправляем подтверждённую причину.
- Служебные страницы намеренно ограничены: сохраняем ограничения.
- Страница доступна, но отсутствует в поиске: исследуем причину на следующем этапе контроля индексации.

**Важно:** успешный ответ сервера и разрешение индексирования не гарантируют появления страницы в поисковой выдаче.

## 2. Где нажать / Как проверить (инструкция)

### А. Получить список страниц для проверки из GURU

**Часть 1. Определить источники URL**

GURU должен автоматически использовать адреса, уже сохранённые в проекте.

Основные источники:

1. Основной адрес сайта из «Платформы».
2. Системные страницы сайта.
3. Коммерческие разделы и категории.
4. Посадочные страницы продуктов и услуг.
5. Опубликованные карточки товаров.
6. Статьи и публикации, если их URL сохранены.
7. Дополнительные страницы, созданные пользователем в проекте.

**Не создавать новое хранилище URL.**

Использовать существующие данные «Платформы» и связанных разделов GURU.

Для каждого адреса показывать:

- Название страницы.
- Тип страницы.
- Полный URL.
- Активную ссылку для открытия.
- Назначение проверки.

**Часть 2. Определить, какие страницы должны индексироваться**

| Тип страницы | Решение |
|---|---|
| Главная | Проверять обязательно |
| Категория товаров | Проверять, если предназначена для поиска |
| Карточка товара | Проверять, если имеет собственный поисковый URL |
| Страница услуги | Проверять |
| Коммерческая посадочная | Проверять при самостоятельной поисковой ценности |
| Статья | Проверять, если опубликована для поискового трафика |
| Страница контактов | Проверять при необходимости присутствия в поиске |
| Корзина | Обычно не требует индексирования |
| Страница успешной оплаты | Обычно не требует индексирования |
| Страница успешной отправки формы | Обычно не требует индексирования |
| Личный кабинет | Не должен раскрывать закрытые данные |
| Дублирующиеся и технические URL | Проверять обоснованность индексирования |

**Важно:** не требуйте индексирования всех технических адресов. Цель заключается в максимальной доступности полезных страниц, предназначенных для поиска.

**Часть 3. Сформировать список в GURU**

Внутри существующей инструкции автоматически выводить блок:

**«Адреса страниц проекта для проверки»**

Пример для «Коричного яблока»:

| Страница | Адрес |
|---|---|
| Главная | https://k-apple.ru/ |
| Новогодние подарки 2027 | https://k-apple.ru/novogodnie-podarki-2027 |
| Индивидуальный заказ | https://k-apple.ru/individualnyj_zakaz |
| Остальные категории | Фактические URL из GURU |
| Карточки товаров | Фактические URL из GURU |
| Статьи | Фактические URL из GURU |

**Требования к автоматическому списку:**

1. Показывать все известные проекту целевые URL, а не только примеры.
2. Не дублировать одинаковые адреса.
3. Сохранять фактический протокол, домен и путь.
4. Использовать опубликованные адреса, а не ссылки на редактор Tilda.
5. Не формировать адреса путём угадывания названия страницы.
6. Если URL отсутствует, показывать «URL не заполнен».
7. Для отсутствующего значения давать переход к существующему месту ввода.
8. При изменении URL в проекте обновлять список автоматически.
9. Не создавать новые поля и не изменять существующую структуру GURU.

Если адрес ведёт на раздел страницы через `#`, не считать его самостоятельной индексируемой страницей без отдельного подтверждения.

**Особенность Tilda:** для товаров из встроенного Каталога могут генерироваться собственные товарные URL. Их необходимо получать из фактического каталога или сохранённых данных, а не придумывать по названию товара.

**Ожидаемый результат:** пользователь видит готовый список адресов и понимает, какие страницы необходимо проверить.

### Б. Проверить главную страницу через Яндекс Вебмастер

**Часть 1. Открыть инструмент**

1. Откройте https://webmaster.yandex.ru/.
2. Войдите через рабочий Яндекс ID.
3. В левой верхней части выберите сайт проекта.
4. В левом меню раскройте **«Инструменты»**.
5. Нажмите **«Проверка ответа сервера»**.

**Часть 2. Заполнить параметры**

1. Найдите поле **«Опрашиваемый URL»**.
2. Скопируйте из GURU адрес главной страницы.
3. Вставьте его в поле.

Для проекта «Коричное яблоко»:

`https://k-apple.ru/`

4. Найдите поле **«Робот»**.
5. Выберите **«Основной робот Яндекса»**.
6. Найдите поле `If-Modified-Since`.
7. Если в нём указана дата, нажмите крестик справа от значения.
8. Убедитесь, что поле пустое.
9. Нажмите **«Проверить»**.
10. Дождитесь появления результата.

**Почему очищаем If-Modified-Since:**

Это поле используется для условных HTTP-запросов. При определённых условиях сервер может вернуть `304 Not Modified`.

Для обычной проверки доступности нужен запрос без этого условия.

**Часть 3. Проверить HTTP-ответ**

Найдите блок ответа сервера.

Проверьте:

1. Код статуса HTTP.
2. Время ответа сервера.
3. Размер страницы.
4. Кодировку.
5. Тип содержимого.
6. Сообщения об ошибках.
7. Статус SSL, если он отображается.

**Ожидаемый результат:**

`200 OK`

Для обычной HTML-страницы это означает, что сервер успешно вернул документ.

### В. Правильно интерпретировать результат проверки сервера

| Показатель | Правильный результат | Когда требуется действие |
|---|---|---|
| HTTP-код | 200 OK | Код не соответствует ожидаемому |
| Время ответа | Без превышения допустимого времени ожидания | Ответ слишком медленный или периодически отсутствует |
| Размер документа | Не превышает поддерживаемые ограничения | Документ слишком большой или пустой |
| Кодировка | Текст отображается корректно | Появляются ошибки отображения |
| Content-Type | Соответствует фактическому документу | Возвращается неподходящий формат |
| SSL | Нет ошибок сертификата | Сертификат недействителен или соединение не устанавливается |
| Содержимое | Реальный материал сайта | Вместо страницы получена ошибка, CAPTCHA или заглушка |

**Часть 1. Проверить содержимое ответа**

1. Прокрутите результаты проверки вниз.
2. Найдите раскрываемый блок **«Содержимое страницы»**.
3. Нажмите на него.
4. Посмотрите полученный HTML.
5. Убедитесь, что он относится к проверяемой странице.
6. Проверьте отсутствие CAPTCHA, страницы блокировки или сообщения DDoS-защиты.

**Важно:** ответ `200 OK` может возвращаться даже для страницы защиты от роботов. Поэтому при наличии DDoS-защиты необходимо дополнительно проверить содержимое ответа.

**Часть 2. Определить необходимость исправления**

Если сервер возвращает реальное содержимое сайта и не показывает ошибок, ничего менять не требуется.

Если вместо страницы получена CAPTCHA или сообщение блокировки:

1. Зафиксируйте фактический URL.
2. Проверьте, воспроизводится ли проблема повторно.
3. Обратитесь к хостинг-провайдеру или поставщику защиты.
4. Сообщите, что основной робот Яндекса получает страницу защиты вместо содержимого.
5. После исправления повторите проверку.

Не отключайте DDoS-защиту целиком без подтверждённой необходимости.

### Г. Выполнить массовую проверку HTTP-ответов

**Это основной способ проверки уже известных Яндексу страниц.**

**Часть 1. Открыть статистику обхода**

1. Откройте https://webmaster.yandex.ru/.
2. Выберите нужный сайт.
3. В левом меню раскройте **«Индексирование»**.
4. Найдите **«Статистика обхода»**.
5. Нажмите на название.
6. Дождитесь загрузки отчёта.

**Часть 2. Показать все страницы**

1. Найдите переключатель режима отображения.
2. Выберите **«Все страницы»**.
3. Дождитесь загрузки таблицы.
4. Найдите столбцы с адресом страницы, датой обхода и кодом ответа.
5. Убедитесь, что отображаются данные нужного сайта.

В этом режиме Вебмастер может показывать до 50 000 страниц, которые посещал робот.

**Часть 3. Найти страницы с ошибками**

1. Найдите значок фильтра таблицы.
2. Откройте фильтрацию.
3. Выберите параметр **«Код ответа сервера»**.
4. Установите условие для проверки нужного кода.
5. Начните с `404`.
6. Посмотрите найденные страницы.
7. Повторите проверку для `403`, `429` и ошибок `5xx`.
8. При необходимости проверьте неожиданные перенаправления `3xx`.

**Важно:** отсутствие ошибки в текущем отчёте не гарантирует отсутствие ошибки в настоящий момент. Отчёт отражает ответы, полученные роботом во время предыдущих обходов.

**Часть 4. Определить значимость ошибок**

Для каждого найденного проблемного URL:

1. Посмотрите адрес страницы.
2. Найдите соответствующий адрес в списке GURU.
3. Определите назначение страницы.
4. Установите, должна ли она существовать и индексироваться.
5. Если страница важная, переходите к индивидуальной проверке.
6. Если это намеренно удалённая или техническая страница, оцените корректность её ответа.

**Не исправляйте все ответы 404 подряд.**

Если адрес действительно удалён и не должен существовать, корректный `404` может быть нормальным результатом.

**Часть 5. Проверить последние изменения**

1. В отчёте «Статистика обхода» найдите переключатель режима.
2. Выберите **«Последние изменения»**.
3. Найдите страницы, у которых изменился HTTP-код.
4. Обратите внимание на переходы с `200` на `404`, `403` или `5xx`.
5. Для важных страниц выполните повторную проверку ответа сервера.

**Ожидаемый результат:** определены важные страницы с подтверждёнными или потенциальными проблемами доступности.

**Ограничение:** отчёт не выполняет новую проверку каждого URL в реальном времени. Он показывает историю обхода роботом.

Если нужная страница отсутствует в отчёте, это не доказывает, что она недоступна.

### Д. Выполнить массовую проверку robots.txt

**Часть 1. Открыть инструмент**

1. Откройте Яндекс Вебмастер.
2. Выберите сайт.
3. В левом меню раскройте **«Инструменты»**.
4. Нажмите **«Анализ robots.txt»**.
5. Дождитесь загрузки файла.

Для подключённого сайта содержимое файла обычно подставляется автоматически.

**Часть 2. Проверить правила**

1. Найдите блок **«Результаты анализа robots.txt»**.
2. Откройте вкладку **«Правила обхода»**.
3. Посмотрите действующие директивы.
4. Перейдите на вкладку **«Ошибки»**.
5. Проверьте, обнаружены ли синтаксические ошибки или противоречия.

**Ожидаемый результат:** файл корректно обрабатывается Яндексом.

**Часть 3. Проверить несколько URL одновременно**

1. Прокрутите страницу до раздела **«Доступ к страницам»**.
2. Найдите поле **«Список страниц»**.
3. Вернитесь к списку URL в GURU.
4. Скопируйте адреса страниц, предназначенных для индексирования.
5. Вставьте адреса в поле Вебмастера, каждый с новой строки.
6. Нажмите **«Проверить»**.
7. Дождитесь результата.

Пример:

`https://k-apple.ru/`

`https://k-apple.ru/novogodnie-podarki-2027`

`https://k-apple.ru/individualnyj_zakaz`

При большом количестве адресов выполняйте проверку последовательными группами.

**Часть 4. Интерпретировать результаты**

| Результат | Значение | Решение |
|---|---|---|
| Обход разрешён | robots.txt не запрещает адрес | Продолжить проверку |
| Обход запрещён | Сработала запрещающая директива | Проверить обоснованность запрета |
| Проверка не выполнена | URL или ресурс вызвал ошибку | Провести индивидуальную диагностику |

**Если важная страница закрыта:**

1. Найдите запрещающую директиву.
2. Проверьте, действительно ли адрес должен индексироваться.
3. Установите источник правила.
4. Если запрет ошибочный, исправьте его в настройках сайта.
5. Повторите проверку того же URL.

**Важно:** Tilda автоматически формирует `robots.txt`. Не заменяйте весь файл пользовательским кодом ради исправления одного правила без проверки последствий.

### Е. Проверить Meta Robots на важных страницах

Инструмент «Анализ robots.txt» не заменяет проверку метатега `robots`.

Для проверки используем **«Анализ индексации страницы»**.

**Часть 1. Открыть инструмент**

1. Откройте https://webmaster.yandex.ru/.
2. Выберите сайт.
3. В левом меню раскройте **«Инструменты»**.
4. Нажмите **«Анализ индексации страницы»**.
5. Найдите поле URL.

**Часть 2. Проверить страницу**

1. В GURU найдите необходимую страницу.
2. Скопируйте её полный адрес.
3. Вставьте URL в поле инструмента.
4. Нажмите **«Проверить»**.
5. Дождитесь результата.

**Часть 3. Интерпретировать результат**

| Результат | Решение |
|---|---|
| Страница доступна для индексирования | Проверяемые запреты отсутствуют |
| Страница закрыта от индексирования | Установить причину |
| Проверка не выполнена | Проверить URL и доступность страницы |

Инструмент учитывает ограничения `robots.txt` и метатега `robots`.

**Важно:** он проверяет по одному URL за раз.

Поэтому используйте его прежде всего для:

- Главной страницы.
- Ключевых коммерческих страниц.
- Представителей основных типов страниц.
- Страниц с выявленными ошибками.
- URL, у которых есть признаки нежелательного `noindex`.

Не выполняйте сотни одинаковых проверок без установленной причины.

### Ж. Исправить ошибочный noindex на Tilda

Выполняйте только если обнаружен нежелательный запрет.

**Часть 1. Открыть настройки страницы**

1. Откройте https://tilda.cc/login/.
2. Выберите нужный проект.
3. Найдите проблемную страницу.
4. Откройте её **«Настройки»**.
5. Перейдите на вкладку **«SEO»**.
6. Найдите **«Отображение в поисковой выдаче»**.
7. Нажмите **«Настроить отображение в поисковой выдаче»**.
8. Найдите **«Запретить поисковикам индексировать эту страницу»**.

**Часть 2. Проверить настройку**

Если страница должна индексироваться, галочка запрета должна быть снята.

Если запрет установлен ошибочно:

1. Снимите галочку.
2. Сохраните настройки.
3. Опубликуйте страницу.
4. Откройте Яндекс Вебмастер.
5. Повторите анализ индексирования.

**Ожидаемый результат:** нежелательный запрет больше не обнаруживается.

**Важно:** отсутствие метатега с явным значением `index` не является ошибкой.

Не добавляйте `index, follow` вручную, если соответствующие ограничения отсутствуют.

### З. Проверить общий запрет индексирования сайта

Выполняйте при обнаружении массовых проблем.

1. Откройте Tilda.
2. Выберите нужный проект.
3. Перейдите в **«Настройки сайта»**.
4. В левом меню нажмите **«SEO»**.
5. Найдите раздел **«Запрет индексации»**.
6. Найдите пункт **«Запретить поисковикам индексировать этот сайт»**.
7. Проверьте состояние галочки.

Для опубликованного сайта, предназначенного для поисковой выдачи, общий запрет должен быть выключен.

**Если запрет выключен:** ничего не изменяйте.

**Если запрет включён ошибочно:**

1. Снимите галочку.
2. Сохраните настройки.
3. Опубликуйте все страницы.
4. Повторите проверку в Вебмастере.

Не снимайте ограничения с закрытого или тестового сайта без подтверждения владельца.

### И. Проверить товарные страницы интернет-магазина

Выполняйте, если проект продаёт товары через Tilda.

**Часть 1. Получить адреса**

GURU должен использовать фактические URL товаров, сохранённые в «Платформе».

Если товар использует автоматически созданный адрес каталога Tilda, проверять необходимо именно этот опубликованный URL.

Не создавайте URL на основании названия товара.

**Часть 2. Проверить видимость товаров**

1. Откройте https://tilda.cc/login/.
2. Выберите проект.
3. Перейдите в **«Каталог товаров»**.
4. Найдите необходимый товар.
5. Проверьте его видимость.
6. Убедитесь, что товар опубликован.

**Часть 3. Проверить URL**

1. Откройте опубликованный адрес товара.
2. Убедитесь, что отображается правильная карточка.
3. При наличии проблемы перейдите в Яндекс Вебмастер.
4. Откройте **«Проверка ответа сервера»**.
5. Введите URL товара.
6. Выберите основного робота.
7. Нажмите «Проверить».
8. Изучите результат.

При подозрении на запрет дополнительно используйте «Анализ индексации страницы».

**Важно:** для товаров Каталога Tilda может автоматически создавать отдельные URL и товарную карту Sitemap.

Их полноту будем отдельно проверять на следующем этапе **2.2. Проверка Sitemap**.

Не создавайте дополнительные страницы товаров без необходимости.

### К. Индивидуально проверить проблемные URL

Выполняйте, если массовая проверка обнаружила ошибки или нужный URL отсутствует в статистике обхода.

**Часть 1. Выбрать адрес**

1. Откройте в GURU список страниц проекта.
2. Найдите проблемную страницу.
3. Скопируйте её URL.
4. Определите, должна ли она существовать и индексироваться.

**Часть 2. Проверить сервер**

1. Откройте Яндекс Вебмастер.
2. Перейдите в **«Инструменты» → «Проверка ответа сервера»**.
3. Вставьте полный адрес.
4. Выберите основного робота.
5. Очистите поле `If-Modified-Since`.
6. Нажмите **«Проверить»**.
7. Посмотрите HTTP-код.
8. Откройте «Содержимое страницы».
9. Убедитесь, что робот получает нужный документ.

**Часть 3. Проверить запреты**

1. Перейдите в **«Инструменты» → «Анализ индексации страницы»**.
2. Введите тот же URL.
3. Нажмите «Проверить».
4. Проверьте результат.

**Ожидаемый результат:** известны фактическая доступность и наличие либо отсутствие проверяемых запретов.

Если проблема подтверждена, устраните её и повторите обе проверки.

### Л. Определить действия при ошибках

| Ошибка | Что означает | Что делать |
|---|---|---|
| 200 OK | Сервер вернул документ | Проверить содержимое и ограничения |
| 301 / 308 | Постоянный редирект | Проверить конечный URL |
| 302 / 307 | Временный редирект | Убедиться, что он предусмотрен |
| 304 | Документ не изменился относительно условного запроса | Очистить If-Modified-Since и повторить проверку |
| 403 | Доступ запрещён | Проверить защиту сервера и ограничения |
| 404 | Страница отсутствует | Проверить URL и публикацию |
| 429 | Сервер ограничивает запросы | Проверить нагрузку и защиту |
| 500 / 502 / 503 | Ошибка сервера | Проверить хостинг и повторяемость ошибки |
| SSL-ошибка | Проблема защищённого соединения | Проверить сертификат и домен |
| Disallow | Роботу запрещён обход | Проверить правило robots.txt |
| noindex | Индексирование запрещено | Проверить настройки страницы |
| Пустой HTML | Робот не получил содержимое | Проверить ответ и публикацию |
| CAPTCHA вместо страницы | Робот получил страницу защиты | Проверить настройки антибот-защиты |

**Порядок исправления:**

1. Найдите проблемный URL.
2. Прочитайте точное сообщение.
3. Определите источник ошибки.
4. Убедитесь, что страница действительно должна существовать и индексироваться.
5. Измените только настройку, вызвавшую проблему.
6. Сохраните изменения.
7. Если изменялась Tilda, опубликуйте соответствующие страницы.
8. Повторите проверку.
9. Сравните новый результат с первоначальным.

**Не меняйте DNS, robots.txt, сертификаты и глобальные настройки сайта без подтверждённой причины.**

### М. Подтвердить завершение проверки

**Часть 1. Сверить массовую диагностику**

1. Откройте «Статистика обхода».
2. Проверьте список страниц с ошибками.
3. Убедитесь, что выявленные проблемы важных страниц устранены либо имеют установленную причину.
4. Проверьте даты последнего обхода.

**Часть 2. Сверить robots.txt**

1. Откройте «Анализ robots.txt».
2. Проверьте результаты массовой проверки.
3. Убедитесь, что необходимые URL разрешены для обхода.
4. Проверьте отсутствие критических ошибок в правилах.

**Часть 3. Сверить индивидуальную диагностику**

1. Проверьте главную страницу.
2. Проверьте ключевые коммерческие разделы.
3. Проверьте выявленные проблемные страницы.
4. Убедитесь, что нежелательные ограничения устранены.

**Ожидаемый результат:** необходимые страницы технически доступны, а выявленные препятствия для обхода устранены.

**Важно:** если URL отсутствует в «Статистике обхода», это означает отсутствие подтверждённых данных о его обходе в данном отчёте. Не считайте такой URL проверенным автоматически.

Проверку включения страниц в поисковую базу выполняем отдельно в разделе 3.

### Итоговый результат

**Готово**

- GURU предоставил доступные адреса страниц проекта.
- Массовая проверка HTTP-ответов выполнена.
- Массовая проверка robots.txt выполнена.
- Главная и приоритетные страницы проверены.
- Подтверждённые технические ошибки устранены.
- Нежелательные ограничения индексирования отсутствуют.
- Существующие настройки сохранены.
- Не создано дублирующих инструментов и источников данных.

**Требует проверки**

- Часть необходимых URL отсутствует в данных GURU.
- Некоторые страницы ещё неизвестны роботу.
- Ошибки исправлены, но повторная проверка не завершена.
- Не подтверждена доступность отдельных приоритетных страниц.
- Данные статистики обхода ещё не обновились.

**Проблема**

- Важная страница недоступна.
- Робот получает ошибку сервера.
- Вместо содержимого возвращается страница защиты.
- Обнаружен ошибочный Disallow.
- Установлен нежелательный noindex.
- URL перенаправляет на неправильную страницу.
- SSL-соединение не устанавливается.

**Не требуется**

Индивидуальная проверка всех страниц, когда массовая диагностика и выборочные проверки дают достаточные сведения, а признаков проблем нет.

Этот статус не отменяет проверку доступности самого сайта и важных страниц.

### Результат для Яндекс Вебмастера

- **Назначение:** обеспечение технической доступности страниц для поискового робота.
- **Приоритет:** фундаментальная настройка.
- **Основные инструменты:** «Статистика обхода», «Анализ robots.txt».
- **Вспомогательные инструменты:** «Проверка ответа сервера», «Анализ индексации страницы».
- **Источник URL:** существующие данные GURU.
- **Метод:** массовая проверка и индивидуальная диагностика проблемных адресов.
- **Основное ограничение:** техническая доступность не гарантирует включения страницы в поисковую выдачу.
- **Результат:** известные технические препятствия устранены, сайт готов к проверке Sitemap и фактической индексации.

**После завершения проверки доступности можно переходить к 2.2. Проверка Sitemap.**
