# 3.1.6. Успешная регистрация

## 1. Что сделать (инструкция)

Настроить Яндекс Метрику для учёта новых пользователей, которые успешно создали учётную запись на сайте.

**Успешная регистрация:** система создала нового пользователя, и он получил предусмотренный доступ к личному кабинету.

Не путайте:

| Действие | Что подтверждает |
|---|---|
| Открытие страницы регистрации | Интерес посетителя |
| Нажатие «Зарегистрироваться» | Попытку регистрации |
| Отправка регистрационной формы | Передачу введённых данных |
| Создание учётной записи | Успешную регистрацию |
| Вход в существующий аккаунт | Авторизацию, а не новую регистрацию |
| Покупка доступа | Отдельный платёжный результат |

**Рекомендуемый идентификатор Яндекс Метрики:** `ym-register`. Он предусмотрен официальными рекомендациями Яндекса для регистрации пользователей.

Для Tilda возможны два варианта:

1. Регистрация через обычную форму Tilda с подключённым приёмщиком «Личный кабинет».
2. Встроенная регистрация через `/members/signup`.

Инструкции отличаются. Используйте только тот способ, который фактически работает на сайте.

Если сайт не предусматривает регистрацию пользователей, цель не требуется.

## 2. Где нажать / Как проверить (инструкция)

### А. Найти или проверить существующую цель

1. Откройте https://metrika.yandex.ru/.
2. Авторизуйтесь через рабочий Яндекс ID.
3. Выберите счётчик сайта.
4. В левом меню нажмите «Цели».
5. Найдите цели, связанные с регистрацией пользователей.
6. Если подходящая цель существует, нажмите значок редактирования.
7. Определите её тип и условие достижения.
8. Убедитесь, что условие соответствует успешной регистрации, а не просто открытию страницы.
9. Если цель настроена корректно, повторно её не создавайте.

**Если подходящей цели нет:** сначала определите механизм регистрации на сайте. Не создавайте цель до того, как узнаете, какое событие она должна отслеживать.

### Б. Определить механизм регистрации Tilda

1. Откройте https://tilda.cc/login/.
2. Войдите в аккаунт сайта.
3. Выберите нужный проект.
4. Нажмите «Настройки сайта».
5. В левом меню выберите «Подключаемые модули».
6. Найдите «Личный кабинет».
7. Нажмите «Управление модулем».
8. Откроется управление пользователями личного кабинета.
9. В левом меню найдите «Настройки личного кабинета».
10. Откройте вкладку «Основные».
11. Найдите «Разрешить регистрацию через форму».
12. Посмотрите состояние галочки.

**Если галочка включена:** Tilda предоставляет встроенную страницу самостоятельной регистрации.

Её адрес обычно имеет вид:

`https://example.ru/members/signup`

Скопируйте фактическую ссылку с главной страницы управления личным кабинетом.

**Если галочка выключена:** проверьте, используется ли отдельная форма Tilda с приёмщиком «Личный кабинет».

Не включайте открытую регистрацию только ради аналитики. Это изменяет способ предоставления доступа к сайту.

### В. Настроить регистрацию через обычную форму Tilda

Этот вариант позволяет использовать встроенную передачу виртуального события отправки формы.

**Часть 1. Проверить приёмщик личного кабинета**

1. Вернитесь в панель управления сайтом Tilda.
2. Нажмите «Настройки сайта».
3. Откройте раздел «Формы».
4. Найдите группу сервисов «Другое».
5. Выберите «Личный каб.».
6. Если сервис уже подключён, откройте его настройки.
7. Если отсутствует, начните подключение.
8. Найдите поле выбора группы пользователей.
9. Выберите группу, в которую должны попадать новые зарегистрированные пользователи.
10. Нажмите «Добавить», если создаёте подключение.
11. Убедитесь, что приёмщик появился среди подключённых сервисов.

Не создавайте вторую интеграцию, если подходящая уже работает.

**Часть 2. Проверить форму регистрации**

1. Откройте страницу Tilda, на которой находится регистрационная форма.
2. Перейдите в редактор.
3. Найдите блок формы.
4. Нажмите «Контент».
5. Найдите раздел «Поля для ввода».
6. Убедитесь, что форма содержит обязательные данные для выбранного способа регистрации, например email.
7. Найдите раздел «Приём данных из формы».
8. Установите галочку у подключённого приёмщика «Личный кабинет», если её ещё нет.
9. Нажмите «Сохранить и закрыть».
10. Опубликуйте страницу.

Если форма отсутствует, добавьте стандартный блок из категории «Форма», затем выполните указанные действия.

**Часть 3. Проверить предоставление доступа**

1. Откройте Tilda → «Настройки сайта» → «Подключаемые модули».
2. Выберите «Личный кабинет» → «Управление модулем».
3. В левом меню откройте группу, которую указали в приёмщике.
4. Откройте настройки группы.
5. Найдите параметр «Добавлять пользователей в группу без подтверждения».
6. Посмотрите его состояние.

Если автоматическое добавление включено, новый пользователь может получать доступ без отдельного решения администратора.

Если требуется ручное подтверждение, не включайте автоматическое добавление только ради цели Метрики.

**Важно:** отправка формы и фактическое создание пользователя должны проверяться отдельно.

### Г. Найти виртуальное событие формы Tilda

1. Вернитесь в редактор страницы регистрации.
2. Найдите блок регистрационной формы.
3. Нажмите «Настройки».
4. Прокрутите панель вниз.
5. Найдите пояснение об отправке формы в системы аналитики.
6. Скопируйте виртуальный адрес отправки.

Пример:

`/tilda/formXXXXXXXXXX/submitted`

Используйте только фактический адрес из настроек формы.

**Что означает событие:** Tilda отправила форму и зарегистрировала соответствующий виртуальный просмотр.

**Чего оно не гарантирует:** создания аккаунта, подтверждения контакта или предоставления доступа.

Поэтому для использования этой цели как основной необходимо дополнительно подтвердить регистрацию в личном кабинете.

### Д. Создать цель на отправку регистрационной формы

Используйте этот вариант, если регистрация действительно выполняется через обычную форму Tilda.

1. Откройте https://metrika.yandex.ru/.
2. Выберите счётчик сайта.
3. В левом меню нажмите «Цели».
4. Убедитесь, что подходящей цели с тем же виртуальным адресом нет.
5. Нажмите «Добавить цель».
6. На экране «Новая цель» найдите раздел «Вовлечённость».
7. Выберите «Посещение страниц».
8. В поле «Название» введите:

   `Регистрационная форма отправлена`

9. Выберите условие `URL содержит`.
10. Вставьте виртуальный адрес из Tilda.
11. Сравните идентификатор формы посимвольно.
12. Нажмите «Добавить цель».
13. Найдите созданную цель в списке.
14. Сохраните её числовой ID.

**Результат:** создана техническая цель отправки регистрационной формы.

Она не должна называться «Успешная регистрация», пока не подтверждено, что каждое её достижение соответствует созданному аккаунту.

Если используется встроенная страница `/members/signup`, этот способ не применяйте автоматически: у неё нет подтверждённого в документации аналога виртуального события обычной формы Tilda.

### Е. Настроить точную цель успешной регистрации

Для основной бизнес-конверсии предпочтительно использовать событие, которое возникает только после успешного создания нового аккаунта.

Яндекс рекомендует идентификатор:

`ym-register`

**Часть 1. Создать цель**

1. Откройте Метрику.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Цели».
4. Проверьте, не существует ли уже цель с идентификатором `ym-register`.
5. Если такой цели нет, нажмите «Добавить цель».
6. Выберите категорию «Пользовательские события».
7. Нажмите «Целевое событие · ex JS-событие».
8. В поле названия введите «Успешная регистрация».
9. Выберите условие «Совпадает».
10. В поле идентификатора укажите:

   `ym-register`

11. Нажмите «Добавить цель».
12. Убедитесь, что цель появилась в списке.

**Часть 2. Обеспечить передачу события**

Создание цели само по себе не включает автоматическую отправку `ym-register` из Tilda.

Необходимо, чтобы сайт или интеграция вызвали метод Метрики **только после подтверждённого создания пользователя**.

Формат вызова Яндекса:

`ym(НОМЕР_СЧЁТЧИКА, 'reachGoal', 'ym-register')`

Где `НОМЕР_СЧЁТЧИКА` заменяется на фактический ID установленного счётчика.

Такой вызов должен выполняться после успешного ответа системы регистрации, а не при нажатии кнопки, отправке формы или обычном входе в аккаунт.

**Для стандартного личного кабинета Tilda:** официальная документация не подтверждает наличие готового переключателя, который автоматически передаёт `ym-register` после создания пользователя.

Если уже есть работающая интеграция, передающая подтверждённое событие, используйте её.

Если такой интеграции нет, потребуется отдельная реализация с доступом к результату регистрации. Не вставляйте вызов `reachGoal` просто в кнопку регистрации: это создаст ложные конверсии.

До реализации передачи цель останется созданной, но её работоспособность не будет подтверждена.

### Ж. Подготовить контрольную регистрацию

1. Убедитесь, что целевая форма или встроенная страница регистрации работает на опубликованном сайте.
2. Подготовьте новый email, который ещё не использовался для регистрации.
3. Не используйте существующую учётную запись для положительного теста.
4. Откройте новое приватное окно Chrome.
5. Не авторизуйтесь в Яндекс Метрике внутри этого окна.
6. Откройте страницу регистрации.
7. Если используется обычная опубликованная страница Tilda, добавьте к её URL параметр `_ym_debug=2`.
8. Дождитесь загрузки.
9. Откройте панель отладки Метрики, если она доступна на странице.
10. Во вкладке `Counters` проверьте номер счётчика.

Если встроенная страница регистрации личного кабинета не содержит доступного отладчика Метрики, это не доказывает неисправность регистрации. Для проверки передачи события потребуется подтверждённая интеграция или иной доступный диагностический механизм.

### З. Выполнить одну регистрацию

1. Введите подготовленный новый email или телефон.
2. Заполните предусмотренные регистрационной формой поля.
3. Подтвердите необходимые согласия.
4. Нажмите кнопку регистрации.
5. Если система требует одноразовый код, получите его и введите в соответствующее поле.
6. Дождитесь завершения операции.
7. Если пришло письмо с данными для входа, откройте его.
8. Следуйте предусмотренной процедурe завершения регистрации.
9. Зафиксируйте время теста.

**Ожидаемый результат:** система сообщает о создании пользователя либо позволяет войти в новый аккаунт.

Не считайте открытие страницы регистрации или нажатие кнопки успешной конверсией.

### И. Подтвердить создание пользователя в Tilda

1. Откройте административный кабинет Tilda.
2. Выберите проект.
3. Перейдите в «Настройки сайта» → «Подключаемые модули».
4. Откройте «Личный кабинет» → «Управление модулем».
5. Перейдите в раздел «Все пользователи».
6. Найдите тестовый email или телефон.
7. Откройте карточку пользователя.
8. Проверьте, что пользователь действительно создан.
9. Если должна предоставляться определённая группа доступа, найдите её в карточке.
10. Убедитесь, что пользователь состоит в нужной группе либо имеет ожидающий подтверждения статус согласно принятому бизнес-процессу.

Если требуется подтверждение администратора, завершите предусмотренную процедуру и проверьте итоговый доступ.

**Ожидаемый результат:** новый пользователь действительно существует, а требуемые условия регистрации выполнены.

Для дополнительного контроля откройте страницу входа в приватном окне и выполните первый вход под тестовой учётной записью.

### К. Проверить событие в Яндекс Метрике

**Если используется виртуальная цель формы:**

1. Откройте опубликованную страницу регистрации с `_ym_debug=2`.
2. При корректной новой тестовой отправке откройте панель отладки.
3. Перейдите во вкладку `Console`.
4. Найдите `PageView` виртуального адреса `/tilda/form.../submitted`.
5. Сравните адрес с условием цели.

**Если используется целевое событие `ym-register`:**

1. Выполните регистрацию через систему, в которой настроена передача события.
2. Откройте отладчик Метрики.
3. Перейдите во вкладку `Events`.
4. Найдите сведения о достижении `ym-register`.
5. Во вкладке `Console` проверьте вызов `reachGoal` и идентификатор счётчика.

**Ожидаемый результат:** событие передано правильному счётчику.

Если `ym-register` отсутствует, но аккаунт создан, проверьте реализацию передачи события. Не создавайте дополнительную цель на кнопку вместо исправления интеграции.

### Л. Проверить достижение цели в отчёте

**Через 10-15 минут после теста:**

1. Откройте https://metrika.yandex.ru/.
2. Выберите счётчик.
3. Слева нажмите «Конверсии».
4. Установите период, включающий время теста.
5. Найдите проверяемую цель.
6. Посмотрите показатель «Достижения цели».
7. Сравните его с количеством подтверждённых регистраций.

**Ожидаемый результат:** новая подтверждённая регистрация соответствует достижению основной цели.

Если достижения нет через 15 минут:

1. Проверьте период и счётчик.
2. Проверьте фильтры собственных посещений.
3. Убедитесь, что цель существовала до теста.
4. Проверьте передачу события через отладчик.
5. Повторите просмотр отчёта через 15 минут.

Если через 30-60 минут данных нет, проверьте настройку события и доступность счётчика. Этот интервал является практическим ориентиром диагностики, а не гарантированным пределом обработки.

### М. Исключить ложные и повторные регистрации

1. Возьмите email уже существующего тестового пользователя.
2. Откройте форму регистрации в приватном окне.
3. Попробуйте выполнить регистрацию с этим же адресом, если система допускает такую попытку.
4. Посмотрите результат: новый аккаунт не должен создаваться повторно.
5. Убедитесь, что система не передала `ym-register` как событие новой успешной регистрации.
6. Отдельно выполните обычный вход в существующий аккаунт.
7. Убедитесь, что авторизация не учитывается как новая регистрация.

**Правильный результат:** основная цель срабатывает на создание нового аккаунта, а не на повторный вход, повторную отправку или открытие регистрационной страницы.

Если используется виртуальная цель отправки формы, она может фиксировать повторные отправки. В таком случае её нельзя без дополнительной проверки считать числом уникальных регистраций.

### Н. Подготовить цель для Яндекс Директа

После успешной сверки:

1. Откройте Метрику → «Цели».
2. Найдите проверенную цель успешной регистрации.
3. Скопируйте её числовой ID.
4. Убедитесь, что её достижения соответствуют реально созданным аккаунтам.
5. Проверьте отсутствие дублирования с целями отправки формы и авторизации.
6. Используйте цель в Директе только после подтверждения её достоверности.

Не добавляйте одновременно регистрацию, вход в аккаунт и отправку регистрационной формы как три равнозначные основные конверсии одного пользователя.

## 3. Сверка (инструкция)

| Критерий | Правильный результат |
|---|---|
| Сценарий регистрации | Установлен |
| Счётчик Метрики | Подключён правильно |
| Источник события | Определён |
| Цель Метрики | Создана или найдена без дублей |
| Тестовая регистрация | Завершена |
| Пользователь в Tilda | Создан |
| Доступ | Соответствует правилам проекта |
| Событие Метрики | Передано при успешной регистрации |
| «Конверсии» | Достижение зарегистрировано |
| Повторный вход | Не считается новой регистрацией |
| Повторная отправка | Не создаёт ложную успешную регистрацию |

### Итоговый статус

**Готово:** новый аккаунт создан, регистрация подтверждена, соответствующее событие передано и цель достигнута.

**Требует проверки:** аккаунт создан, но передача события или его регистрация в отчётах ещё не подтверждена.

**Проблема:** цель срабатывает без создания пользователя, передача отсутствует или повторная авторизация учитывается как новая регистрация.

**Не требуется:** проект не предусматривает регистрацию пользователей.

### Результат для аналитики

- Назначение: успешная регистрация.
- Приоритет: основная бизнес-конверсия, если регистрация является значимым результатом проекта.
- Предпочтительный идентификатор Метрики: `ym-register`.
- Резервный механизм Tilda: виртуальная отправка регистрационной формы с обязательной сверкой созданных аккаунтов.
- Использование: аналитика новых пользователей и последующая оптимизация Яндекс Директа.
