# 2.2. Проверка Sitemap

## 1. Что сделать (инструкция)

Проверить, что все необходимые файлы Sitemap существуют, доступны поисковому роботу Яндекса, содержат актуальные адреса страниц и корректно обрабатываются Яндекс Вебмастером.

**Целевое действие:** подтвердить, что Яндекс получает актуальные карты сайта, включая страницы, категории товаров, карточки товаров и опубликованные материалы.

Различайте:

| Состояние | Что подтверждает |
|---|---|
| Sitemap существует | Файл карты сайта создан |
| HTTP 200 OK | Файл доступен для загрузки |
| Корректный XML | Структура соответствует требованиям |
| URL присутствует в Sitemap | Адрес передаётся поисковой системе |
| Sitemap обработан со статусом OK | Яндекс успешно обработал файл |
| Страница находится в поиске | Яндекс включил конкретную страницу в поисковую базу |

**Приоритет:** фундаментальная настройка.

**Практическая ценность:**

- Передавать Яндексу актуальные адреса страниц.
- Облегчать обнаружение новых товаров, категорий и публикаций.
- Проверять полноту передаваемой структуры сайта.
- Находить технические ошибки Sitemap.
- Контролировать обработку карт поисковым роботом.
- Исключать ненужное ручное редактирование файлов.

Для проверки используем штатные инструменты Яндекс Вебмастера:

- «Файлы Sitemap».
- «Анализ файлов Sitemap».
- «Проверка ответа сервера».

**Рекомендация для GURU:** использовать автоматическую генерацию Sitemap, если она предусмотрена платформой сайта.

**Условия применения:**

- Sitemap существует и обрабатывается корректно: повторно не создаём.
- Обнаружена ошибка: определяем и устраняем причину.
- Используется интернет-магазин: проверяем товарные URL.
- Используется CMS с публикациями: проверяем Sitemap опубликованных материалов.
- Файл корректен, но Яндекс показывает старое предупреждение: сравниваем дату последней загрузки и текущий результат проверки.
- Файл уже известен Яндексу: повторно не добавляем.

**Важно:** Sitemap сообщает поисковой системе об адресах страниц, но не гарантирует их включения в поиск.

## 2. Где нажать / Как проверить (инструкция)

### А. Получить адреса страниц и Sitemap из GURU

**Часть 1. Определить исходные данные**

GURU должен автоматически использовать уже сохранённые сведения проекта:

1. Основной URL сайта из «Платформы».
2. Системные страницы.
3. Коммерческие разделы и категории.
4. Посадочные страницы товаров и услуг.
5. Опубликованные карточки товаров.
6. Дополнительные коммерческие страницы.
7. Адреса публикаций, если они сохранены в проекте.

**Не создавать новое хранилище URL.**

**Часть 2. Предоставить ссылки на карты сайта**

В инструкции автоматически показывать раздел:

**«Sitemap проекта для проверки»**.

Для «Коричного яблока»:

| Назначение | Файл |
|---|---|
| Основные страницы | https://k-apple.ru/sitemap.xml |
| Товары | https://k-apple.ru/sitemap-store.xml |
| Индекс публикаций | https://k-apple.ru/sitemap-feeds.xml |
| Публикации потока «Блог» | https://k-apple.ru/sitemap-feed-932486340531.xml |
| Правила обхода | https://k-apple.ru/robots.txt |

Адреса дополнительных карт необходимо получать из опубликованных файлов и настроек сайта, а не генерировать предположительно.

**Часть 3. Предоставить список целевых страниц**

GURU должен использовать список URL, подготовленный при проверке доступности страниц в шаге 2.1.

Для каждой страницы показывать:

- Название.
- Тип страницы.
- Полный URL.
- Активную ссылку.

Если URL отсутствует, показывать «URL не заполнен» и переход к существующему месту ввода.

**Требования:**

1. Не дублировать URL.
2. Не придумывать отсутствующие адреса.
3. Использовать основной домен.
4. Отдельно учитывать системные и коммерческие страницы.
5. Обновлять список при изменении исходных данных.
6. Не изменять существующие поля и структуру GURU.

**Ожидаемый результат:** пользователь получает ссылки на необходимые Sitemap и страницы без повторного ручного ввода.

### Б. Проверить наличие файлов Sitemap

**Часть 1. Проверить основную карту**

1. Откройте Chrome.
2. Вставьте адрес основного Sitemap.
3. Нажмите Enter.
4. Дождитесь загрузки.
5. Убедитесь, что браузер отображает XML.

Пример:

`https://k-apple.ru/sitemap.xml`

**Часть 2. Проверить дополнительные карты**

Если они используются:

1. Откройте товарную карту.
2. Проверьте наличие XML.
3. Откройте карту публикаций.
4. Проверьте наличие XML.
5. Если карта является индексом Sitemap, откройте указанный внутри неё файл.

**Для «Коричного яблока»:**

`sitemap-feeds.xml` является индексом и содержит ссылку на:

`sitemap-feed-932486340531.xml`

Вложенный файл содержит семь адресов опубликованных статей.

**Часть 3. Проверить структуру**

Пример обычного Sitemap:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.ru/</loc>
  </url>
</urlset>
```

Пример индекса Sitemap:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://example.ru/sitemap-articles.xml</loc>
  </sitemap>
</sitemapindex>
```

Это примеры структуры, не фактическое содержимое проекта.

| Элемент | Назначение |
|---|---|
| `urlset` | Список URL |
| `url` | Отдельная страница |
| `loc` | Адрес страницы или Sitemap |
| `lastmod` | Дата изменения |
| `sitemapindex` | Индекс других Sitemap |
| `sitemap` | Запись вложенной карты |

**Важно:** сообщение Chrome «This XML file does not appear to have any style information» не является ошибкой.

XML не обязан иметь визуальное оформление.

### В. Проверить автоматическую генерацию Sitemap в Tilda

Выполняйте, если сайт создан на Tilda.

**Часть 1. Открыть настройки**

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь.
3. Выберите нужный проект.
4. Перейдите в **«Настройки сайта»**.
5. В левом меню нажмите **«SEO»**.
6. Найдите **«Редактирование sitemap.xml»**.
7. Откройте этот раздел.

**Часть 2. Определить режим генерации**

Tilda предусматривает:

| Режим | Назначение |
|---|---|
| Автоматическая генерация | Формирование карты на основе страниц |
| Автоматическая генерация с дополнением | Автоматическая карта и дополнительные URL |
| Ручное управление | Самостоятельное сопровождение XML |

**Рекомендация:** сохранять автоматическую генерацию по умолчанию.

**Часть 3. Проверить существующие настройки**

1. Посмотрите активный режим.
2. Если используется автоматическая генерация, ничего не изменяйте.
3. Если используется режим с дополнением, проверьте вручную добавленные URL.
4. Если включено ручное управление, выясните причину его использования.

**Важно:** ручное управление требует самостоятельного обновления карты при изменении страниц и адресов сайта.

Не переключайте работающую карту в ручной режим без конкретной необходимости.

**Ограничение Tilda:** основной `sitemap.xml` поддерживает до 3000 записей или 3 МБ.

Это ограничение генератора Tilda. Яндекс поддерживает Sitemap большего размера.

### Г. Проверить товарный Sitemap

Выполняйте для интернет-магазинов на Tilda.

**Часть 1. Найти файл**

1. Откройте опубликованный товарный Sitemap.
2. Убедитесь, что файл доступен.
3. Найдите элементы `loc`.
4. Проверьте адреса товаров.

Для «Коричного яблока»:

`https://k-apple.ru/sitemap-store.xml`

**Часть 2. Проверить настройки каталога**

Если файл отсутствует или формируется неправильно:

1. Откройте Tilda.
2. Выберите проект.
3. Перейдите в **«Каталог товаров»**.
4. Откройте настройки каталога.
5. Перейдите на вкладку **«Дополнительно»**.
6. Найдите блок **«Параметры Sitemap»**.
7. Проверьте опцию **«Включить генерацию Sitemap»**.

**Если генерация уже включена и файл работает:** ничего не изменяйте.

**Часть 3. Сверить товары**

1. Откройте Каталог товаров.
2. Найдите опубликованный товар.
3. Откройте его на сайте.
4. Скопируйте полный URL.
5. Найдите его в товарном Sitemap.
6. Проверьте совпадение адресов.

**Важно:** если товар имеет отдельную посадочную страницу и собственную каноническую ссылку, необходимо учитывать фактический индексируемый URL.

Не создавать дубли товарных страниц исключительно ради Sitemap.

### Д. Проверить Sitemap публикаций

Выполняйте, если используется CMS «Потоки».

**Часть 1. Проверить подключение**

1. Откройте Tilda.
2. Выберите нужный проект.
3. Перейдите в **«Настройки сайта» → «Подключаемые модули»**.
4. Найдите **«CMS Потоки»**.
5. Убедитесь, что модуль подключён.

**Часть 2. Проверить публикации**

1. Нажмите **«Управление модулем»**.
2. Откройте нужный поток.
3. Посмотрите список публикаций.
4. Откройте одну из статей.
5. Найдите поле **«Видимость»**.
6. Проверьте, что установлено **«Опубликовано»**.
7. Откройте «SEO и соцсети».
8. Проверьте состояние настройки **«Запретить поисковикам индексировать эту страницу»**.

**Правильный результат:** публикация существует, доступна по собственному адресу и не имеет нежелательного запрета индексирования.

**Часть 3. Проверить вывод потока на сайт**

Если поток ещё не представлен на сайте:

1. Создайте или откройте существующую страницу публикаций.
2. Добавьте блок из категории «Потоки и CMS».
3. Откройте **«Контент»** блока.
4. Найдите **«Выводить поток»**.
5. Выберите действующий поток.
6. Сохраните изменения.
7. Опубликуйте страницу.
8. Проверьте открытие отдельных публикаций.

Для «Коричного яблока» используется блок **FD101N**, подключённый к потоку «Блог».

**Важно:** создание страницы со списком публикаций само по себе не гарантирует устранение ошибок Sitemap. Это дополнительная проверка работоспособности публикаций.

**Часть 4. Проверить карты потока**

1. Откройте `sitemap-feeds.xml`.
2. Найдите ссылку на вложенную карту.
3. Откройте вложенный файл.
4. Проверьте наличие опубликованных URL.
5. Сравните их с реальными публикациями.

**Ожидаемый результат:** карта формируется и содержит действующие адреса опубликованных материалов.

Если поток используется, не отключайте CMS для устранения ошибки Sitemap.

### Е. Проверить ссылки на Sitemap в robots.txt

**Часть 1. Открыть файл**

1. Откройте опубликованный сайт.
2. Добавьте к основному адресу `/robots.txt`.
3. Нажмите Enter.
4. Найдите директивы `Sitemap:`.

Пример:

```text
Sitemap: https://example.ru/sitemap.xml
Sitemap: https://example.ru/sitemap-store.xml
```

**Часть 2. Проверить адреса**

1. Посмотрите все директивы `Sitemap:`.
2. Проверьте домен и HTTPS.
3. Откройте каждый указанный файл.
4. Убедитесь, что адрес существует и возвращает корректное содержимое.

**Ожидаемый результат:** `robots.txt` указывает на необходимые действующие карты сайта.

**Важно:** Яндексу достаточно ссылки на Sitemap в `robots.txt` или добавления файла через интерфейс Вебмастера.

Повторно добавлять обнаруженный файл не требуется.

### Ж. Проверить ответ сервера для Sitemap

**Часть 1. Открыть инструмент**

1. Откройте https://webmaster.yandex.ru/.
2. Выберите нужный сайт.
3. В левом меню раскройте **«Инструменты»**.
4. Нажмите **«Проверка ответа сервера»**.

**Часть 2. Заполнить поля**

1. Найдите **«Опрашиваемый URL»**.
2. Вставьте адрес Sitemap.
3. В поле **«Робот»** выберите **«Основной робот Яндекса»**.
4. Найдите `If-Modified-Since`.
5. Для обычной проверки очистите указанную дату, если поле заполнено.
6. Нажмите **«Проверить»**.
7. Дождитесь ответа.

**Часть 3. Изучить результат**

Проверьте:

- HTTP-код.
- Время ответа сервера.
- Кодировку.
- Тип содержимого.
- Размер файла.
- Сообщения об ошибках.

**Ожидаемый результат:**

`200 OK`

Для XML-файла корректным типом содержимого является, например, `application/xml`.

**Важно:** заполненное поле `If-Modified-Since` не означает ошибку. Если сервер вернул `200 OK` и файл получен, повторная проверка только из-за даты не требуется.

**Часть 4. Проверить дополнительные карты**

Повторите проверку для всех необходимых файлов, если их доступность ещё не подтверждена.

Не выполняйте повторные проверки файлов, по которым уже получен актуальный подтверждённый результат без признаков проблемы.

### З. Проверить XML через «Анализ файлов Sitemap»

**Часть 1. Открыть инструмент**

1. Откройте https://webmaster.yandex.ru/.
2. Выберите нужный сайт.
3. В левом меню раскройте **«Инструменты»**.
4. Нажмите **«Анализ файлов Sitemap»**.

**Часть 2. Выбрать режим**

1. Найдите переключатели **«Текст»**, **«URL»**, **«Файл»**.
2. Выберите **«URL»**.
3. Найдите поле ввода.
4. Вставьте адрес Sitemap.
5. Нажмите **«Проверить»**.
6. Дождитесь результата.

**Часть 3. Проверить показатели**

| Показатель | Что проверить |
|---|---|
| Тип файла | Sitemap или индекс Sitemap |
| Размер | Файл успешно загружен |
| Количество ссылок | Соответствует содержимому |
| Количество вложенных Sitemap | Соответствует структуре индекса |
| Ошибки | Отсутствуют блокирующие ошибки |

**Ожидаемый результат:** сообщение **«Ошибок не найдено»**.

Если файл является индексом, его проверка не заменяет проверку вложенных карт.

**Часть 4. Проверить вложенные Sitemap**

1. Откройте индекс.
2. Скопируйте URL вложенного файла из `loc`.
3. Вернитесь в анализатор.
4. Вставьте URL.
5. Нажмите «Проверить».
6. Проверьте количество ссылок и отсутствие ошибок.

**Важно:** анализатор проверяет корректность файла в момент обращения. Он не подтверждает, что поисковый робот уже обновил сведения в своей базе.

### И. Проверить Sitemap в обновлённом интерфейсе Вебмастера

**Часть 1. Открыть раздел**

1. Откройте Яндекс Вебмастер.
2. Выберите сайт.
3. В левом меню нажмите **«Индексирование»**.
4. Выберите **«Файлы Sitemap»**.
5. Дождитесь загрузки списка.

**Часть 2. Изучить таблицу**

В обновлённом интерфейсе отображаются:

| Столбец | Назначение |
|---|---|
| Источник | URL Sitemap |
| Статус | Последний результат обработки |
| Последняя загрузка | Дата обработки роботом |
| Число ссылок в файле | Количество обнаруженных URL |

**Часть 3. Проверить статус**

Возможные результаты:

| Статус | Значение | Решение |
|---|---|---|
| OK | Файл обработан успешно | Ничего не менять |
| В очереди | Обработка ожидается | Проверить позднее |
| Редирект | URL перенаправляет | Проверить конечный адрес |
| Ошибка | XML некорректен | Изучить сообщение |
| Не проиндексирован | Файл не обработан, возможна ошибка загрузки | Проверить текущий HTTP-ответ |
| Предупреждение со старой датой | Последняя обработка не отражает нынешнее состояние | Сравнить с текущими проверками |

**Важно:** предупреждение необходимо интерпретировать вместе с датой последней загрузки.

Если файл сейчас доступен и проходит анализатор, а последняя загрузка была до исправления, не нужно повторно изменять сайт без новой подтверждённой ошибки.

### К. Учитывать временные ограничения Яндекс Вебмастера

Если появляется сообщение:

**«Инструмент работает в режиме "Только для чтения"»**,

это означает, что временно недоступны действия по добавлению, удалению, восстановлению или отправке Sitemap на переобход.

**Что сделать:**

1. Не пытайтесь многократно добавлять файл.
2. Не удаляйте действующие карты.
3. Сохраните опубликованные файлы без изменений.
4. Проверьте их доступность через «Проверку ответа сервера».
5. Проверьте XML через анализатор.
6. Вернитесь к статусу после восстановления работы инструмента.

Яндекс регулярно проверяет файлы Sitemap самостоятельно.

**Срок обработки:** обычно до двух недель после добавления или изменения.

Если ускоренный переобход доступен, его можно использовать для изменённого файла. По документации Яндекса предусмотрено до 10 ускоренных запросов для одного хоста, а заявленный срок обработки составляет до трёх дней.

Не используйте лимит ускоренных проверок без необходимости.

### Л. Сверить URL из GURU с содержимым Sitemap

**Часть 1. Получить адреса**

GURU должен предоставить список целевых страниц проекта из уже существующих данных.

**Часть 2. Проверить ключевые URL**

1. Откройте нужный Sitemap.
2. Нажмите `Command + F` на Mac или `Ctrl + F` на Windows.
3. Введите путь страницы.

Например:

`/novogodnie-podarki-2027`

4. Найдите элемент `loc`.
5. Проверьте полный адрес.

**Часть 3. Проверить разные типы страниц**

Для сайта с интернет-магазином отдельно проверяйте:

- Главную страницу.
- Основные категории.
- Коммерческие посадочные страницы.
- Карточки товаров.
- Опубликованные статьи.

Проверять каждую запись большого Sitemap вручную не требуется.

**Часть 4. Проверить нежелательные адреса**

Убедитесь, что карты не содержат подтверждённо ненужных записей:

- Неправильный домен.
- Нежелательные HTTP-версии.
- Удалённые страницы.
- Некорректные дубли.
- Служебные URL, не предназначенные для поиска.
- Страницы с ошибочным каноническим адресом.

Если важный URL отсутствует:

1. Проверьте, опубликована ли страница.
2. Проверьте её фактический URL.
3. Проверьте другие Sitemap.
4. Проверьте настройки генерации.
5. Проверьте ограничения индексирования.
6. Исправьте только установленную причину.

### М. Устранить ошибки Sitemap

| Ошибка | Причина | Что делать |
|---|---|---|
| 404 Not Found | Файл отсутствует по адресу | Проверить генерацию и URL |
| 403 Forbidden | Файл недоступен | Проверить ограничения |
| 429 | Ограничение запросов | Проверить защиту сайта |
| 5xx | Ошибка сервера | Проверить хостинг |
| Редирект | Файл расположен по другому адресу | Проверить конечный URL |
| Некорректный XML | Ошибка структуры | Исправить источник данных |
| Неверный домен | Устаревшие адреса | Исправить источник URL |
| Нет нужной страницы | URL не попал в карту | Проверить публикацию и генерацию |
| Старая ошибка в Вебмастере | Робот ещё не обновил данные | Сравнить дату и актуальные проверки |
| Файл не обработан | Обработка ещё не выполнена | Проверить доступность и состояние очереди |

**Последовательность исправления:**

1. Определите проблемный файл.
2. Прочитайте сообщение Яндекса.
3. Проверьте дату последней обработки.
4. Проверьте текущий HTTP-ответ.
5. Проверьте XML через анализатор.
6. Установите фактическую причину.
7. Измените только необходимую настройку.
8. Если изменялся сайт, сохраните и опубликуйте изменения.
9. Повторно выполните техническую проверку.
10. Проверьте последующий результат обработки в Вебмастере.

**Не удаляйте работающий Sitemap ради устранения устаревшего предупреждения.**

### Н. Подтвердить результат проверки

**Часть 1. Проверить доступность**

1. Убедитесь, что необходимые Sitemap существуют.
2. Проверьте актуальные HTTP-ответы.
3. Убедитесь, что файлы доступны основному роботу Яндекса.

**Часть 2. Проверить XML**

1. Проверьте основную карту.
2. Проверьте товарную карту, если используется.
3. Проверьте индекс публикаций, если используется.
4. Проверьте вложенные Sitemap.

**Часть 3. Проверить обработку Яндексом**

1. Откройте «Индексирование → Файлы Sitemap».
2. Найдите соответствующие файлы.
3. Проверьте текущие статусы.
4. Сравните даты последних загрузок.
5. Отдельно зафиксируйте устаревшие предупреждения, ожидающие повторной обработки.

**Ожидаемый результат:** необходимые Sitemap доступны, корректны и передают фактические адреса страниц.

Если техническая проверка завершена, но Яндекс ещё не обновил старый статус, дополнительные изменения сайта не требуются. Обновление статуса остаётся отдельным контрольным действием.

### Итоговый результат

**Готово**

- Необходимые файлы существуют.
- Sitemap доступны поисковому роботу.
- Структура XML корректна.
- Целевые URL присутствуют в соответствующих картах.
- Яндекс подтвердил успешную обработку файлов.
- Нежелательное дублирование отсутствует.

**Требует проверки**

- Файлы технически исправны, но Яндекс ещё не обновил статус.
- Изменения находятся в очереди на обработку.
- Не все необходимые URL сверены.
- Отдельные дополнительные Sitemap ещё не проверены.

**Проблема**

- Файл недоступен.
- Сервер возвращает ошибку.
- XML некорректен.
- Карта содержит неправильные URL.
- Необходимые страницы отсутствуют из-за ошибки генерации.
- После повторной обработки Яндекс сообщает об актуальной неисправности.

**Не требуется**

- Повторное создание уже существующего Sitemap.
- Ручное добавление карты, которую Яндекс уже обнаружил.
- Создание товарного Sitemap без товарного каталога.
- Создание Sitemap публикаций при отсутствии соответствующего модуля.
- Постоянное ручное обновление автоматически создаваемых файлов.

### Результат для Яндекс Вебмастера

- **Назначение:** обеспечение передачи актуальной структуры сайта Яндексу.
- **Приоритет:** фундаментальная настройка.
- **Основные инструменты:** «Файлы Sitemap», «Анализ файлов Sitemap».
- **Дополнительный инструмент:** «Проверка ответа сервера».
- **Источник URL:** существующие данные GURU и опубликованные Sitemap.
- **Механизм:** автоматическое формирование и обработка файлов.
- **Ограничение:** наличие URL в Sitemap не гарантирует индексирования.
- **Использование:** контроль обнаружения страниц и диагностика ошибок карт.

**После технического подтверждения корректности Sitemap можно переходить к 3.1. Страницы в поиске.**
