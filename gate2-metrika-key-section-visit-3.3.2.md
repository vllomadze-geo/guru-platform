# 3.3.2. Посещение ключевого раздела

## 1. Что сделать (инструкция)

Настроить Яндекс Метрику для регистрации посещений коммерчески значимого раздела сайта и проверить, что соответствующая конверсия корректно передаётся и отображается в отчётах.

**Целевое действие:** посетитель открыл страницу, которая представляет важный этап знакомства с товаром, услугой или коммерческим предложением.

Различайте:

| Действие | Что подтверждает |
|---|---|
| Просмотр раздела | Посетитель открыл определённую страницу |
| Изучение предложения | Посетитель взаимодействовал с содержимым, если это подтверждено дополнительными данными |
| Переход к товару | Посетитель заинтересовался конкретным предложением |
| Отправка заявки | Посетитель совершил обращение |
| Покупка | Посетитель совершил коммерческое действие |

**Приоритет:** поведенческая конверсия.

Для отслеживания используем штатную цель Яндекс Метрики **«Посещение страниц»** из категории «Вовлечённость».

Дополнительный JavaScript не требуется, если страница имеет собственный URL и на ней работает счётчик Метрики.

**Практическая ценность:**

- Определять заинтересованность в важных коммерческих предложениях.
- Сравнивать источники трафика по посещениям выбранного раздела.
- Анализировать путь посетителя от знакомства с предложением до заявки или покупки.
- Создавать аудитории на основе посещения значимых страниц, когда это необходимо для рекламы.

**Условия применения:**

- Существует коммерчески значимая страница с собственным URL: цель можно настроить.
- Посещение страницы уже учитывается подходящей целью: повторно не создаём.
- Требуется только количество просмотров страницы: используем стандартные отчёты Метрики.
- Отдельного URL нет: сначала определяем, возможно ли штатное отслеживание.
- Посещение раздела не представляет самостоятельной аналитической ценности: цель не требуется.

**Важно:** не создавайте цели для всех страниц сайта. Отслеживайте только разделы, посещение которых помогает принимать конкретные маркетинговые решения.

## 2. Где нажать / Как проверить (инструкция)

### А. Выбрать коммерчески значимый раздел

**Часть 1. Определить назначение**

Выберите страницу, которую посетитель изучает перед обращением, оформлением заказа или другим важным действием.

| Тип бизнеса | Возможный ключевой раздел |
|---|---|
| Интернет-магазин | Специальная коллекция, сезонное предложение, индивидуальный заказ |
| Сайт услуг | Страница конкретной услуги |
| B2B | Корпоративные решения, сотрудничество |
| SaaS | Тарифы, корпоративный продукт |
| Образовательный проект | Программа обучения, условия поступления |

**Часть 2. Проверить необходимость цели**

Перед созданием ответьте на три вопроса:

1. Существует ли отдельная опубликованная страница?
2. Поможет ли информация о её посещении оценивать эффективность маркетинга?
3. Не отслеживается ли это действие уже существующей целью?

Если достаточно обычной статистики посещаемости, дополнительная цель не нужна.

**Рекомендация для GURU:** по умолчанию выбирать один наиболее значимый раздел. Дополнительные цели создавать только при самостоятельной аналитической необходимости.

### Б. Найти существующую цель в Яндекс Метрике

1. Откройте https://metrika.yandex.ru/.
2. Войдите через рабочий Яндекс ID.
3. Выберите счётчик нужного сайта.
4. В левом меню нажмите **«Цели»**.
5. Просмотрите существующие цели.
6. Найдите цель с названием выбранного раздела или соответствующим URL.
7. Если цель найдена, проверьте её название, числовой ID и условие.
8. Убедитесь, что она отслеживает необходимую страницу.

**Если цель существует и настроена правильно:** не создавайте новую. Переходите к проверке её работоспособности.

**Если условие неправильное:** сначала установите причину расхождения. При необходимости исправьте существующую цель, не создавая дубль.

**Если подходящей цели нет:** продолжайте настройку.

### В. Проверить страницу и её адрес в Tilda

**Часть 1. Проверить опубликованную страницу**

1. Откройте действующий сайт проекта.
2. В меню найдите выбранный раздел.
3. Нажмите на его название.
4. Дождитесь полной загрузки страницы.
5. Убедитесь, что открылось нужное содержимое.
6. Нажмите на адресную строку браузера.
7. Скопируйте полный URL.

Например:

`https://example.ru/collection-2027`

Это образец, а не адрес конкретного проекта.

**Часть 2. Проверить адрес в Tilda**

1. Откройте https://tilda.cc/login/.
2. Авторизуйтесь в аккаунте сайта.
3. Выберите нужный проект.
4. Найдите выбранную страницу в списке страниц проекта.
5. Откройте её **«Настройки»**.
6. Перейдите на вкладку **«Главное»**.
7. Найдите поле **«Адрес страницы»**.
8. Сравните его с адресом опубликованной страницы.

**Правильный результат:** опубликованный URL соответствует адресу страницы, указанному в Tilda.

**Если адрес правильный:** ничего менять не нужно.

**Если адрес отличается:**

1. Проверьте, открывается ли нужная страница.
2. Убедитесь, что браузер не перенаправляет посетителя на другой URL.
3. Для условия цели используйте действующий адрес после перенаправления.
4. Не меняйте URL страницы исключительно ради аналитики.

Если настройки страницы изменялись, сохраните их и нажмите **«Опубликовать»**.

Если изменений не было, повторная публикация не требуется.

### Г. Проверить подключение Яндекс Метрики

**Часть 1. Определить номер счётчика**

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный сайт.
3. Посмотрите числовой номер счётчика.
4. Зафиксируйте его для последующей проверки.

**Часть 2. Проверить интеграцию с Tilda**

1. Откройте https://tilda.cc/login/.
2. Выберите нужный проект.
3. Нажмите **«Настройки сайта»**.
4. В левом меню откройте **«Аналитика»**.
5. Найдите раздел **«Яндекс Метрика»**.
6. Проверьте подключённый номер счётчика.
7. Сравните его с номером в Яндекс Метрике.

**Ожидаемый результат:** номера совпадают.

**Если счётчик уже установлен и работает:** ничего менять не требуется.

**Если счётчик отсутствует:**

1. Убедитесь, что он не установлен другим способом.
2. Если установки действительно нет, подключите существующий счётчик через раздел «Аналитика».
3. Сохраните настройки.
4. Опубликуйте все страницы сайта.
5. Проверьте передачу просмотров.

Не устанавливайте второй экземпляр одного счётчика.

### Д. Создать цель «Посещение страниц»

Выполняйте только при отсутствии существующей подходящей цели.

**Часть 1. Открыть создание цели**

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В левом меню нажмите **«Цели»**.
4. Нажмите кнопку **«Добавить цель»**.
5. Откроется окно **«Новая цель»**.
6. Найдите категорию **«Вовлечённость»**.
7. Выберите **«Посещение страниц»**.

**Важно:** в обновлённом интерфейсе Метрики нужный тип находится именно в категории «Вовлечённость».

**Часть 2. Указать название**

1. Найдите поле **«Название цели»**.
2. Введите название, отражающее конкретный раздел.

Например:

`Посещение раздела - Новогодние подарки 2027`

Название должно позволять однозначно определить, посещение какой страницы фиксируется.

**Часть 3. Установить условие**

1. Найдите настройку условия достижения цели.
2. Выберите **«url: совпадает»**.
3. Введите фактический путь страницы.

Пример:

`/novogodnie-podarki-2027`

Путь взят из действительного URL:

`https://k-apple.ru/novogodnie-podarki-2027`

**Почему «url: совпадает»:**

Это условие позволяет отслеживать конкретную страницу по её адресу без включения других страниц с похожими названиями.

Не используйте «url: содержит», если задача заключается в отслеживании одного определённого раздела.

**Альтернативные условия:**

| Условие | Когда использовать |
|---|---|
| `url: совпадает` | Одна конкретная страница |
| `url: содержит` | Несколько URL с общим уникальным фрагментом |
| `url: начинается с` | Страницы одного подраздела |
| `url: регулярное выражение` | Сложные правила соответствия URL |

Для типовой настройки GURU используем **«url: совпадает»**.

**Часть 4. Сохранить цель**

1. Проверьте название цели.
2. Проверьте тип **«Посещение страниц»**.
3. Проверьте условие **«url: совпадает»**.
4. Сравните указанный путь с опубликованным URL.
5. Нажмите **«Добавить цель»**.
6. Убедитесь, что цель появилась в списке.
7. Зафиксируйте её числовой ID.

**Ожидаемый результат:** цель создана и готова регистрировать посещения выбранной страницы.

Создание такой цели не требует повторной публикации Tilda, если счётчик уже работает.

### Е. Подготовить проверку

**Часть 1. Зафиксировать исходные показатели**

1. Откройте Яндекс Метрику.
2. Выберите нужный счётчик.
3. В левом меню нажмите **«Конверсии»**.
4. Найдите созданную цель.
5. Установите период **«Сегодня»**.
6. Убедитесь, что сегмент не выбран.
7. Проверьте показатель **«Достижения цели»**.
8. Запишите значение до теста.

Если цель создана только что и отображается «Нет данных по цели», это ещё не подтверждает ошибку.

**Часть 2. Подготовить браузер**

1. Откройте новое окно Chrome в режиме инкогнито.
2. На Mac нажмите `Command + Shift + N`.
3. На Windows нажмите `Ctrl + Shift + N`.
4. Не авторизуйтесь в Метрике в этом окне.
5. Откройте опубликованную страницу выбранного раздела.
6. Если сайт запрашивает согласие на использование аналитических cookie, разрешите их для теста.

**Часть 3. Включить отладчик**

1. Добавьте к URL параметр `_ym_debug=2`.

Для примера:

`https://k-apple.ru/novogodnie-podarki-2027?_ym_debug=2`

2. Нажмите Enter.
3. Дождитесь полной загрузки страницы.
4. В нижней части сайта откройте панель отладчика Метрики.
5. Перейдите на вкладку `Counters`.
6. Убедитесь, что отображается правильный номер счётчика.
7. Перейдите на вкладку `Console`.

**Ожидаемый результат:** отладчик показывает работу нужного счётчика.

### Ж. Проверить регистрацию посещения страницы

1. В открытом отладчике перейдите на вкладку `Console`.
2. Найдите запись `PageView`.
3. Посмотрите номер счётчика.
4. Посмотрите URL страницы в этой записи.
5. Сравните его с адресом проверяемого раздела.
6. Убедитесь, что указан нужный путь.

**Для проекта «Коричное яблоко» ожидаем:**

Счётчик:

`105213127`

Адрес страницы:

`https://k-apple.ru/novogodnie-podarki-2027`

**Ожидаемый результат:** отображается `PageView` с номером правильного счётчика и URL выбранной страницы.

**Важно:** `PageView` подтверждает передачу просмотра страницы в Метрику, но окончательно достижение цели необходимо проверить в отчёте «Конверсии».

**Если записи нет:**

1. Перейдите на вкладку `Counters`.
2. Проверьте, обнаружен ли счётчик.
3. Проверьте, не блокирует ли браузер Метрику.
4. Убедитесь, что страница опубликована.
5. Если отладчик не работает, используйте `_ym_debug=1` и консоль Chrome.
6. Повторите проверку.

Не устанавливайте дополнительный код счётчика без подтверждения причины ошибки.

### З. Проверить появление конверсии

**Часть 1. Выполнить контрольное посещение**

1. Откройте новое приватное окно Chrome.
2. Перейдите по обычному URL страницы без `_ym_debug=2`.

Для примера:

`https://k-apple.ru/novogodnie-podarki-2027`

3. Дождитесь полной загрузки.
4. Убедитесь, что открылся нужный раздел.
5. Не выполняйте дополнительные перезагрузки без необходимости.

**Часть 2. Проверить отчёт**

1. Откройте https://metrika.yandex.ru/.
2. Выберите нужный счётчик.
3. В левом меню нажмите **«Конверсии»**.
4. Установите период **«Сегодня»**.
5. Проверьте, что дополнительные сегменты отсутствуют.
6. Найдите созданную цель по названию или ID.
7. Если статистика скрыта, включите её отображение.
8. Посмотрите показатели:

   - «Конверсия».
   - «Целевые визиты».
   - «Достижения цели».

9. Сравните количество достижений с исходным значением до теста.

**Ожидаемый результат:** в отчёте появилось достижение выбранной цели.

Метрика обрабатывает данные не мгновенно. Если результат отсутствует, дождитесь обработки информации и обновите отчёт.

**Если достижение отсутствует:**

1. Проверьте правильность выбранного периода.
2. Проверьте номер счётчика.
3. Проверьте название и ID цели.
4. Сравните условие с фактическим URL.
5. Откройте настройки счётчика и раздел «Фильтры».
6. Убедитесь, что контрольный визит не исключён.
7. Вернитесь к результатам отладчика.
8. Повторите тест после устранения выявленной причины.

Если другие посетители одновременно достигали цели, увеличение показателя не обязательно будет равно одному.

### И. Исключить ложные достижения

**Часть 1. Проверить другую страницу**

1. Откройте главную страницу сайта.
2. Не переходите в выбранный раздел.
3. Проверьте URL главной страницы.
4. Убедитесь, что он не совпадает с условием цели.

**Часть 2. Проверить похожие адреса**

Например, если цель отслеживает:

`/novogodnie-podarki-2027`

Она не должна фиксировать посещение:

- `/`
- `/individualnyj_zakaz`
- `/novogodnie-podarki-2028`
- `/novogodnie-podarki-2027/other-page`

При условии `url: совпадает` полный путь должен соответствовать указанному значению.

**Часть 3. Проверить отсутствие дублей**

1. Вернитесь в Метрику.
2. Откройте «Цели».
3. Найдите все цели, использующие URL выбранного раздела.
4. Убедитесь, что отсутствуют две одинаковые цели для одного действия.

Не создавайте отдельные цели для одной и той же страницы без самостоятельной аналитической задачи.

### К. Подготовить цель для Яндекс Директа

После успешной проверки:

1. Откройте Яндекс Метрику.
2. Перейдите в раздел «Цели».
3. Найдите созданную цель.
4. Зафиксируйте её числовой ID.
5. Убедитесь, что достижение подтверждено в отчёте.
6. Определите её назначение как поведенческой конверсии.

**Важно:** посещение раздела не означает, что посетитель оставил заявку или оформил заказ.

Для Яндекс Директа цель может использоваться для анализа заинтересованности, сравнения источников трафика и сегментации аудитории.

Не добавляйте такую цель в стратегию оптимизации автоматически, если отсутствуют данные о её связи с коммерческими результатами.

## 3. Сверка (инструкция)

| Проверка | Правильный результат |
|---|---|
| Ключевой раздел | Выбран по аналитической значимости |
| URL | Совпадает с опубликованной страницей |
| Tilda | Страница опубликована и доступна |
| Счётчик Метрики | Установлен и работает |
| Цель | Существует без дублирования |
| Категория | Вовлечённость |
| Тип цели | Посещение страниц |
| Условие | `url: совпадает` |
| Значение | Соответствует реальному пути страницы |
| Отладчик | Зарегистрирован `PageView` |
| Номер счётчика | Совпадает с действующим |
| Конверсии | Достижение появилось в отчёте |
| Ложные срабатывания | Не выявлены |

### Итоговый результат

**Готово**

- Коммерчески значимый раздел определён.
- URL проверен.
- Цель создана без дублирования либо использована существующая.
- Метрика фиксирует посещение страницы.
- Достижение отображается в отчёте «Конверсии».
- Ложные срабатывания не выявлены.

**Требует проверки**

- Отладчик зарегистрировал просмотр, но конверсия ещё не появилась в отчёте.
- Статистика пока не обработана.
- Есть расхождение между URL страницы и условием цели.

**Проблема**

- Страница недоступна.
- Указан неправильный URL.
- Счётчик не работает.
- `PageView` не передаётся.
- Цель фиксирует посещение неподходящих страниц.
- Обнаружено нежелательное дублирование целей.

**Не требуется**

Отсутствует коммерчески значимый раздел с собственным URL либо посещаемость выбранной страницы достаточно анализировать стандартными отчётами Метрики.

### Результат для аналитики

- Назначение: посещение коммерчески значимого раздела.
- Приоритет: поведенческая конверсия.
- Тип цели Метрики: «Посещение страниц».
- Механизм: регистрация просмотра страницы с заданным URL.
- Основное ограничение: просмотр страницы не подтверждает коммерческое обращение или покупку.
- Использование: анализ заинтересованности посетителей, источников трафика и пути к основным конверсиям.

**После подтверждения правильной регистрации цели можно переходить к следующей поведенческой конверсии.**
