# 3.3.5. Продолжительность визита

## 1. Что сделать (инструкция)

Настроить Яндекс Метрику для регистрации визитов, продолжительность которых превышает установленное время, и проверить, что соответствующая конверсия корректно отображается в отчётах.

Целевое действие: посетитель достиг установленного порога продолжительности визита на сайте.

Приоритет: поведенческая конверсия.

Различайте:

| Показатель              | Что подтверждает                                     |
| ----------------------- | ---------------------------------------------------- |
| Время на сайте          | Измеренная продолжительность визита                  |
| Длительный визит        | Продолжительность превысила заданный порог           |
| Активное взаимодействие | Требует дополнительных данных о действиях посетителя |
| Покупка или заявка      | Подтверждённое коммерческое действие                 |

Практическая ценность:

- Выделять визиты с продолжительным взаимодействием.
- Сравнивать качество трафика из разных источников.
- Анализировать связь продолжительности визита с заказами и заявками.
- Формировать аудитории для дальнейшего анализа, если установленный порог действительно значим.

Для отслеживания используем штатную цель Яндекс Метрики «Продолжительность визита» из категории «Вовлечённость».

### Как Метрика измеряет продолжительность

Метрика рассчитывает продолжительность визита как разницу между первым и последним зарегистрированными событиями.

Например, посетитель открыл сайт, через две минуты перешёл в каталог, а затем ещё через минуту открыл другой раздел. В таком случае продолжительность визита составляет приблизительно три минуты, если эти действия были зарегистрированы счётчиком.

Важно: открытая вкладка браузера сама по себе не подтверждает непрерывное чтение сайта. Без последующих регистрируемых событий продолжительность может быть меньше фактического времени нахождения вкладки открытой.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://yandex.ru\&sz=32)

Яндекс+1



Условия применения:

- Нужен конкретный порог продолжительности как конверсия: настраиваем.
- Достаточно знать среднее время на сайте: используем существующий отчёт.
- Подходящая цель уже существует: проверяем её без создания дубля.
- Нет достаточных данных для выбора порога: сначала собираем статистику.
- Продолжительность не связана с бизнес-результатом: цель необязательна.

Правило GURU: порог времени выбираем на основе фактических данных проекта, а не произвольно.

## 2. Где нажать / Как проверить (инструкция)

### А. Проверить существующую цель в Яндекс Метрике

1. Откройте [https://metrika.yandex.ru/](https://metrika.yandex.ru/?utm_source=chatgpt.com).
2. Войдите через рабочий Яндекс ID.
3. Выберите счётчик нужного сайта.
4. В левом меню нажмите «Цели».
5. Просмотрите список существующих целей.
6. Найдите цель «Продолжительность визита» либо цель с названием, содержащим порог времени.
7. Если такая цель существует, откройте её настройки.
8. Посмотрите значения часов, минут и секунд.
9. Зафиксируйте её название, числовой ID и установленный порог.

Если подходящая цель уже существует: повторно создавать её не нужно.

Если цель отсутствует: сначала определите, имеет ли смысл её создавать, и выберите порог по реальным данным.

### Б. Изучить фактическую продолжительность визитов

Часть 1. Открыть отчёт

1. Откройте [Яндекс Метрику](https://metrika.yandex.ru/?utm_source=chatgpt.com).
2. Выберите нужный счётчик.
3. В левом меню нажмите «Отчёты».
4. Откройте категорию «Аудитория».
5. Выберите «Время на сайте».
6. Установите период «Последние 30 дней», если данные за этот период доступны.
7. Убедитесь, что дополнительные сегменты не выбраны.

Этот путь подтверждён [официальной документацией Яндекса](https://yandex.ru/support/metrica/ru/visitors/activity-time?utm_source=chatgpt.com).

Часть 2. Изучить показатели

1. Посмотрите распределение визитов по продолжительности.
2. Найдите показатель «Время на сайте».
3. Посмотрите среднюю продолжительность визита.
4. Обратите внимание на долю коротких и длительных визитов.
5. При наличии данных о заказах и заявках сравните их частоту в группах с разной продолжительностью.

Важно: средняя продолжительность не является готовым порогом для создания цели.

Часть 3. Выбрать порог

Оцените следующие условия:

| Критерий               | Что установить                                                 |
| ---------------------- | -------------------------------------------------------------- |
| Фактическая статистика | Как долго обычно продолжаются визиты                           |
| Коммерческие конверсии | При какой продолжительности чаще происходят заявки или покупки |
| Частота достижений     | Достаточно ли визитов выбранной продолжительности              |
| Аналитическая ценность | Помогает ли этот порог отличить заинтересованных посетителей   |

Например, если анализ показал, что при продолжительности от двух минут вероятность покупки заметно повышается, можно рассмотреть порог в две минуты.

Это пример, а не рекомендация установить две минуты для всех сайтов.

Если связь продолжительности с коммерческими результатами не подтверждается, достаточно стандартного отчёта.

### Г. Создать цель «Продолжительность визита»

Выполняйте только при отсутствии подходящей цели и наличии обоснованного порога.

Часть 1. Открыть создание цели

1. Откройте [https://metrika.yandex.ru/](https://metrika.yandex.ru/?utm_source=chatgpt.com).
2. Выберите нужный счётчик.
3. В левом меню нажмите «Цели».
4. Нажмите фиолетовую кнопку «Добавить цель».
5. Откроется окно «Новая цель».
6. Найдите категорию «Вовлечённость».
7. Выберите «Продолжительность визита».

Часть 2. Заполнить настройки

1. Найдите поле «Название».
2. Укажите название, отражающее выбранный порог.

Например:

`Продолжительность визита - более 2 минут`

3. Найдите поля:
   - «Часы»
   - «Минуты»
   - «Секунды»
4. Укажите обоснованный порог.

Пример заполнения для двух минут:

| Поле    | Значение |
| ------- | -------- |
| Часы    | `0`      |
| Минуты  | `2`      |
| Секунды | `0`      |

Не используйте пример как готовую настройку проекта. Фактическое значение выбирается после анализа статистики.

Часть 3. Сохранить цель

1. Проверьте название.
2. Проверьте значения времени.
3. Нажмите «Добавить цель».
4. Убедитесь, что цель появилась в списке.
5. Запишите её числовой ID.
6. Проверьте сохранённый порог.

Ожидаемый результат: цель создана и готова отслеживать визиты установленной продолжительности.

Создание цели не требует повторной публикации Tilda, если действующий счётчик уже работает.

Ограничение: этот тип цели нельзя включать в составную цель Яндекс Метрики.&#x20;

### Д. Подготовить контрольную проверку

Часть 1. Зафиксировать исходный показатель

1. Откройте Метрику.
2. Выберите нужный счётчик.
3. В левом меню нажмите «Конверсии».
4. Найдите созданную цель.
5. Установите период «Сегодня».
6. Проверьте показатель «Достижения цели».
7. Запишите его значение.

Если отображается «Нет данных по цели», это не обязательно означает ошибку.

Часть 2. Подготовить браузер

1. Откройте Chrome в режиме инкогнито.
2. На Mac нажмите `Command + Shift + N`.
3. На Windows нажмите `Ctrl + Shift + N`.
4. Не авторизуйтесь в Яндекс Метрике в приватном окне.
5. Откройте опубликованный сайт проекта.

Приватное окно позволяет избежать влияния фильтра «Не учитывать мои визиты», связанного с авторизацией владельца счётчика. Другие фильтры при этом продолжат действовать.

### Е. Выполнить контрольный визит

Пример для порога 2 минуты.

Используйте именно тот порог, который установлен в проверяемой цели.

1. Откройте главную страницу сайта.
2. Дождитесь полной загрузки.
3. Запустите секундомер.
4. Оставьте страницу открытой.
5. Через 2 минуты 10 секунд перейдите по внутренней ссылке на другую страницу сайта.
6. Дождитесь её полной загрузки.
7. Убедитесь, что переход выполнен в той же вкладке браузера.
8. Завершите контрольную проверку.

Ожидаемый результат: между первым и последующим зарегистрированными событиями прошло больше установленного порога.

Почему недостаточно просто подождать две минуты:

Продолжительность рассчитывается по зарегистрированным событиям. Если посетитель открыл страницу и больше ничего не сделал, Метрика может не получить события, подтверждающего фактически прошедшее время.

Поэтому после ожидания выполняем конкретное действие, например переход на другую страницу.&#x20;

### Ж. Проверить регистрацию событий

Часть 1. Включить отладчик

1. Откройте опубликованный сайт.
2. Добавьте к адресу `_ym_debug=2`.

Пример:

`https://example.ru/?_ym_debug=2`

3. Нажмите Enter.
4. Дождитесь загрузки страницы.
5. В нижней части сайта откройте панель отладки.
6. Перейдите во вкладку `Counters`.
7. Проверьте номер счётчика.
8. Откройте вкладку `Console`.
9. В меню отладчика включите `Preserve log`, если необходимо сохранять записи между переходами.

Часть 2. Выполнить проверку

1. Запустите контрольный визит.
2. Дождитесь превышения выбранного порога.
3. Перейдите на другую страницу.
4. Вернитесь к отладчику.
5. Найдите зарегистрированные события `PageView`.
6. Проверьте, что они относятся к нужному счётчику.
7. Если доступно время событий, сравните их временные отметки.

Важно: наличие двух `PageView` подтверждает передачу просмотров. Само по себе оно ещё не доказывает достижение временной цели.

Для окончательной проверки используется отчёт «Конверсии».&#x20;

### И. Исключить ложные достижения

Часть 1. Проверить короткий визит

1. Откройте новое приватное окно.
2. Перейдите на сайт.
3. Выполните несколько действий за время, существенно меньшее установленного порога.
4. Завершите визит.
5. Проверьте, что эти действия не создают достижения временной цели.

При проверке учитывайте, что отчёт может содержать достижения других пользователей.

Часть 2. Проверить сторонние события

На Tilda продолжительность визита могут изменять события, отправляемые встроенными функциями и пользовательскими скриптами.

Например:

- Открытие новой страницы.
- Переход по внешней ссылке.
- Достижение другой цели.
- Передача виртуального просмотра.
- Отправка параметров визита.

Такие действия могут законно влиять на продолжительность, поскольку Метрика использует зарегистрированные события.

Не изменяйте существующие настройки Tilda только для увеличения продолжительности визитов.

### Итоговый результат

Готово

- Порог выбран по фактическим данным.
- Цель создана либо использована существующая.
- Счётчик работает.
- Контрольный визит превысил установленный порог.
- Достижение подтверждено в отчёте.
- Нежелательное дублирование отсутствует.

Требует проверки

- События зарегистрированы, но достижение ещё не появилось в отчёте.
- Продолжительность визита недостаточно подтверждена событиями.
- Недостаточно данных для выбора аналитически значимого порога.

Проблема

- Указан неправильный порог.
- Счётчик не регистрирует действия.
- Контрольный визит разделился на несколько визитов.
- Достижения не соответствуют установленному условию после диагностики.

Не требуется

Продолжительность визитов достаточно анализировать стандартным отчётом «Время на сайте» либо этот показатель не представляет самостоятельной ценности для бизнеса.

### Результат для аналитики

- Назначение: выделение визитов установленной продолжительности.
- Приоритет: поведенческая конверсия.
- Тип цели: «Продолжительность визита».
- Механизм: разница между первым и последним зарегистрированными событиями.
- Основное ограничение: измеренная продолжительность не равна времени непрерывного активного чтения.
- Использование: сегментация трафика и анализ связи длительности визитов с бизнес-конверсиями.
